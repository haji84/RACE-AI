## 判定ルール

1. 掲載された歴史的な**予想ライン**を用い、走行中の実際の隊列と混同しない。掲載日時の事前時刻認証や映像は、今回の歴史統計には要求しない。
2. 掲載ラインの全車番と確定結果の実出走車番集合が一致した場合のみ、同ライン3車／同ライン2車＋別1車／3車別ラインに分類する。
3. 単騎の入着、同ライン2車の着順位置、ライン構成人数（3車ちょうどか4車以上か）、同着による複数払戻は独立した欄に保持する。
4. 重複・全車番不一致・掲載情報の欠落は明示的な `INVALID`／`CONFLICT`／`MISSING` として集計し、推測のラインを補完しない。
5. 母数は固定し、取得成功率・未取得件数・掲載元URL・結果URLを必ず付ける。
6. 分類割合は取得・整合済みのサンプル内だけで計算し、全国全件を代表するものとして表示しない。

## 再計算・収集

- `keirin_line_retro_2026.py`: 既存の月別 `race_results_YYYYMM.csv` と、取得済みの掲載ラインJSONLを結合し、レース別照合台帳と人数別カバレッジJSONを作る。
- `keirin_line_source_collector_2026.py`: 掲載元の過去の1日・1開催場単位ページを、少量・間隔を空けて取得する下準備。robots指定とアクセス拒否を尊重し、拒否時は停止する。事前認証時刻を捏造しない。**本環境からの実HTTP取得は未実証**。
- `test_keirin_line_retro_2026.py`: ローカル合成入力を使う11テスト合格。全国の本番取得成功を意味しない。

例（既に GitHub PR #312 の `race_results_2026??.csv` を利用）：

```
python keirin_line_retro_2026.py --results-dir ./results --lineups ./keirin_published_lines_verified_sample_20261118.jsonl --out-dir ./line_audit
```

取得時の例（GitHubへ自動保存する仕組みはまだ接続していない。公開ページ取得が許容される場合に限り）：

```
python keirin_line_source_collector_2026.py --results-dir ./results --out-dir ./new_lines --start 2026-11-01 --end 2026-11-18 --max-pages 10
```

収集成功したJSONLを上の集計に `--lineups` で追加する。**今回は全国22,245件の掲載ラインをまだ全件取得・分類できていないため、全国の割合や回収率を完成と判定しない。**
