## 条件2: 本番暗号化保存の明示的承認と信頼済み運転経路
- 既存公開GitHubへのAES-256-GCM暗号文の長期保管は、暗号文・**サイズ・更新日時・コミット時刻**を外部から観察できる。ユーザーの別途の明示的な承認が必須。**現在未承認**。
- 新しく追加した `scripts/keirin_github_production_bundle.py` と `scripts/keirin_github_production_archive.py` は、既存 `scripts/keirin_github_checkpoint.mjs` と `state/keirin-encrypted-history` のみを再利用する提案コード。公開GitHubの本番経路 `state/keirin/production/v1/` は合成テスト上で使っただけで、リアルGitHubへの本番書込みは行っていない。
- 本番pushの要求: 信頼済みmainの専用成功producer、同一プロジェクトID/SHA、既存の本番Secret、前向きで期限内に固定した本物の出走データと全オッズ、独立復号・SHA検証、fast-forward、公開暗号文承認値。
- 現状: 対応コードはDraft PR #103のみ。保護main上の**専用本番producerは未有効化**。外部契約未確認・公開暗号文承認未確認のため本番SecretをPRジョブへ渡さず、本番保存を起動しない。

## 実証の順序
1. 正当な契約/取得許可を確認した既存データ源を1つ固定。独立して全210/504通りの取得可能性を確認。
2. 信頼済みmainの本番データ供給ランナーを、鍵非公開・無課金・権限最小でレビュー。
3. ユーザーが公開暗号文のリスクに**明示的に了承**した後だけ、本番用の暗号アーカイブを有効化。認めない場合は、public Gitへの本番暗号文保存をしない。
4. 実在する未来の同一レースでPR #101→#103の予想2版を締切前に原本SHA付で固定し、暗号化保存、別ランナーで復号・整合性検証。締切後の後付けは禁止。
5. 公式確定結果・払戻・返還/訂正の独立照合と、8点固定vs可変の仮想投資・回収率を比較。
