# 競輪：調子・落車・欠場・復帰を条件付き予想に接続（2026-11-20）

## 位置づけ
従来のA/B予想原本を変更せず、調子・落車前後・復帰の出典付き事実から、別系統の研究用conditioned A/B候補を自動作成する。C（過去連係履歴）は別の任意方式であり、C待ちでA/Bを止めない。

既存の race_ai/keirin_nationwide_auto_generator.py は歴史的予想を再現するため固定SHA（blob f899a2317cf38d1be8e8832eaa678af6666a7d4a）を保持する。これを変更すると過去の実予想を正確に再現できないため、追加計算は race_ai/keirin_form_fall_shadow.py に分離した。

## 条件付き自動処理
1. 既存の出走前カード private/cards/<race_id>.json を読み込む。
2. 同レースの追加原本 private/cards/<race_id>.form.json は補正要求として検出するが、このJSONだけでは採用しない。公式登録番号を確認した取得器から渡される `form_evidence_loader` が原資料を再解析し、同一選手との結合を確認して RACE_AI_KEIRIN_PRIVATE_FORM_SUPPLEMENT_V1 を再構成する必要がある。既定CLIにローダーがなければ補正だけHOLDにし、元のA/Bは保存できる。
3. 各PROGRAMの元bytesを private/raw/<sha256>.html に保存する必要がある。既存のraw SHA検査で原本一致を確認。遅い公開時刻、取得時刻、未来の結果、違う選手・レース、重複、存在しない資料はHOLD。推測で補完しない。
4. A/Bは従来のまま締切前作成・RSA/AES暗号保存。追加資料がある場合のみ別のconditioned A/Bを計算し、<race_id>.form.sealed.json にAES-256-GCM/RSA-OAEP-SHA256で独立保存。別runnerはその暗号文SHAを確認する。
5. 研究結果と元のA/Bを混同しない。Cの実履歴ラベルがなくても処理を続ける。

## 事実と判断を分ける
- 事実：公式等の掲載済み落車完走不能、欠場期間、完走順位・出走人数、復帰後の出走、本人・取材コメント、出典の公開・取得時刻。
- 自動評価：直近180日内の完走6走について前3走と直近3走の着順指数の差で上向き・下向き・差が小さい・データ不足を分類。落車については前後それぞれ完走3走以上の成績差を別表示。休養は出典付きの明示欠場期間のみ計算。期間中の出走空白を勝手に「休養」としない。
- 条件付研究係数：近況の差×0.10、十分な落車前後成績差×0.03を加え、合計を±0.08以内に制限する。Aの三連単候補順位、Bの6局面シナリオ相対重みにだけ反映。データ不足なら変更0。
- コメントは原文と件数を記録するが、自動でケガの重さや完治・医療状態を推定しない。落車したというだけで減点しない。落車後の着順差があっても、落車が原因と断定しない。
- 係数と閾値は未校正の研究仮説。実測的中確率ではなく、今後の前向き比較が必要。

## 公開・完成ゲート
Public GitHubに平文買い目、ソースHTML、選手ごとのプライベートデータ、コメント原文、秘密鍵を公開しない。公開ログは件数・ハッシュ・HOLD理由の固定コードのみ。実際の元ページと構造化入力の意味的な一致は、SHAの照合だけでは証明できない。

2026-11-20の追加実装では、公式公開画面の正常な操作から出走表・予想印・コメント・登録番号付きプロフィール・実過去結果を取得する経路と、原資料を読み直して結合する検査を追加した。小倉5Rの6名・44件の過去結果・6件のコメントを実際に取得して照合できたが、この取得確認自体は本番予想の合格ではない。全国全選手の継続取得・全レース対応は別の拡張工程であり、全件完了とは扱わない。

今回のユーザー指示による運用合格条件は、未来の実レース1件で登録番号照合→履歴自動取得→元A/B・補正A/Bの締切前保存→公式結果との同一条件比較を完走すること。既存GitHub内のmain限定ジョブをこの1件のために追加し、既存の実行間隔で処理する。Secrets・権限・外部サービス・公開範囲・課金・投票は変更しない。実合格後の全国拡張まで承認されている。1件の運用合格と、予測精度の改善の証明は分ける。後者には同じ分母での継続的な盲検比較が必要である。詳細は [未来レース受入れ条件](KEIRIN_FUTURE_FORM_CANARY_20261120.md) を参照。
