# RACE AI 高度予測設計 v0.7
設計日: 2026-10-13
状態: DESIGN ONLY（設計登録。実装・実データ受入・映像解析・予測精度は未実証）
対象: ボートレース優先・研究用。自動投票・決済は対象外。

## 0. 整合性と既存基盤
この文書は、別途存在するRACE AI v0.2の公式データ設計、v0.4のF/L研究、v0.5のF/L分類、v0.6の時点付きオッズ・写真機能に対する追加設計である。これらの旧版コードをこのGitHubリポジトリへ移植した事実は確認できていない。今回は設計のみを変更し、ソフトが完成したとは扱わない。

- データは予想時点 decision_at に公開済みかつ取得済みの情報だけを使う。結果、事後映像、最終オッズは過去予想に混入させない。予想は不変の識別子・出典・版・ハッシュで保存する。
- 枠番、艇番、実進入コース、展示進入コースは別の情報。枠と実進入のズレだけを「前付け試行」「抵抗」「押し出しの原因」と確定しない。
- スタート展示ST、本番ST、同一コースの過去STは区別。F/L・欠場・失格・数値不明をST=0として平均に混ぜない。
- 前付けする側と前付けされる側の双方を評価し、特定選手ペアの少数対戦を過大評価しない。
- 標準の最大買い目8点。設定で16・24・32点に拡張可能。期待値が不足するときは0点を許可。予想対象の3連単120通りについて整合的な確率分布を出す。

## 1. 同一実進入コース別の直近ST
### 要件
- 選手登録番号 × 実進入コース1～6で、予想時点より前の最新5走・10走・20走の本番STを集計する。「その選手の直近10走」全体を「同コース直近10走」と呼ばない。
- 最新順のST系列、走数n、最後の該当日、平均、中央値、母標準偏差、最速/最遅、ST順位、F/Lなどの非数値状態件数を記録する。欠けた走は欠けたままにする。
- 年間の同コース平均STと比較し、今節、会場別、ナイター/昼、F前後は標本が足りる場合に限って細分化する。昼夜の違いを直ちに能力差と見なさない。
- 同コースの事例が少ない場合は選手の長期同コース成績、当該コース全体、会場別の基準に階層縮約し、標本数と不確実性区間を表示する。
- 直近スタートが速いというだけで本番のスタート順を確定しない。風、起こし位置、助走距離、展示進入、行き足を併用する。

### 入力仕様
race_id / venue_id / scheduled_start_at / result_published_at / captured_at / player_registration_id / lane_number / actual_entry_course / official_st / start_status / official_start_rank / race_grade / day_night / source_id / raw_sha256。
集計器は結果の published_at と captured_at の双方が decision_at 以下である走のみ採用。選手名ではなく登録番号で結合し、ソース訂正は版履歴を残す。

## 2. オリジナル展示・直前情報の時刻付き保存
### 対象
- 通常展示タイム
- スタート展示の進入とST
- オリジナル展示の1周タイム・回り足タイム・直線タイム
- 公開時刻、取得時刻、展示観測時刻（取得可能な場合）、データ原本、SHA-256、取得権限、改訂履歴
- 直前の風向・風速・波高・気温・水温・潮汐と、同時点のオッズ

### 保全規則
- exhibition_snapshot_id / race_id / player_id / kind / numeric_value_or_null / unit / published_at / captured_at / source_id / raw_sha256 / revision を不変レコードで保存。値の変更時は上書きせず新しい版を追加する。
- 欠測は null と missing_reason（未掲載、取得不能、映像のみ、未許諾、公開時刻不明など）。0を欠測に使わない。
- 予想時点より後に取得した展示や後日の修正表示は、その予想の特徴量に組み込めない。
- 利用条件が未確認なら自動巡回を行わず、許可されたファイル入力・人手記録に限定。ページを見られることと自動取得・再利用の許可は別。
- 展示数値は同条件内で比較する。展示1項目が最速だから他の機力も最強とは断定しない。

## 3. 展示動画の解析設計
### 動画から取得する観測点
1. ピット離れの差
2. 待機行動の進入争い・前付けの試行・抵抗
3. 起こし位置・助走の深さとカド
4. 起こしからスリット付近までの行き足
5. スリット後の直線の伸びと艇間変化
6. 1マーク進入、旋回時の滑り、出口の加速、2マーク以降

### 判定品質
- evidence_id、動画ソース、権利状態、clip_id、動画内時刻、対象艇、観測領域、解析値または序数ラベル、信頼度、人手レビュワー、判定時刻、ラベル版を残す。
- 行き足・伸び足は映像画角・遠近・カメラ追尾が同条件の場合に相対比較。測定根拠のない数値の秒差や速度は表示しない。
- 映像ラベルは VERIFIED_VIDEO / HUMAN_REVIEWED / ESTIMATED / UNKNOWN。映像再生不能、艇識別不確実、遮蔽、画角不一致ならUNKNOWN。
- 映像取得・録画・解析・保存・再配布の権利を提供元ごとに検査。許諾未確認なら外部モデルへ送信しない。利用者提供映像も用途と保存範囲の確認が必要。
- 人手検証で機力評価を校正できるまで「展示動画解析で確認済み」と報告しない。

## 4. 前付けする側・される側の能力
### 定義を分離する
- entry_shift: 枠番と確定実進入コースの違い（結果表から計算できるが、能動的な前付けの証拠ではない）。
- front_attempt: 映像等で内側を取りに動いた試行。
- front_success: その試行で内側を取ったと確認できた結果。
- resistance_attempt: 相手の進入主張に対する抵抗を映像で確認。
- defense_success: 抵抗して進入を維持。
- displacement: 受け手が外側へ移動。誰の行動が原因かは個別映像の証拠がなければUNKNOWN。
- deep_inside: 1コース維持だが起こしが深くなった状態。助走距離の数値は計測根拠がある場合のみ保存し、それ以外は深い/通常/不明の区分。

### 仕掛ける側の分析
- 直近20・50・100走の試行割合と、試行時の取得コース分布。
- 前付け試行成功率、成功後と失敗後の本番ST、1着・2連対・3連対率、決まり手。
- 6号艇から2コースに前付けして得た2コースと、通常の2号艇・2コースは別の条件として比較。
- 選手個別・会場・枠・相手構成・風・展示機力を統計モデルで考慮。内側へ動けたことと勝ちやすくなったことを混同しない。

### される側の分析
- 前付けに対する進入抵抗率、抵抗して維持したときの勝率とST。
- 深インでも逃げ・先マイ・3連対を維持できたか。通常の同じ実進入コースでの成績と比較。
- 外へ押し出されたときの新しい実進入コース別ST、1着・2連対・3連対率、差し/まくり/まくり差しの決まり手。
- 外へ押し出された結果好走した選手を単純に「前付けに強い」と断定せず、会場・相手・艇/モーター・レース条件で調整する。
- 前付けした者とされた者双方の役割をイベント単位で保存する。単に共走しただけのレースは「前付けの成功試行」として数えない。

## 5. 選手ペア別の前付け攻防
### 正規データ構造
entry_interaction_event:
race_id / challenger_registration_id / defender_registration_id / observation_phase / initial_order / attempted_order / exhibition_order / actual_order / front_attempt / resistance_attempt / front_success / defense_success / displacement / deep_inside / start_depth_distance_or_null / evidence_level / video_frame_refs / source_id / published_at / captured_at / reviewer / label_version。

### 集計
- 仕掛ける側Aと受ける側Bのペアについて、試行回数を分母に「内側取得」「受け手の抵抗成功」「外押し出し」「深イン」「攻防後の着順」の率を分ける。
- ペアA→BとB→Aは別集計。同一レースの複数攻防はそれぞれイベントIDで管理し、同じイベントを二重加算しない。
- 試行の映像がない場合は「進入変更統計」にとどめる。特定のAがBを押し出したという因果ラベルは作らない。
- 標本の少ないペアは選手別・実進入コース別の基準分布へ縮約（階層モデルと正則化）。nと不確実性区間を必ず表示。
- n<10は探索用参考表示のみとする初期表示ルール。境界値は実レース検証に応じ見直し、n>=10でも精度保証はしない。
- ペア比較では、2人の艇番、実進入コース、会場、レース時期、助走の深さ、風向、カドの位置、直前展示の機力を条件に入れる。

## 6. 進入シナリオと全120通りの着順予測
- 展示前は通常進入、前付け進入、深イン、カド変化など複数の進入シナリオを確率で表現。
- 展示後は実際の展示進入と展示動画を新しい証拠として更新。ただし本番進入の確定とは扱わない。
- 各シナリオで6艇全員の実進入コース別ST分布、前付け/被前付け適性、深イン、行き足、伸び足、回り足、風、モーター、決まり手相性を評価する。
- 3連単の予測確率はシナリオごとの発生確率×そのシナリオ条件付き3連単確率を合算して求め、全120通りの合計を1にする。
- 発走前の公表/取得時刻付きオッズのみ使用。期待回収率=該当3連単確率×当該時点のオッズ倍率×100。確定払戻は予測時の期待値計算に使わない。
- 標準最大8点、設定で16/24/32点。期待値、較正の誤差と不確実性を考慮してAIが0点を選択可能。自動投票は対象外。
- 取消、返還、同着など現行研究用モデルが扱えない状態は「検証不能」の理由を残し、勝手に有利な結果だけ選別しない。

## 7. 画面表示の要件
- 6艇の比較表: 選手名/番号、枠と進入想定、同コースST直近5/10/20、ST標準偏差、同コース年間ST、展示1周/回り足/直線、映像からの行き足/伸び/ターン、前付け傾向、被前付け耐性。
- 進入シナリオ: 123456、162345等を見やすく表示し、前付け予想時は押し出された側も含め6艇の期待値を再計算。
- 相性表: 「AがBへ前付けを試行したn件」「抵抗成功m件」など、母数、観測の信頼度、期間、出典を併記。動画未確認の場合は「前付け試行未確認」と表示。
- 全指標で根拠、公開時刻、取得時刻、サンプル数、欠測、推測ラベルを閲覧可能にする。
- 買い目ごとの予測確率、オッズ更新時刻、期待回収率、購入見送り、判断時刻と予想ハッシュを確認できる。

## 8. 受入基準とテスト
1. 正式原本で艇番、選手番号、実進入、ST、結果を照合できること。実ファイルなしのモック合格は本番受入合格としない。
2. 同一実進入コース直近5/10/20走を正確に集計。他コース履歴が混入しないこと。
3. F/Lや欠測を0で平均せず、選手番号の異なる同名選手を混同しないこと。
4. オリジナル展示3数値の公開・取得時刻、版、hashを保持し、ページ更新により前回値が消失しないこと。
5. 決定時刻後のオッズ、結果、映像、展示修正が当時の予想に漏洩しないこと。
6. 枠と実進入の差だけでは前付け試行/抵抗/押し出しの因果ラベルにならないこと。
7. 1号艇深イン、2号艇が3コースへ押し出された場合、6艇全員の条件付き着順が更新されること。
8. 未対戦ペア、n=1などで0%/100%に飛ばず基準率へ戻ること。母数と不確実性を表示できること。
9. 展示動画は実再生・利用許諾・艇同定・人手検証が整うまでは解析済みと判定しないこと。
10. 過去未使用期間でベースモデル、ST追加、展示追加、ペア追加、映像追加を同一レース群で比較。進入予測、LogLoss、Brier、確率較正、的中率、回収率、最大損失を検証すること。
11. 開発中の段階で実際の予想精度が改善したとは報告しない。無許諾の取得・公開・配信は行わない。

## 9. 実装順序
P0: B/K公式原本の実ファイル受入 → 実進入/ST正規化 → 同コース直近5/10/20走の自動集計。
P1: 許諾確認済みオリジナル展示、直前気象と時点付きオッズの履歴保存。
P2: 前付けする側/される側のイベント、深イン、外押し出し、ペア別の階層集計。
P3: 利用条件を満たす展示映像の取込、フレーム根拠、人手検証付き行き足・伸び足・ターン・ピット離れ解析。
P4: 進入シナリオと3連単確率モデル統合、通常最大8点/拡張16・24・32点/見送り0点、独立した実レース未使用期間検証。
