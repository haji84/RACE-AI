# 競輪の実データ予測・確率表示・継続検証を接続する実装計画

**Goal:** 直前の全27節・追加6能力を継続し、既存モデルの実データ比較、整合する着順確率の選手画面表示、未来レースの原本固定と独立採点まで進める。

**Spec:** `docs/KEIRIN_DETAILED_DEVELOPMENT_SPEC_20261125.md`。オーナーは今回「完成させて予想精度向上」と明示して継続実装を指示した。既存Python/JS/GitHub運用を使い、新しい基盤や課金は導入しない。

## 境界

- 旧A/B・公開原本・Cの方針を保持。改善候補は別の比較Bとして保存する。
- 公開取得元の実データを私用0700領域で解析する。生の過去データ・予想原本・鍵を公開Gitへ追加しない。
- 過去再現は日付順の研究とし、公開時刻が保存されていない資料を正式な締切前予想と呼ばない。
- 新しい候補と比較方法を固定してから未使用の評価データを採点する。少数の前向き的中を統計的改善としない。
- 全員完走・同着なし条件。全着順、2車単、3連単は既存 `JointFinish` の同じ分布から出す。上位8点だけを確率へ正規化しない。
- 新しい解析の確率は新しいモデル・生成時刻として表示し、古い保存買い目の確率へ後付けしない。

## Task 1: データ復元と固定した比較

- [ ] 先行研究が使った公開GitHubの固定commit・DB・出走表を取得し、SHA、Git blob、期間、欠損、利用条件を確認する。
- [ ] 既存の出走表／登録番号／過去走アダプターを再利用し、学習・調整・評価のデータを分離する。
- [ ] 既存の順序付き順位学習、残差学習、全着順分布を使い、A/B_before/比較Bを同一入力・同一点数で比較する。単一の調整期間で選び、評価期間で再選択しない。
- [ ] 三連単Top4、二車単Top2、Top1/8、確率損失、校正、日別の不確実性、欠損を保存する。結果が改善しない案は採用しない。

## Task 2: 単一予測分布の保存とカルテ接続

- [ ] `JointFinish` の出力をrace_id、全出走車、モデル版、入力SHA、元データSHA、生成時刻、基準時点と結ぶserializerを追加する。
- [ ] 完全な三連単分布から二車単・各着順確率・Top2/3・期待／最頻着順を検査可能な形で出す。
- [ ] JSで有限性・車番集合・全組合せ・確率和・各順位の和・Top3周辺・時点／版を検証する。
- [ ] 選手名から確率と根拠、未評価能力、データ基準を開ける画面へ接続する。旧予想・券種・絞込み・配分・転がしを保全する。
- [ ] GitHub移植画面と既存Siteを区別し、変更した実配信経路で実データを読み戻す。既存Siteのソース取得・公開はSitesの既存権限を使い、新しいバックエンドは作らない。

## Task 3: 未来原本と自動経路

- [ ] 実行時点で未締切の全確認対象について、旧版と比較Bを同じ入力で固定する。欠測は項目別に保留し対象数を残す。
- [ ] 既存の所有者宛て公開鍵暗号／Git保存を再利用し、ローカルの平文を公開しない。原本の復元不能を新規初期化で代用しない。
- [ ] 締切前のGitHub証拠、別実行の読戻し、公式／二媒体結果、画面反映、既存PDCAへの入力を接続する。
- [ ] 全国実行と統計的精度の受入を分け、残るものを完了扱いにしない。
