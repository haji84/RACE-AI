# GitHub Pagesで保存予想を閲覧する

ユーザーは予想を見られるサイトを要求し、まだ公開URLがないと明示した。従来の「進めよ」を引き継ぎ、既存URLの追加質問を繰り返さず実装する。GitHubだけを使う。既存画面・暗号化状態・モデル・原本・実行中workerは保持する。

## 選択

実装上の選択は、既存の7ページをGitHub Pagesに配置し、表示用JSONだけを専用のランダムな32バイト鍵でAES-256-GCM暗号化する方法。公開するのは画面コードと暗号文のみ。閲覧鍵は本人に渡すURLのfragmentにだけ含め、HTTP・Git・公開成果物・ログ・localStorage/sessionStorageには出さない。URLはブラウザの履歴・ブックマークに残り得る。リンクを知っている人が閲覧できる。ログインによる本人認証とは表示しない。

原本の `RACE_AI_STATE_KEY` は別物であり、変更・出力・転用しない。閲覧用鍵は原本SQLiteを解読できない。閲覧URLと鍵の控えはGit外の0600ファイル。画面と暗号文だけの公開ディレクトリとは分離する。

平文予想をPagesに置く方法は原本保護の指示に反する。HTMLファイルの手動読み込みだけでは予想を見られるURLという目的を満たせない。Cloudflare・Vercel・新しいプロバイダー・課金・アクセス権変更は使わない。GitHub Pagesのbranch方式を使用し、Actionsのcontents/pages/id-token権限も追加しない。Pages管理APIが拒否されたら回避せず、公開ブランチと検証結果を準備した状態で必要な設定を具体的に伝える。

## 表示

同期確認済みの朝版156レース・624予想を、既存の純粋なprojectionで読み取る。対象の内容SHAを固定し、別時点の福岡6Rを朝版の分母に混ぜない。モデル・買い目・SHA・時刻・結果観測は元のまま。モデル実行、追加取得、再採点はしない。

ブラウザがURLの `#saved=<cipher_sha256>.<base64url_view_key>` を読み、同一originの固定 `views/<sha>.json` のみを取得し、ハッシュとAES-GCMを検証して既存UIに渡す。公開ファイルと鍵の不一致、改変、上限超過、不正なfragmentは固定の日本語エラーで停止する。鍵を入力する追加操作は不要。

通常の画面遷移では秘密fragmentを保持する。7ページ、モデル・履歴条件選択、日付、リロード、ブランドリンク、スキップリンクで秘密を消さず、外部通信・POST・秘密のブラウザ永続化を発生させない。通常のローカル生成画面とJSON読込は従来通り。

## 公開と検証

公開先は同じpublicリポジトリの `gh-pages` のみ。公開ファイルは固定assetと暗号文、`.nojekyll`、件数・SHAのみのmanifest。未知ファイル、平文JSON、鍵、symlink、改変assetは拒否する。既存Gitの宛先・rewrite拒否・通常push・親commit照合を再利用し、state用のref許可リストを広げない。既存Pagesがあれば上書き前提にせず調べる。

実際のPages設定・HTTPS応答・配信ファイルSHA・本人用リンクでの624予想表示を確認してからURL発行完了と報告する。配信データは検証済みスナップショット。継続自動更新、的中率改善、独立した締切前証明、無期限保存の実証とは扱わない。
