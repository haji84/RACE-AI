# 結果の自動照合と通常のレース画面

ユーザーは、レース終了後の結果・的中確認が止まることと、スクショにある内部モデルID、研究/監査、英語の不足コード、SHA、大きな説明枠を修正するよう指示した。既存の公開承認・GitHub限定・所有者キー・原本保全を継承する。追加の設計/公開確認は求めず、既存のネイティブ実装方式で進める。

## 確認した原因

- 前回の5分ジョブは選手の90日＋当日成績だけを更新し、暗号化した保存予想の結果フィードを更新しない。
- 結果フィードは既存の予想workerの巡回・artifact・表示専用ジョブに依存する。2026-11-07の保存132レース中、確認済み98・未照合34という監査記録があり、最近の表示ジョブは原本maintenanceで結果公開前に失敗している。
- ブラウザの暗号化結果フィード確認は既に60秒間隔。未公開の結果を画面の再読込だけで補えない。
- `renderDetail` は通常のレース画面へ監査用hero、内部版名、不足コード、証拠欄を直接展開している。スクショのびわこ1Rが具体例。

## 採用する接続

既存の5分ジョブを結果だけの読取・照合にも使う。別案の新サービス/新キー/新workerは既存条件と不要な二重収集のため採らない。従来workerへの依存だけを残す方法では、元の停止が解消しない。

既存の `boat-saved-view-input.json` bootstrapを所有者キーで開き、現在の暗号化表示フィードから保存済みレースを読む。予想生成・model intake・原本maintenanceを呼ばない。新しい公式結果は既存SP取得と共用し、1run合計最大12GET・1秒間隔・取得元の待機を維持する。未照合の当日結果を優先し、過去未照合と訂正は残余で再確認する。日別フィードは当日と直近の保存日を扱い、既に終了した前日も取り残さない。

SP結果の `infolist3t` の組番・払戻、`returnlist`、明示された登録番号/着順を厳密に読む。未公表・特払・曖昧な結果を的中/不的中へ変換しない。返還・同着・取消を保持する。結果原文とcursorは既存intradayの暗号化packetに保持し、Kで成績が補完されても未公開の結果packetを落とさない。再取得の表示時刻だけでは更新せず、意味のある結果変更を保存する。

既存の `saved_result_sync.parse_capture` / `saved_view_feed.update_view` を通して登録番号・race_id・元予想時刻を照合し、現在フィードへ結果だけを追記する。元予想・時刻・SHA・正式精度の適格条件は変更しない。同日で公式締切が変わった場合は、raw-bound SPの全艇一致と全予想が両方の締切より前に保存されていることを確認した表示用参考だけを許す。正式適格へ昇格しない。競合更新はCASで止め、保持したpacketから次回やり直す。

既存の小さな `racer-live-status.json` へ結果同期の状態・確認時刻・件数だけを任意追加し、通常画面でも「確認中/更新済み/確認待ち」が分かるようにする。公開の原文/レース別予想/キー/平文SQLiteは追加しない。初期化し直さず、既存の全世代を残す。GitHubの5分起動と配信待ちがあり、終了直後の秒単位保証とは称さない。

## 通常の画面

レース名・締切・予想・結果と的中判定を先に置く。発走・状態の未取得を連ねず、巨大な監査heroを除く。モデル選択は日本語名＋朝/直前で短くし、未学習等の重要な性質は短い「参考予想」で残し、内部ID/版/時刻/SHAは閉じた詳細へ置く。英語不足コードを通常画面へ出さず、結果未同期は「公式結果を確認中」と説明する。合成データは合成表示を維持し、未確定を不的中として扱わない。

結果はレースを開いた時に見つけやすい場所へ置き、当選組番・保存予想との一致・返還・最終確認を示す。モデル切替・会場・日付・選手カルテ・買い目編集中の内容を維持する。結果の表示更新ボタンは暗号化フィードを読み直すだけで、投票やモデル再実行をしない。技術的な監査情報は折りたたんだ詳細から確認できる。

## 受入

架空の「保存予想→締切→公式未公表→確定→的中/不的中→払戻訂正」を実Git・既存暗号化feed・ブラウザまで通す。返還・同着・取消、誤登録番号、異日/未来、元予想改変、同時writer、状態破損、K補完後の結果保持、予算編集中の表示保全を試験する。実SP原文を私有領域で検証し、実Actionsで旧保存予想への結果反映と公開画面を確認する。スクショの320/390pxとPC1440pxで、通常画面に内部コード/SHA/監査heroが露出しないことを確認する。
