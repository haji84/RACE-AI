# 6艇の画像内番号追跡を完成させる設計

ユーザーは完成までの実装・テストを明示しており、設計質問の追加を求めていない。以下は実装担当の判断。既存PR71だけで進め、本番モデル・稼働中の自動予想を切り替えない。

## 実測した原因と選択

既存日本動画の可読番号12領域は全て追跡より前で失敗した。艇検出漏れ、重なった艇体の一括除外、番号の局所化失敗、過大な加工が原因で、時間条件を緩めても直らない。固定horizontal-bandで候補4個の切捨てだけを外すと、同じ条件で4/12から11/12、全6種類を含む自動番号領域になる。既存全37文字CRNNの手動位置によるnative診断は10/12だが、これは自動識別の成功ではない。

選択は「印字番号の領域を主対象にして画像内で追跡する」。艇体全体を主対象とする案は自然な重なりで番号まで捨てるため採用しない。新しい予想モデル系統は作らず、既存CRNNと原画素を再利用する。新しい学習済みCV重みが必要になれば、まず固定実験で必要性を検証し、既存原本を上書きしない。

## 契約

- `race_ai/boat_video_marker_identity.py` の `MarkerIdentityTracker(min_observations=3,max_gap_seconds=.5)` が `update(frame, markers, *, t, frame_index, scene)` を受ける。markersは原画像内の`box:[x,y,w,h]`, `text:str`, `sequence_likelihood:float|None`, `context_status` を持つ。contextは `SINGLE_MARK` / `MULTIDIGIT_GROUP` / `NONTARGET` / `AMBIGUOUS`。画像と入力全体の検査後に状態を更新する。
- 番号は1〜6の実OCRだけから得る。3回以上の別の原frame・PTS・画素観測が必要。同一画面の複数crop/加工を別観測に数えない。raw likelihoodを確率や的中率とは表示しない。
- 画像内の位置・速度による一対一対応でmarkerを追う。過去に確立した番号は、同じmarkerが可視で、明確な対応があり、最後の番号観測から.5秒以内の場合だけ、OCR不読時にも由来を明記して保持できる。marker自体が消えた位置を補間して出力しない。
- scene/時刻/画像サイズの不連続、重複番号、異番号の競合、曖昧な対応、機材64等の複数字文脈、overlayではUNKNOWNまたは証拠をリセットする。色や艇番の消去法をID根拠にしない。
- 出力は `RACE_AI_BOAT_MARKER_IDENTITY_OBSERVATION_V1`、`coordinate_space=IMAGE_PX`、番号marker box、track_id、根拠frame/時刻/SHAを持つ。`hull_box=null`を許し、全艇体の位置・world座標・強さ・本番適格を推定しない。`identity_validated=false/model_eligible=false`を維持する。
- full-frame番号localizer/readerは別moduleとし、原画素の自動局所化と既存全37文字CRNNを使う。semantic contextで複数字や非番号を区別し、候補を切り捨てたことを完全処理と偽らない。全候補の診断で有効性を確かめてから製品経路へ組み込む。
- 既存のTesseract/CRNN factory、camera policy、位置計測のdefaultは変えない。新経路は明示的な画像内識別用とする。録画/保存・予想原本・本番切替は別の条件を維持する。

## 実動画の受入

原本から出力を見ない別担当が、番号アンカー付きの6本の短い連続区間を封印する。Nesnad既存動画は可視範囲が変わるため、全25秒の6艇同時表示を正解として捏造しない。6種類それぞれの自動識別と可視frameの連続対応、誤番号、swap、欠測を評価する。手動ROIを識別器へ渡さない。

既存Toda原本も通常公開取得のlocal provenanceがあるが、権利・日時・公式真正性UNKNOWNを保持した私有CV診断だけに使う。既拒否sourceの別host取得、原本の公開/再配布、学習許諾や本番レース認証への昇格はしない。

実参照はAIによる開発用で、人間の正解・独立holdoutではない。6クラスの短い実測と一般的な現場精度、現在LIVE取得、強さ評価、予想改善を混同しない。6種類の実画素での識別に達しない限り完成と報告しない。

## 実測後の読み取りと統合

全3,060自動領域の英数37文字CRNNは固定参照8/12、日本語の一部も含むPP-OCRv4全6,625クラスは10/12で、後者は1〜6を全て含む。ただし生の数字出力692件には既知の非数字誤読8件があり、OCRだけを艇番へ昇格させない。PPの平均文字scoreと実際の1文字CTC経路和を区別し、語彙を数字だけへ再正規化しない。私有の明示パス・SHA固定・CPU用の任意依存として追加し、既定エンジンを切り替えない。

Nesnad原本の既存12数字・5非数字とsynthetic字体による7クラス（数字1〜6・reject0）のHOG/SVM、および同原本の数字周辺・岸の非対象領域による二値context分類器を開発用に固定した。重みは私有のCC BY-SA 4.0由来資産として保存し、Gitへ入れない。Toda原本を訓練に使わない。これらの分類を使う経路は明示opt-inとし、`DECLARED_DEVELOPMENT_GLYPH_CLASSIFIER`・モデルSHA・`sequence_likelihood=null`・非確率scopeを記録する。汎用OCRの「7」を文字列から「1」へ置換する処理ではなく、別の教師あり画像分類結果である。学習重複のある開発評価であり、独立精度や本番適格を示さない。

`MarkerIdentityPipeline`は全画面の自動候補抽出、任意の読み取り・分類器、実画素のcontext追跡、3別frameの番号証拠を統合する。同じ数字の内包候補は大きい領域1個へまとめ、rawは保持する。異番号の重なり・別位置の重複番号はUNKNOWNとする。再検出した現在の番号位置で追跡中の相対位置を補正し、context外なら明示的に再seedする。再検出と局所読みを同一frameの2票へ数えない。番号の見えない位置やworld座標・強さは出力しない。

現在の全76原frameを使った製品moduleの開発検証では1〜6の登録出力があるが、画面内での連続coverage・誤登録・swapは別に原画と照合する。累積した登録数、静止画の正読、6個の番号が一度現れた事実を、6艇の継続識別の完成へ読み替えない。
