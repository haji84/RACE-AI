# 日次の選手成績接続

ユーザーは「毎日の結果取得→選手別・コース別の再集計→カルテ反映」が未接続という説明を受け、「接続して」と実装を指示した。公開承認とGitHubのみの制約を継承する。追加の選択・確認を依頼しない。

## 実装方針

既存公式K日次アーカイブの厳密なパーサーと、所有者認証済み月別履歴を再利用する。直近90暦日を表示期間とし、期別の得点勝率とは別に1着率・2連率・3連率・正常STの平均を示す。失格/F/L等の実出走は率の分母に含め、欠場と不明進入を区別する。欠測日・未報告場・ST標本数も明示する。

取得済み月別履歴から直近90日を初期投入する案を採用する。90日分を再取得する案は不要な取得を増やし、収集開始以降だけを90日成績と呼ぶ案は対象範囲を誤認させるため採用しない。毎朝06:20 JSTに前日までの未取得日と直近訂正を有限回数で取得する。最大7 GET/run、同一取得元は1秒以上空け、429/拒否/形式不一致では保留する。

原文と状態は既存state/boat-pdca-transfer内の独立namespaceへ既存所有者キーで暗号化・追記する。新しい鍵やサービスを作らず、予想原本・既存stateの他namespaceを変更しない。公開するのは選手別集計JSONだけで、予想・SQLite・結果原文を含めない。日次JSONはgh-pagesの独立固定パスへ更新し、UIの通常公開や保存予想の更新で上書きしない。本番カルテは既存CSPで許可されたraw.githubusercontent.com/haji84/RACE-AI/gh-pages/data/racer-daily.jsonを読み、ActionsのGITHUB_TOKENによるpushがPagesビルドを発火しない制約を回避する。追加権限や外部サービスは不要。更新時点・期間・不足を示し、期別成績は保持する。ローカルは同一origin、オフラインは埋め込みJSONを使用する。

履歴のGit取得は全commit/treeを維持するblob:noneフィルターを使い、実際に読む暗号文だけ取得する。初回実行で全namespaceの履歴一括転送が停止し、新規runner相当の比較では通常取得約1.5GiBに対しcommit/treeは約8MiBだった。古い世代はMAC付きheadの連鎖と元commit/現在treeの同一blobを検証し、不要な旧暗号文のダウンロードを避ける。設定は各Gitコマンドの環境内に限定し、共有リポジトリのconfigを変更しない。

部分取得した親treeへの追記ではwrite-tree --missing-okを使う。通常のwrite-treeが未取得の継承blobまで実体化して停止することを実runnerのコード位置で特定し、別namespaceの1MiB暗号文・旧世代暗号文を取得せず第3世代を正常pushできる試験で再現・修正した。親treeは検証済みremote上に固定し、新しいblobはローカルでhash-object済み、push先の完全性検査とCAS・同一tree検証は維持する。診断出力は例外の種類とコード位置のみで、例外本文・コマンド引数・原文・変数値を出さない。

GitHubの定期実行はmain上のworkflowに限られる。実装は既存PR71へ追加し、定期実行用の1workflowだけをmain向けの独立PRにする。mainの保護・既存CIを回避せず、PR71の他の作業をmainへ混ぜない。workflowはレビュー済み実装SHAを固定して実行する。初回の実収集・反映を確認してから有効化を完了扱いとする。

## 検証と失敗時

同一日の再実行は二重計上せず、訂正は原文履歴を保持して最新解釈を再集計する。状態の欠損・MAC/AES不一致を空DBへ置き換えない。失敗時は前回の正常集計を維持し、取得・成功時点を偽らない。保存予想・買い目・全イラストを保持し、古いレースの予想入力へ新しい集計を入れない。
