# Independent official racer-name binding

The owner requires B abbreviations to be resolved through registration-linked independent official evidence, never guessed suffixes or prefix-only identity checks. Existing118 baselines and the display/original v1 receipts remain immutable. This component supplies a separately versioned, time-stamped identity proof; it does not yet adopt that proof into a new prediction model or change v1 validators.

An exact current-day official racelist body must establish date/venue/race, closing time, all six lanes, printed registrations and both matching registration profile links. Reuse `parse_official_racelist`; a registration in the request URL alone is insufficient. The new proof pins the frozen baseline snapshot ID, its original B archive SHA, and its original six-boat identity digest. It retains both the B name and the independently observed full name.

All six registrations and lanes must agree. Canonically equal names use `EXACT_CANONICAL_NAME`. A different name is accepted only as `VERIFIED_B_ABBREVIATION` when the B canonical name is exactly four characters and is a strict prefix of the longer official name, AND the independent complete racelist registration/body evidence passes. The lexical check is a consistency restriction, never identity evidence. Other name changes fail closed for a future explicit contract. Raw observations and original B names are not rewritten.

The proof records the actual source capture/availability, generation, local exclusive write/readback and cloud immutable write/readback clocks separately. Unknown upstream publication remains null. Proof/source/runner/cloud clocks cannot cross JST date or race closing when publishing. Readers can inspect a previously saved proof after closing on the same day. No historical source can be reintroduced as a previous prediction input. Later consumers must pin the exact proof receipt and respect its actual availability; B-only input names alone do not establish physical exhibition phase.

Only the existing owner-attested official racelist scope is used, at most one1MB/10s GET per selected race. No B archive/day refresh, original/media reacquisition, raw HTML retention, credentials, trust widening or Production changes. Preview publication reuses the exact existing OIDC verifier, workflow branch/name/environment/audience/subject/concurrency; auth code/settings do not change.

Protected Blob saves use new name-binding namespaces. They keep immutable proof versions and nonce receipts, then update a verified latest pointer only if chronologically newer. The binding references a fully verified existing baseline, whose bytes and program identity remain unchanged. Old v1 APIs and prediction builders do not consume aliases implicitly. This staged identity foundation is incomplete for end-to-end alias-aware exhibition/model/UI integration until that separate version is implemented and measured.

An immutable finalization marker is mandatory for every pinned/latest API read. Its trusted `receipt_confirmed_at` is measured after exact receipt-byte readback and must satisfy body-cloud-save <= receipt-confirmation < closing, same JST date. An unmarked orphan receipt is ineligible. The marker pins exact receipt SHA, nonce, snapshot, original baseline nonce/ID/archive/program identity. Marker persistence and discovery-pointer persistence are not claimed to occur before closing; these record/discover an already observed pre-close durable receipt and are never prediction-input timing evidence. Latest writes begin only after a fresh pre-close check. API reads resolve the original immutable baseline nonce, never its mutable latest pointer. The original baseline cloud save must precede the new source capture.

Live proof should use one previously untested future race with an actual B abbreviation, chosen from the approved saved program, e.g. Marugame3R/registration3584 if its actual cutoff still permits. No formal full name is inferred beforehand. Full normalized backup bytes and protected API must replay, alongside preserved118 baselines/legacy post digests. UNVALIDATED, skip, empty recommendations and the existing video/physical-calibration limits remain.
