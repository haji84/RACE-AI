# P0 予想処理の新しいトリガー：公式直前情報が掲載されたら（2026-10-24）

関連：[Issue #67](https://github.com/haji84/RACE-AI/issues/67) / [Draft PR #72](https://github.com/haji84/RACE-AI/pull/72) / 既存高度予想 [Draft PR #71](https://github.com/haji84/RACE-AI/pull/71)。

## ユーザーが指定した最終ルール

従来の「締切まで2〜10分のレースだけ調べる」は**本来の選定方針ではなくなった**。今回以降の主判定は **公式BOAT RACEの当該レース `beforeinfo` が初めて実際に`AVAILABLE`として観測されたこと**。公開前は`PENDING`として選ばない。**締切10分前より早く情報が出た場合も候補に含める。**

1. 当日公式Bから全開催・全Rの予定締切を把握して、終了済みを除いて締切の早い順で候補化。デフォルトに**最大10分の時間上限は設定しない**。最終公式投票締切が確認されるまでは締切をあくまで予定時刻と明記する。
2. 第三者サイトの更新やオッズを公開判定に使わず、該当レースの公式`beforeinfo`を**実際に取得/正規化した時点で`status=AVAILABLE`**、日付・場・R・6艇登録番号の整合と**取得完了時刻が締切前**であることを確認する。この時点で「**入力確認の開始候補**」になる。
3. 展示タイム/ST、当日の風・波、過去K履歴、元ソースの独立公表時刻・取得時刻、用途別許諾、科学的に根拠ある相対風向/水面係数を別々にチェック。**`AVAILABLE`でも展示STがF/L/PENDINGなら欠測のまま**。元PR #71総合・展開モデルが要求する数値・出典と権限が揃わない間は`NO_FORECAST`。実行準備が整ったレース同士の中では予定締切の早いものを先に処理。
4. **モデルの実行→全120通り→各最大8点→締切前の外部書込み・読戻し**が全条件成立した場合だけモデル別`PREDICTION_FROZEN`。時刻切れなら後出しTop8禁止。結果・配当・返還・改訂は公式確定後に独立取得して照合し、予想内容は変えない。
5. 同じレースが観測済みなら重複処理しない。原データの取得・長期キャッシュ、イベント監視や定期的なアクセスについては、**別のソース別権限・レート・費用の受入審査が必要**。常時監視・公式側の「掲載された瞬間の通知」を現在の試験コードだけで自動実現したとは報告しない。

### 必要な状態分類

| 状態 | 意味 | 予想できるか |
| --- | --- | --- |
| `PENDING` | 公式直前情報を観測したが未掲載 | **まだ選ばない** |
| `PREVIEW_AVAILABLE` | 公式直前情報の存在・レース一致を観測 | 入力充足審査を**開始**。10分上限なし |
| `PREVIEW_PARTIAL` | 直前情報はあるが展示ST等に欠測 | 欠測を明記。PR71 FULLは**未実行** |
| `INPUTS_ADMITTED` | K/全展示/風波・出典時刻・目的権限等、既存入力契約を全て充足 | 既存PR71推論を開始可能 |
| `PREDICTION_FROZEN` | 別モデルごとに締切前の永続書込/独立受付/読戻し成功 | 正式照合対象の候補 |
| `CUTOFF_PASSED` | 受付締切を過ぎた | 新規確定は禁止、未予想は評価台帳に残す |

## 今回の具体的なGitHub変更

- `race_ai/boat_deadline_first_selector.py`：`all_closing_candidates(...,min_minutes=0,max_minutes=None)`を標準化し、10分超で除外する条件を**撤去**。既存の明示的な短時間の試験モードでは任意の`max_minutes`を指定できるが、通常運用の制約にはしない。
- `pick_first_published_preview`：公式`AVAILABLE`とレース本人確認・締切前取得の組のみを「公開観測済み」として締切最早順に採択。これはsource publication original時刻の独立証明ではなく、モデル用データの用途許可でもない。
- `scripts/p0_cutoff_ordered_preview_20261024.py`：旧「最初の2候補を締切2〜10分で判定」から「当日公式Bの未終了候補を締切順に最大2件だけ前時点ページ確認、公式`AVAILABLE`を選定トリガーとし、**完全展示数値が揃った候補とは別のフィールド**で保存」に変更。`selected_race`は**公式直前情報観測済み候補**、`numeric_ready_race`は**6艇展示タイム/STと風波の数値が揃った候補**であって、まだPR71 FULLの正式な推論・8点やsource-use許可ではない。
- `tests/test_boat_deadline_first_selector.py` / `tests/test_p0_beforeinfo_publication_trigger.py`：締切まで29分・40分あるレースでも公式`AVAILABLE`なら候補となること、未掲載・非数値展示ST・締切超過・誤った日時やref・勝手な外部アクセスを拒否することを合成条件でテストする。
- 上記コードは**2026-10-24固定・一回限りの研究用統合試験**。今後の全レースの即時検知・再開復旧・ライブモデル運用には、公式に適した入力配信と継続運転の別実装・独立検査が必要。これを`今すでに直前情報が出た瞬間に動く`と誤報しない。
- 旧3指標B-LITEは比較用。PR #71の総合・展開・条件付きモデルと旧予想SHAは**一切変更していない**。
