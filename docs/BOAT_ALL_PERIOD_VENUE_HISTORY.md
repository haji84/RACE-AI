## 集計定義

`VenueHistory.profile(racer_id, venue_code, as_of=...)` と `profiles()` は全24場を返す。分母・対象期間・原本SHA集合・取得可用時刻を保持する。予想モデル・係数・学習・原本予想は変更しない。

- `opportunities`: 取得原本に記録された対象選手の機会数。生涯出走数の主張ではない。
- 1着率/2連率/3連率: **数値着順1〜6の記録数**を分母に計算。F/L/K/S・欠測は別件数として表示し、黙って消さない。提供元や公式番組表の当地勝率とは区別する。
- ST平均・母標準偏差: OK STだけを使う。整数の1/100秒の和・二乗和で集計し、F/L/未取得を0秒としない。
- コース別成績は過去の実進入コースだけで分類。艇番から実進入を補わない。
- 内側進入・外側変位は観測回数。前付けの意図を断定しない。
- 決まり手は公式Kの既存分類を再利用。1コース敗戦時の勝者決まり手は**代理指標**であり、当該選手が直接まくられた事実ではない。同着は特別結果件数を保持する。
- 公式の当地勝率/当地2連率/当地3連率、グレード、モーター交換周期はKファイルに十分な項目/時点証拠が無いため未提供。全国成績を当地成績へ代用しない。
- 「観測した直近30走」と「本当の直近30走」を混同しない。欠けた日付がある間は正式な直近特徴量・正式バックテストに使わない。

状態は `PARTIAL_OBSERVED` / `INCOMPLETE_NO_OBSERVATIONS` / `COMPLETE_OBSERVED` / `COMPLETE_NO_OBSERVATIONS`。最後の2状態は指定した**全暦日原本**が完全に解析済みの場合のみ。全生涯の未出走証明ではない。

## 全期間の取得・保存・再開

`HistoryMonth` は原LZHと観測改訂を月単位SQLiteに保持する。既存8MiB上限を拡大せず、263か月を別々のAES-256-GCM checkpointにする。A→B→Aも原本を消さず、最新観測を選ぶ。不正形式の原本はQUARANTINED、公開索引掲載なのに404はMISSINGとして残し、休催とは判定しない。

`collect-all` は明示的な初回 `--initialize` と、所有者の `RACE_AI_STATE_KEY` を必須とする。通常再開で進捗や月別checkpointが消えていたら停止する。認証済みbootstrapを取得前に保存し、月ごとの原本はcreate-only checkpoint、進捗は所有者キーに結び付いたHMACを持つ。進捗ポインタの更新中断は保存済み署名版から回復する。完了した暗号化checkpointや待機receiptが孤立しても再取得・上書きせず検証して再開する。

HTTPは公式ホストの許可URLだけ、redirect拒否、サイズ上限、逐次1秒間隔。これはローカル運用間隔であって提供元公表の数値quotaではない。429/Retry-After/403/通信失敗は既存 `source_retry_policy` の待機を保存し、inline retryや別サービスへ切替えない。最初のメニュー取得で失敗しても認証済み待機を保存する。

取得対象日は初回メニュー観測時のJST日まで。すでに掲載されている当日ファイルを昨日までに切って取得完了と称さない。未来の日付の入力が索引に含まれる場合は除外件数を保持し、そのまま全掲載分取得完了としない。

所有者キーが無ければ、全期間・月単位とも `HOLD_OWNER_STATE_KEY_MISSING`、追加GET0で停止する。合成キー、GITHUB_TOKENからの鍵生成はしない。

既存 `forecast-audit-ui.yml` の既存intake/readbackに、最初の掲載月200501の**最大5ファイル**のcheckpointと別job復元を追加した。新workflowや定期処理は無い。この一回の限定batchは全263か月を自動運用済みという意味ではない。全期間収集の実行入口は下記CLIで、確保した署名進捗と暗号化月別原本を再利用する。

```
python -m scripts.boat_venue_history inspect --source-dir /private/raw \
  --term-file /private/fan2604.lzh --menu-file /private/official-k-menu.html --end 2026-11-05
python -m scripts.boat_venue_history collect-all --out-dir /private/history --initialize
# 次の実行は --initialize を付けず、既存進捗を検証して続行
python -m scripts.boat_venue_history collect-all --out-dir /private/history --max-months 1
python -m scripts.boat_venue_history capture-month --month 200501 --out-dir /private/month-attempt
python -m scripts.boat_venue_history restore-month --month 200501 --folder /private/month-attempt
```

全期間の長期保管やGitHub artifact/cacheの期限・退避は別の受入条件。現行の7日artifactだけで永久保存を達成したとは報告しない。原本を暗号化せず公開する方法でキー不足を回避しない。
