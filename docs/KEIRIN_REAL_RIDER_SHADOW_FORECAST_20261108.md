# KEIRIN 実選手データ対応：部分入力シャドー予想と正式PR71の分離

更新 2026-11-08。関連：Draft PR #101 / Issue #67。

## なぜ必要か

非楽天の実出走表（KEIRIN HEX、netkeirinなど）では選手名、級班、競走得点、S/H/B、決まり手、想定ラインが得られる一方、既存PR71は別に「終盤加速」「持久力」「連携成功度」「適性」などの正規化済み必須入力を必要とする。**公開されていない能力を推測で捏造してフルPR71を動かすことは禁止**。

2026-11-08松山7Rは、非楽天KEIRIN HEXの公表資料から7選手・競走得点・S/H/B・決まり手・想定ラインが確認できる例。ただし同じレースでも公開サイト間で集計期間・得点の丸め・掲載率が食い違う場合があり、別サイトの生データを無根拠に混ぜてはいけない。研究値と出走時点の証拠を分ける。

## 今回の追加実装

- `race_ai/keirin_real_rider_shadow.py`：既存 `assemble_permitted_pre_race` を呼び**347/437全検査項目の確認状態**を作ったうえで、実際に根拠付きで取得済みの競走得点、B本数/出走数、逃/捲の実績、想定ラインだけで研究用の**全210/504組合せ→上位8点**を計算する。
- `race_ai/keirin_real_shadow_intake.py`：本人の非公開 `inbox/raw/*.json` の実レース観測値を拾い、`inbox/shadow_pre/` に予想原本を一度だけ保存。すでに同一レースがある場合は書き換えない。
- `scripts/keirin_permissioned_owner_agent.py`：本人保管データの取り込みにこの別研究ルートを接続。既存のPR71とは**別モデル・別保存先**で並走する。PR71に欠測値を流さない。
- `tests/test_keirin_real_rider_shadow.py`：7車の合成実測形状を対象に、347件の状態記録、未取得の保留、全210通りの上位8点、得点無上限、締切65秒前の禁止、ソースなし/市場情報混入の拒否、非公開原本の二重保存禁止を確認。

## 仮説と事実

予想対象の**実選手名/得点/S/H/B/決まり手**は資料の事実データ。**想定ライン**は出走前の仮説で当日の実走順ではない。スコア係数やライン組合せ補正は**未学習の設計値**で、特定レースの勝率/的中率を実測校正したものではない。

システムは、実際に確認できない選手の直前体調・怪我理由・展開の実績・風による有利不利を**入力しない**。必須項目の欠測がある場合、**正式PR71は停止し、部分入力シャドーだけを研究用として作る**。シャドーの点数は原則8点だが**買い推奨ではない**。

## 完成判定・未実証事項

今回のルートは、適正に提供された非楽天の非公開データを受け取れば未来レースの未校正**研究予想**を自動計算・保存できる。ただしサイトを自動巡回するコードではない。一般公開ページを閲覧・保存できることと、第三者サイトの無人機械取得/学習/商用再利用が許可されることは異なる。

- 合成CI成功：347状態検査＋予想8点＋原本一度きり保存。
- 正式PR71完成：**未**。欠測が残っていれば停止する仕様を維持。
- 実レースの全資料自動取得：**未**。正当な継続供給元は未接続。
- 実レース締切前の独立した署名/証明・公式結果との正式照合：**未**。
- 本番main統合、車券購入、課金、結果リーク：実施しない。
- **「研究シャドー8点」≠「既存PR71の正式8点」≠「実際の的中率98%」**。

## 前向きの継続運用

すでに非公開ローカルの `inbox/raw/` へ日時・取得元・race_id・直近の選手成績とラインが含まれるJSONが到着する場合、常駐中のオーナー用エージェントは締切前の処理でシャドーを保存する。出走表ページを事前に開いた人の保存作業は別で、自動化が完了したとはみなさない。
