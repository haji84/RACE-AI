上位要件: Issue #67（4競技予想・PDCA）、実装優先: Issue #68。
参照元: docs/RACE_AI_REQUIREMENTS_20261015.md（53章要求整理）、AGENTS.md、PROJECT_STATE.md、ROADMAP.md、RACE-AI PR #59–65、KEIRIN-AI PR #1。

## 1. 変更理由・範囲
- ZBookの停止・フリーズ・電源OFFで、当日出走表の収集、締切前予想凍結、公式結果照合、PDCAが止まらない構造を目指す。ZBookは任意の重い学習・映像研究・開発用で、通常の4競技予想運用の必須依存にしない。
- ボート優先の既存53章詳細要件を削除せず、競輪・オートレース・競馬の別ルール/モデルを新設する。各競技の取得許諾・実動作証拠が揃うまで「全競技完了」と表示しない。
- GitHub Actionsはまず**再現可能なCI / 収集・予想・結果照合の短時間バッチ**を担う。定期ジョブは遅延・欠落し得るため締切ジャスト実行を前提にせず、予告・予備実行・未処理回収を設計する。
- Cloudflare Workers/Queues/D1/R2等は**比較候補**。既存Vercel Preview/Blobの置換や本番切替は別の権利・コスト・移行・実接続検証後の承認事項。GitHub Actionsが永続サーバーや長時間GPUに向くという前提を置かない。
- Codexはコード作成とPRの担当であり、Actionsはワークフローの実行担当。Actions導入だけでCodexが無人開発を継続するとはみなさない。実装/レビュー/承認の分離を維持。

## 3. 実行アーキテクチャと依存関係
1. **Discovery（Actions）**: 許可されたソースで対象日の4競技開催・全Rを発見し、`sport/venue/event_date_JST/race_no/meet`の安定IDで台帳化。欠測と「開催なし」を混同しない。
2. **Ingestion（Actionsまたは既存Worker）**: 適法取得が確認できた情報だけ、時刻・原出典・用途別許諾・訂正履歴・ハッシュ付きで更新。必要データの種類は競技別ソースマトリクスに列挙し、取得不能データは未知として記録。
3. **Snapshot & Forecast**: 締切時刻を実データで検証し、十分なバッファを確保して事前特徴量スナップショットを作成。事前公開時刻/取得時刻/実保存時刻が締切以前であることを機械検証し、オッズなしの全組合せランキング上位最大8点をappend-onlyで凍結。**締切後の新規凍結や予想の遡及変更を禁止**。出走変更後は許容時刻内のみ新しい版を作成。
4. **Settlement & PDCA**: 公式の確定結果と払戻・返還・中止・訂正を別版で受領。締切前に本当に保存された予想のみスコア化し、1点/8点的中、正しい投資分母の回収率、確率が校正済ならBrier/LogLoss/校正誤差、捕捉率・見送り率・欠測率を記録。
5. **Training & Promotion**: 学習・検証・未使用未来レースを分け、モデル候補は既存版と同一の前向きコホートで比較。実測改善・安全/権利・回帰テストが満たされるまで自動昇格しない。重い学習/映像は任意のZBook/承認済み計算資源に隔離し、その不稼働が通常バッチを止めない。
6. **Read/API/UI**: 既存の認証・private Blob・API・Preview保護を再利用。外部公開・Cloudflare移転・Production変更は別の移行審査で決める。

## 4. 収集情報の完全性・権利・鮮度
- **共通**: 開催日/締切/発走/出走変更、参加ID、過去戦績の時点、選手/馬のコンディションとして正規公開された事実、コース・気象/路面等、確定結果と払戻。独自推定は一次事実と別フィールド。
- **ボート**: 進入・コース別ST、モーター/艇、整備、F/L、展示/オリジナル展示、風/波/水面、過去対戦、直前変更、公式結果。
- **競輪**: 7/9車等の参加数・点数・近走・脚質・決まり手・S/H/B・ライン/番手・競輪場適性・風・欠場/並び変更、公式結果。
- **オート**: ハンデ・試走・スタート・機力/整備・走路湿乾・天候・反則/欠車・公式結果。
- **競馬**: 主催(JRA/地方)・馬/騎手/調教師・枠・斤量・コース/距離・上がり/ラップ・近走/調教/血統（許諾がある範囲）・馬場/気象・取消/除外、公式結果。
- すべてに`source_url/source_id/permission_scope/available_at/captured_at/normalized_at/as_of/content_hash/revision`と欠測理由を持たせる。法律・規約・契約の**用途別**条件を確認し、権利不明の収集/保存/学習/再配信は停止する。動画は個別審査。スクレイピングが許されると推定しない。
- ソース別の鮮度SLO案は実測後に決める。未取得/失敗/未開催/中止/払戻待ちを区別する。

## 5. Actionsの運用要件
- Cron/scheduleは正確な締切保証ではない。ジョブ起動/開始/終了/予想実保存と締切のずれを計測。保守的な事前凍結、安全余裕不足の`MISSED_DEADLINE`、未処理回収と重複防止をテストする。
- `workflow_dispatch`で同一開催の再実行/障害再現を行えるようにするが、**不確実な既存POST、STOPPED状態、nonceは勝手に再投入しない**。
- 分離ワークフロー: CI、日次発見、取得、事前予想、結果照合、週次/日次PDCA。必ずしも別ジョブ数を増やす必要はなく実装責任と証拠を分離する。
- 各実行は実行ID/commit SHA/モデル版/収集範囲/件数/失敗理由/保存版/入力SHAと成果物SHAを記録。秘密情報/個人情報/許諾不明資料をGitHub artifactsやPublicリポジトリへ保存しない。
- Private storageへの書込は最小権限の認証済み経路のみ。未信頼PRから特権実行やSecretsへのアクセスを与えない。GitHub Actions無料枠/ストレージ/外部API/Cloudflare/Vercelのコストはユーザー上限と予算ゲートで監視。新たな支払い条件は承認。
- 予想実行に必要な状態はCIワークスペースにだけ置かない。分断/失敗/再起動/同時起動から復旧し、予想を事後上書きしない。
- Cloudflare利用は正式な価格/制限/認証/互換性比較と既存Preview/Productionの非破壊移行E2E成功後の別決定。**この仕様書はCloudflare移行の実施承認ではない**。

## 6. 開発の権限・検証
- Codexは最新main/PR #59–65/Issue #67–68を確認して既存機能の再利用表を作る。PR #61に本仕様が保存されているか確認し、採用後に正式仕様/AGENTS/ROADMAP/PROJECT_STATEと実装の差分を追跡。
- 既存依存スタックを無条件にマージしない。main保護、正確なheadのCI、開発者から独立したレビュー（CodeRabbit不可）、実データ・実端末確認、最後のHuman Gateを維持。
- マージは変更要件の実装→テスト→独立レビュー→依存整合→main統合→実動作の単位ごと。PR数で成果を測定せず、未統合の増殖を防止。
- 今回の新要件は実装コード/ワークフローを追加していない。Codexが許可された安全工程から着手し、実装の開始や自律運用を作成時点では主張しない。

## 7. 受入試験と完成条件
1. ボート/競輪/オート/競馬の合成fixtureで日次発見→更新→締切前オッズなし8点凍結→結果訂正→PDCAが再現できる。
2. 少なくとも合法に使用できる**実データで1競技1レースのE2E**を証拠化。4競技それぞれは許諾の取れたソースから個別に実E2Eを通し、全競技完了には各競技の実証が必要。
3. ZBookが停止・通信断でも、許可されたクラウド実行の取得/予想/検証が完了する実測（別環境での検証を可）。ZBookを使わないテストだけでは不十分で、定期実行の実観測が必要。
4. 対象日程で全レース台帳の対象件数、締切前凍結件数、未予想理由、時間超過・欠測、公式照合数を再現可能に報告。予想があるレースだけを分母にしない。
5. 締切遅延・欠場/変更・中止/返還・時点不整合・重複/復旧・外部データ欠測・秘密漏洩拒否・同時実行をテスト。
6. 正確なmain headでのCI、独立レビュー、private保存・復元とAPI/スマホ実動作を検証。一般公開/課金/権限変更/Production切替を自動実施しない。
7. 300レース以上の前向き評価と競技別サンプル数・1点/8点的中率・正しい回収率・比較モデルの改善が測れた段階ではじめて精度改善を宣言。96–99.7%は希望目標で実績ではない。
