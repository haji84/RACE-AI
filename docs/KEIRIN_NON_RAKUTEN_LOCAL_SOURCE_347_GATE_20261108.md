# 競輪：非楽天の保存済み実資料→347項目監査→既存PR71予想経路

2026-11-08 / Draft PR #101 / Issue #67

## 今回到達した接続点

以前は、個人の研究用データがすでに専用JSONになっていることを前提としていた。今回、次の**実際にユーザーが保存できる入力形式**を追加した。

- 非楽天の出走表から自分で保存したUTF-8のCSV（`race_ai/keirin_owner_saved_csv.py`）。
- KEIRIN HEXの出走表を、ユーザーがMarkdown形式で保存したテキスト（`race_ai/keirin_owner_saved_hex.py`）。HTMLを丸ごとコピーしたものや、別サイトの表構造は、現時点ではサポートしていない。
- いずれも **サイトへ一度もHTTPアクセスしない**。公開GitHubに個人の資料・契約書・予想原本を置かず、本人保有の非公開フォルダーだけで自動処理する。
- 本人が`inbox/markdown/*.md`と対応する`*.meta.json`を置いた後、継続稼働する本人用の研究エージェントが`markdown→csv→raw JSON→347/437監査`の順に処理する。締切前に必要な全ての資料・環境・特徴量がある場合に限って、既存PR71の8点予想・private SQLite原本へ送る。
- マーク、印、他サイトのモデル確率、買い目、オッズ、結果後データは予想特徴量に取り込まない。
- 「並び予想」はあくまでも**出走前に他サイトが掲載した想定ライン**であり、当日の実走行順や公式確定ラインと同一視しない。ラインと出走者を照合して、先頭・番手・後続・単騎の役割を個別観測項目にする。自動で車番を創作しない。
- 同一ページ内で着順数と出走数が合わない場合は**不一致として無効化**し、当該勝率・3連対率をモデルに投入しない。ページ掲載の率を恣意的に信用したり、欠測を0埋めしない。
- 100点、200点を超える競走得点も**上限なし**。元得点を保存して、未校正の単調変換を入力する。
- 入力のsource_url、本人の保存時刻、SHA-256、レースID、モデル入力前の欠測件数、取り込んだ特徴量の元キーを保存する。資料の掲載時刻は独立証明されていない場合「本人の初回観測時刻」を保守的な上界として利用する。

## 対応可能な入力と限界

| 入口 | できること | できないこと |
|---|---|---|
| 本人が保存したKEIRIN HEX Markdown | 出走表の得点、S/H/B、決まり手、想定ライン、役割を検出。別の明示資料があれば級班等も照合 | サイトへ無人巡回して保存／アップストリームの公表時刻を証明 |
| 本人が保存した非楽天UTF-8 CSV | 選手名・車番・級班・脚質・得点、勝敗数と率、S/H/B、決まり手、ギアの一部を変換 | 欠けた直近10走、実際の怪我、真の確定並び、気象を捏造 |
| 本人が許可された形式で持つ専用JSON | 347件の状態監査とモデルの必須/任意入力へ変換、モデルを実行できる条件をチェック | 現実のライブ完全性や取得権限の自動保証 |
| 許諾がある外部提供API | 明示範囲に限定した最大1 GET/回の既存接続口 | 未許可のサイトスクレイピング、無制限クロール |

**注意：本ページは機械取得の承諾を代替しない。** KEIRIN HEXの閲覧・コピーが許されても、それは自動収集や商用再配布を無条件に認めるものではない。本人が適法に保存した情報の非公開解析と、独立した無人クローリングは別だ。

## 使い方（本人の私用PC等に永続ディスクがある場合）

本人の非公開ディスクに以下を置く。

```text
/private/race-ai/inbox/
  markdown/
    my-race.md
    my-race.meta.json
  csv/        ← 監視プログラムが作成
  raw/        ← 監視プログラムが作成
  audit/      ← 347項目監査
  pre/        ← 予想前の入力
  results/    ← 別の確認済み結果入力
```

`my-race.meta.json` は、保存したMarkdown元ファイルのSHA-256と、信頼できるレースID・競輪場・開催日・出走予定・公式締切・想定ライン等を持つ。存在しない時刻、出走者、ラインを作らない。形は `tests/test_keirin_owner_saved_hex.py` の合成fixtureを参照。予定締切が確認できない場合は原本の正式な予想に進まず、未確認と残す。

本人限定でエージェントを動かす場合:

```bash
python3 -m scripts.keirin_permissioned_owner_agent \
  --db /private/race-ai/owner.sqlite3 \
  --inbox /private/race-ai/inbox \
  --personal-manual --owner-private-use-confirmed \
  --personal-source-host keirinhex.jp \
  --loop --interval-seconds 120
```

これを**ユーザーのPCで実際に常駐させたことはまだ確認できない**。前処理は自動化しても、Markdownを自動でサイトから取得するものではない。GitHub Actionsのエフェメラルなディスクではprivate SQLiteの無条件な永続性を主張できない。

## 受入ゲートと進捗

合成fixtureにより、全選手/車番、得点、S/H/B、決まり手、想定ライン役割を既存監査に通し、347項目の状態生成、選手の200点超を含むテスト、期限後拒否、ファイルSHA・ライン不一致拒否、二重保存拒否を成功確認した。

**未達成の最終条件**

1. 非楽天の実サイトから、規約と取得条件に合う方法でライブ出走表を無人収集する実データフィーダー。現在はユーザー保存資料からの自動変換のみ。
2. 実際の全出走選手の情報と勝ち上がり、コメント、直近結果、風等の適切な時点付与・補完、およびモデルが要求する必須数値への対応。347件はチェック項目で、外部公開実測347件ではない。
3. 実際の未来レースで「データ到着→原本締切前保存→独立時刻証明→公式結果・返還・訂正→PDCA→次予想」を完走。これが確認できるまで正式自動稼働・的中率向上・98%達成とは表示しない。

本番mainへの統合、新規有料サービス、車券購入は実行していない。
