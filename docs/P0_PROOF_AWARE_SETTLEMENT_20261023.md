# Proof-aware offline result reconciliation (P0, 2026-10-23)

`race_ai/proof_aware_settlement.py` combines PR72's full daily AUDIT_ONLY race list, separately provided normalized official-result claims, and pre-cutoff-forecast claims. Every real-data acceptance requires four **separate independently implemented** verifier callbacks: source/result finality, official cutoff, pinned external forecast freeze receipt, and full-day race coverage. All callbacks default deny. These functions are interfaces for trusted implementers, not permissions granted by an input flag. Official result revisions/refunds must be handled upstream, and the final revision supplied explicitly; any changed outcome after checking requires a new immutable evaluation record.

Missing forecasts remain in the eligible denominator. Report verified subset counts separately; formal Hit@1, Hit@8_all and capture rate stay `null` until full coverage and all listed result finality are independently confirmed. ROI is hypothetical 100yen per chosen ticket, conditional on verified refund NONE for all eligible outcomes; actual purchase ROI remains null without purchase logs. Probability calibration/Brier/log-loss remain null until valid forecast probabilities are available. **Do not report synthetic tests as real results.**

The offline unit tests provide **fictional trust callbacks**; a passing test is NOT proof of legal rights, official race results, real timestamps or real coverage. The current PR #71+72 real transport/freeze writer / result fetch and production verified callbacks have not yet been wired, so no formal actual metric can be reported. Do not modify frozen predictions or model versions after results. No automatic betting, paid service, publishing or main merge.

**Result corrections:** multiple independently verified versions per race are accepted only in consecutive revision order with strictly increasing confirmation time; the latest version controls outcome. A newer unverified revision blocks formal scoring rather than silently retaining stale historical payouts. Prior result versions remain inputs, not overwritten.
