# 競輪三連単95%に向けた検証

対象は全レース。荒れると見込む場合も上限8点とし、1点・4点・8点の結果を同じレースで測る。学習・調整に使った日と評価日を分ける。最終的な判定には、実際の締切前に保存した予想を、開催日をまたいで二つの掲載元の確定結果と照合する。未登録・未確定・結果不一致・返還などの保留も開催台帳に残す。

## 11月25日の公開予想

19時25分35秒（日本時間）までに二元一致した47レースで、公開三連単は17/47（36.2%）。実際の掲載4点は9/36、8点は8/11。同じ47件すべてを一律に採点すると1点3/47、4点14/47、8点24/47（51.1%）。予想A・Bは同じ掲載点数で各10件。三連単を外した30件は、勝者を1着に置けなかった15件、勝者を拾ったが正しい2着と組めなかった10件、正しい1・2着に3着を付けられなかった5件に分かれた。

累積採点で25案の登録を確認し、対象42レースのうち15件が二元一致。今回の4案では、点数境目と三者構成が同じ1レースで採点され、買い目が元と同じで外れた。対戦相手の学習と風の案は、登録対象の結果がまだ採点に入っていない。朝以降に並びを取得した15件は締切前。[19時25分の採点](score-1925.json)・[公開更新の実行](https://github.com/haji84/RACE-AI/actions/runs/45594817138)

18時58分39秒（日本時間）時点の75レースは、45件で結果が二元一致、1件が保留、1件が結果待ち、28件が締切前。公開の掲載点数で三連単は17/45（37.8%）。掲載4点の34件で9件、掲載8点の11件で8件。予想A・Bは同じ45件、同じ掲載点数で各10件。全45件を一律に採点すると、1点3/45、4点14/45、8点23/45だった。全75レースの95%に必要な72件には、残る30件が全て的中しても届かない。公開照合のActionsで保存した結果を、通常認証と公開配信の両方から読み戻した。[公開結果と点数別採点](scoring-and-95-gap.json)・[公開結果更新の実行](https://github.com/haji84/RACE-AI/actions/runs/45590440819)

先に締切前に登録した8案は、重複を除き13レースで結果が確定。予想印の補正案は、同じ12レースで5→5件。西武園4Rを拾い、西武園6Rを落とした。その後に登録した13案では5レースが確定。二車単の一部を使った案が松山8Rの三連単を元と同じ点数で拾った。朝の掲載後に並びが判明した15件の最初の締切は21時00分で、この時点では全件採点待ち。

## 8点のどこに改善が必要か

11月21～24日の現行予想287件を一律8点で再現すると127件的中。95%に必要な273件まで146件足りない。確定した実際の1着だけを与え、残りを元モデルの条件付き評価で選ぶ事後診断でも203/287件。上位2着を正しい順序で先に与えると8点で287/287、4点で269/287。これは条件を切り分ける事後診断である。4点では1・2着に加え、その後の3着候補を改善する必要がある。

実際に異なるラインの選手が1・2着に来た118件では、元の掲載点数で三連単9件、正しい順で1・2着を含めたのは13件。一律8点での的中は19件で、勝者だけを事後に与えても48件だった。勝者に加え、どの別ラインの誰が2着に残るかが大きく効く。元の順位を事後に数えると、287件で95%を含むには上位120点、当日18時58分時点の45件では上位144点が必要だった。これは元モデルの順位が正解からどれだけ離れているかを測った数値である。[1着・着順付き1・2着・正解3人の確認](scoring-and-95-gap.json)

別ラインが1・2着で、最終バックの先頭を確認できた過去4,196件を調べた。B先頭のラインが勝ったのは1,896件、同ラインが敗れて2着に残ったのは1,546件、1・2着とも別のラインだったのは754件。B先頭のラインが2着に残った1,546件でも、B先頭の本人が2着になったのは667件で、残り879件は同じラインの他の選手だった。元の8点に正しい1・2着の組があったのは、それぞれ488件、342件、163件だった。この集計は、Bで前にいたラインの誰がゴール前に残ったかを、映像で確認し学ぶ対象につなげる。[Bの先頭と実際の別線2着の内訳](scoring-and-95-gap.json)

## 新たに学習した情報

| 学習と比較 | 4点の三連単的中 | 8点の三連単的中 | 直近287件の掲載点数 |

| 過去の対戦相手の強さを日ごとに更新。過去12,234件で評価 | 3,234→3,236 | 4,583→4,635 | 93→93 |
| 上位3人がどのラインから来るかを学習。過去12,234件 | 3,234→3,272 | 4,583→4,634 | 93→92 |

対戦相手の強さを更新する方式は、過去の出走者を登録番号で結び付け、同日の全予想について先に特徴を計算してから同日の着順を学習する。過去12,234件の8点で新規211件・失点159件、+0.43ポイント（日単位95%区間 +0.12～+0.73ポイント）。初回の直近転用は登録番号を結べる196件で補正し、未取得91件は元と同じ順位だった。後から照合できた11月24日の締切前番組80件を同じ固定係数で追加すると、補正対象が276件となり、同じ掲載点数で新規2件・失点2件、全8点は127→127件。締切前に固定した当日27件の原本は初回から同じ。共通化した学習入力のコードでも、過去76,005レース全件で従来の研究実装の特徴量と一致した。

三者のライン構成を学習する方式は、各3人内の6通りの順位比を保ち、3人の組み合わせの評価だけを変えた。別に同系統の過去モデル10,867件で8点4,451→4,467（+0.15ポイント、日単位95%区間−0.19～+0.47）。締切前の出走表が残る322件の8点は124→129。直近の現行予想では、4点91→90、8点127→123だった。

点数の境目を直接学習すると、過去12,234件の8点で正しい順の1・2着を含むレースが6,327→7,380に増えた一方、三連単の的中は470件減った。1・2着の候補数を広げたことで、正しい1・2着に付く3着が買い目から外れた。1・2着の捕捉率と、捕捉した場合の3着までの的中率を併記する。気象庁の方式は観測所33か所の記録72,019報のうち、開催場から25km以内で観測時刻・風向風速・コース方位を確認できたレースを使用。締切前出走表と観測の両方を確認できた直近175件の掲載点数では66→62件だった。

出走車数、選手の直近出走履歴の量、Bの観測履歴に応じて、既存の出走表方式・直近1年方式・3年と展開を使う方式を混ぜる案も比較した。前の期間51,056件で学習し、後続12,234件の4点は3,234→3,194、8点は4,583→4,572。締切前の原票がある321件でも8点は119→116件だった。

本番採用につながる一貫した改善は未確認。4案は実際の未締切レースに別々に固定し、元の買い目と同じ点数で照合する。重複を除く対象は28件。掲載点数で買い目が変わるのは、点数境目25件・三者構成1件・対戦相手の伸び15件・風1件。各案のハッシュと事前固定時刻は既存の研究ブランチに記録した。[各試験の成績・入力・固定記録](new-model-comparisons.json)

## 開催日をまたぐ採点

日ごとの公開結果と事前に固定した研究予想を、点数を揃えて累積採点するコマンドを追加した。各レースを日付・方法・研究のハッシュで照合する。同日でも事前保存した対象が重複しない場合は一つの方式として集計でき、同じレースの重複はエラーにする。元ファイルとGitのコミットで確認できる予想登録、未算入の件数、新規的中と取りこぼし、対象75レースの網羅状況を件数で出力する。18時58分時点で計25案、重複を除く42レースの原本を検証した。研究原本を復元してローカルで動作を確認。既存のGitHub Actionsで公開結果が更新されるたび、その公開結果を入力に採点できる。[累積採点の確認](ledger-readback.json)

研究予想の保存から採点までの手順は、元の予想を締切前に固定し、既存の研究ブランチにハッシュと対象の締切を記録する。照合時に暗号化した原本を本人用作業領域へ復元し、公式結果と日別台帳を同一の公開データの改訂から取得する。マニフェストは日付ごとに公開用名簿・結果、研究案ごとに元の買い目、採点形式、固定記録、Git参照を渡す。既に出力がある場合は、新しい時点のファイルを作成する。

```bash
python -m scripts.keirin_research_ledger \
  --manifest /path/to/private/manifest.json \
  --output-new /path/to/private/counts-YYYY-MM-DD.json
```

同一の学習条件の1・4・8点を継続集計し、別案の的中や同じレースの再採点は合算しない。分母の確定時に通常の三連単を比較できない返還などがある場合は、理由と件数を開催台帳から別に確認する。1日分の途中集計や対象の一部だけの高い的中率は、全レースでの95%の到達基準にしない。
