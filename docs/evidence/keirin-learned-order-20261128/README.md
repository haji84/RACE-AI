## オッズ・信頼度の受入

`keirin_calibrated_selection.py`で、確率首位を事前固定し、公表時刻・取得時刻が判定時点以前のオッズから三連単の上限2・4・9・12点を選ぶ。候補追加は確率1ポイント以上の増分と、取得後5分以内の5〜10%のオッズ変動控除後のプラスの期待値を初回の評価規則とする。二車単は確率上位2点まで。信頼度は同じモデル・券種・提示規則で、学習期間より後に予想し判定までに結果を確認した実績を使う。同じ帯で30件・3日以上、実測率の各基準、平均予測と実測の誤差10ポイント以内、95%区間を確認する。激アツと高には、95%区間の下限にも90%と80%を適用する。

11月27日の既存GitHubオッズ6版と公式原本60件の時刻を照合した。締切15分前の時点で54件は5分より古く、5件は掲載なし、1件は公開時計が判定時点より後で、適格なオッズは0件だった。現在の保存経路には二車単オッズもない。今回の可変点数・オッズ帯別回収・運用信頼度は判定保留。過去再計算の予測確率帯の分布は監査用に残した。

## 原本と再現

学習済みモデルの木と仕様を、既存の所有者公開鍵宛てのRSA/AES-GCM封筒に保全した。検証レポートに暗号文と平文の照合SHA、コードと固定予想のSHAを記録している。暗号化前のモデルを読み戻し、保存した実レースで同じ着順分布を確認した。復号経路は既存の所有者鍵を使用する。10件未満の集計は件数を掲載し、個別の値が推定できる詳細は所有者宛ての暗号文にまとめた。[暗号化モデル](model.sealed.json) · [照合記録](verification.json)

既存の固定SQLite2件を同じ順で指定し、リポジトリ外の私用ディレクトリで `python -m scripts.keirin_learned_order_study --archives … … --private-root …` を実行する。`--recheck` は同じ木と予想のSHA、代表レースの確率、固定点数集計を再照合する。モデルの復元は `keirin_learned_order.load_frozen` を使用する。計測環境はNumPy 2.2.6とLightGBM 4.6.0。
