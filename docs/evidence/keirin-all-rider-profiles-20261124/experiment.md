# 競輪の登録選手別履歴を使った精度検証

2026年11月18日02:37 JST更新のKEIRIN.JP現役検索を、地区別・男女別の公開ページ246件から取得した。登録番号に重複はなく、国内2,410人、外国招待6人の計2,416件。全件について過去走の有無を調査した。現在の級班や現役状態は名寄せと調査の分母にだけ使う。予想で使う級別・得点・脚質は各レースの出走表に記録された値。[公式の選手検索](https://keirin.jp/sp/racersearch) · [名簿の取得記録](official-registry-receipt.json)

2023年11月24日から2026年11月23日までの月別CSVと、出走表・結果を収録したKドリームス由来のSQLiteを使った。月別CSVでは開催初日と実施日が異なるときにレースIDの日次から実施日を決める。府県名の先頭1文字が氏名末尾に混ざる記録は、復元した府県名と期別・氏名が同じ登録番号に一意に一致した場合に採用した。前回確認した別アーカイブの出走表でレース・車番・氏名が一致する登録番号も使った。古い資料の23レースと、両資料が重なる18万件超の行で同じ分割を確認した。同姓同名は個別に判定し、確定できない履歴は予想に渡さない。[月別CSV](https://github.com/Kenseimk/keirin-data/tree/8ba8316329c145aea55b5ada529b0af7b0d94c48/keirin_data) · [保存版のSQLite](../keirin-three-year-20261124/db-provenance.json) · [資料と照合の範囲](coverage.json)

選手ごとに直近365日と60日の過去走を集計する。出走表の競走得点から1〜3着の基準値を作り、実際の着順との差を測る。上がりは当該レース内の中央値との差を使う。逃げ・捲り・差し・マークは結果欄の決まり手で、同じレースの結果欄からSとBも確認する。並びが確認できる過去走は、そのときの予定位置ごとにも集計する。同じ会場・級別の成績も使い、観測が少ない場合は全体平均との差を小さくする。上がりは最終半周のタイム。Hの全選手の実測通過位置と仕掛け開始時点を確認できる全件資料は今回の入力に含まれない。[上がりの公式説明](https://keirin.jp/pc/dfw/portal/guest/guide/question/race.html) · [S・H・Bと決まり手の説明](https://keirin.jp/pc/static/beginner/keirin-glossary/numbers-alphabets.html)

比較は、並びだけで学習する方式、選手別の全体実績も加える方式、予定位置・会場・級別の実績まで加える方式。共通の着順別評価で1着から3着までに適用した。既存Bについては展開から出る候補を保ち、選手特徴で各候補の順位だけを補正する比較も行った。2車単には1・2着の補正だけを使う。各レースで上限内の点数を揃え、各方式の出せる点数での集計も残す。前回の固定係数による並び版は、その学習期間の後にあたる11月分で比較する。

学習は2025年10月1日〜2026年7月31日、調整は2026年8月1日〜9月30日。調整期の3連単4点、8点、2車単2点の順で設定を選ぶ。各レースの履歴には前日までの結果を使う。10月1日〜11月23日の評価用履歴は9月30日の状態で固定し、評価期間中の結果で更新しない。11月の一部は前の検証と重複する。アーカイブに結果欄がある場合も、予想用には出走表と評価開始前の履歴だけを渡す。予想・係数・入力を固定し、その後に評価用の出走レースの着順と払戻を抽出して採点する。締切前の保存版を確認できるレースは別集計する。[固定記録](forecast-commitment.json)

## 検証を再実行する方法

Python 3.12、NumPy、SciPyを使用。アーカイブから照合した過去走を `Ride` として `HistoryBook` に渡し、対象の登録番号・レースID・予定位置・級別で `features()` を取得する。出走表の各選手にその値を `profile` として添え、学習・調整用ファイルは各行が `input` と `outcomes` を持つgzip形式のJSON配列にする。入力や予想の個票は本人用作業領域に保存する。

```sh
python -m scripts.keirin_rider_profile_study \
  --fit fit.json.gz --calibrate calibrate.json.gz --output weights.json
```
