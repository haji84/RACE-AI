# 競輪の登録選手別履歴を使った精度検証

2026年11月18日02:37 JST更新のKEIRIN.JP現役検索を、地区別・男女別の公開ページ246件から取得した。登録番号に重複はなく、国内2,410人、外国招待6人の計2,416件。全件について過去走の有無を調査した。現在の級班や現役状態は名寄せと調査の分母にだけ使う。予想で使う級別・得点・脚質は各レースの出走表に記録された値。[公式の選手検索](https://keirin.jp/sp/racersearch) · [名簿の取得記録](official-registry-receipt.json)

2023年11月24日から2026年11月23日までの月別CSVと、出走表・結果を収録したKドリームス由来のSQLiteを使った。月別CSVでは開催初日と実施日が異なるときにレースIDの日次から実施日を決める。府県名の先頭1文字が氏名末尾に混ざる記録は、復元した府県名と期別・氏名が同じ登録番号に一意に一致した場合に採用した。前回確認した別アーカイブの出走表でレース・車番・氏名が一致する登録番号も使った。古い資料の23レースと、両資料が重なる18万件超の行で同じ分割を確認した。同姓同名は個別に判定し、確定できない履歴は予想に渡さない。[月別CSV](https://github.com/Kenseimk/keirin-data/tree/8ba8316329c145aea55b5ada529b0af7b0d94c48/keirin_data) · [保存版のSQLite](../keirin-three-year-20261124/db-provenance.json) · [資料と照合の範囲](coverage.json)

選手ごとに直近365日と60日の過去走を集計する。出走表の競走得点から1〜3着の基準値を作り、実際の着順との差を測る。上がりは当該レース内の中央値との差を使う。逃げ・捲り・差し・マークは結果欄の決まり手で、同じレースの結果欄からSとBも確認する。並びが確認できる過去走は、そのときの予定位置ごとにも集計する。同じ会場・級別の成績も使い、観測が少ない場合は全体平均との差を小さくする。上がりは最終半周のタイム。Hの全選手の実測通過位置と仕掛け開始時点を確認できる全件資料は今回の入力に含まれない。[上がりの公式説明](https://keirin.jp/pc/dfw/portal/guest/guide/question/race.html) · [S・H・Bと決まり手の説明](https://keirin.jp/pc/static/beginner/keirin-glossary/numbers-alphabets.html)

比較は、並びだけで学習する方式、選手別の全体実績も加える方式、予定位置・会場・級別の実績まで加える方式。共通の着順別評価で1着から3着までに適用した。既存Bについては展開から出る候補を保ち、選手特徴で各候補の順位だけを補正する比較も行った。2車単には1・2着の補正だけを使う。各レースで上限内の点数を揃え、各方式の出せる点数での集計も残す。前回の固定係数による並び版は、その学習期間の後にあたる11月分で比較する。

学習は2025年10月1日〜2026年7月31日、調整は2026年8月1日〜9月30日。調整期の3連単4点、8点、2車単2点の順で設定を選ぶ。各レースの履歴には前日までの結果を使う。10月1日〜11月23日の評価用履歴は9月30日の状態で固定し、評価期間中の結果で更新しない。11月の一部は前の検証と重複する。アーカイブに結果欄がある場合も、予想用には出走表と評価開始前の履歴だけを渡す。予想・係数・入力を固定し、その後に評価用の出走レースの着順と払戻を抽出して採点する。締切前の保存版を確認できるレースは別集計する。[固定記録](forecast-commitment.json)

## 初回の結果

名簿2,416件のうち、採用条件を満たす過去走が3件以上あるのは2,371人。元資料で採用できた最新の結果は11月22日。3年分の資料を調査し、登録番号に結び付けた結果は延べ507,388走。各選手の全体成績、過去の予定位置、競輪場、級別ごとの観測数と特徴を本人用領域に保存した。[現在の選手履歴集計](current-census.json) · [本人用領域の暗号化控えの照合記録](local-envelope-receipt.json)

残る45人は全員の公式プロフィールで脚質と通算出走を確認した。39人は対象期間内の出走も確認できた。残り6人の公式開催欄には月日と着順があるが、年は確定できなかった。追加取得したプロフィールは、既に固定した予想の履歴に加えず本人用の調査資料として保存した。評価では競走得点・並びや着順をレース単位で同じ登録番号に照合できる履歴を使った。[45人の公式プロフィール追加調査](unmatched-official-receipt.json)

一意の着順がある22,372レースで学習し、調整期3,050レースで比較した。3連単4点の的中は、並びのみ701件、全体実績あり684件、位置・会場・級別まで加えると699件。並びのみの方式を採用候補として固定した。履歴ありの2方式では位置・会場・級別を含む方式を既存Bの補正に採用し、補正の強さ0.5を固定。結果を見た後の設定選びは行っていない。予想を用意した3,589件のうち3,582件を採点した。締切前の保存版しか使わない比較は561件のうち557件を採点。[固定基準と調整成績](weights.json) · [採点前のGitHub Actions](https://github.com/haji84/RACE-AI/actions/runs/45223522991)

## 府県表記を揃えた再計算

追加調査で、公式名簿の「福岡県」などの表記が「福岡」などの過去走表記と一致せず、同じ氏名・期別の履歴が落ちていた。公開情報で確認できる府県の末尾を揃え、氏名・期別・登録番号の照合条件は保った。外国招待選手は短縮名と一致候補があっても、個別レースの登録番号を確認できる資料を要する。この再計算は同じ評価期間と同じ係数選び・採点手順を使った表記補正の確認。[府県表記の調査](archive-overlap-aggregate.json) · [外国招待選手の表記調査](foreign-alias-aggregate.json)

全2,416件中2,404人（99.5%）で3走以上を確認できた。府県表記の補正で33人を追加し、登録番号付きの採用結果は延べ511,888走になった。残る12人は公式プロフィールの脚質と通算出走を確認済みで、過去走と各レースの入力の照合が不足している。実際の評価に用いた出走表とプロフィール入力は初回とバイト単位で一致し、学習履歴と係数が更新された。初回の採点後に行った同じ標本での再計算。[補正後の現役選手集計](prefecture-normalized/current-census.json) · [再計算の固定記録](prefecture-normalized/forecast-commitment.json) · [GitHub Actions](https://github.com/haji84/RACE-AI/actions/runs/45226157211)

締切前の保存版557件では、既存Bに選手特徴を足したときの的中数は初回と同じ。3連単4点が106件から111件、最大8点が151件から157件、2車単2点が181件から175件。後日保存の出走表を含む3,582件では、最大4点が628件（17.53%）から645件（18.01%）、最大8点が896件（25.01%）から904件（25.24%）、2車単最大2点は1,020件（28.48%）から1,013件（28.28%）。共通の学習条件で並びに選手特徴を足したときは、締切前557件の3連単最大8点が206件から203件。既存Bの補正で確認できた改善は今回の比較標本・券種・点数での結果で、前向きの検証は未実施。[補正後の採点結果](prefecture-normalized/results.json) · [候補到達と着順別の原因](prefecture-normalized/miss-diagnosis.json) · [着順の補正を分けた試験](prefecture-normalized/finish-stage-diagnosis.json)

## 検証を再実行する方法

Python 3.12、NumPy、SciPyを使用。アーカイブから照合した過去走を `Ride` として `HistoryBook` に渡し、対象の登録番号・レースID・予定位置・級別で `features()` を取得する。出走表の各選手にその値を `profile` として添え、学習・調整用ファイルは各行が `input` と `outcomes` を持つgzip形式のJSON配列にする。入力や予想の個票は本人用作業領域に保存する。

```sh
python -m scripts.keirin_rider_profile_study \
  --fit fit.json.gz --calibrate calibrate.json.gz --output weights.json
```

府県表記の補正を含む関連122テストとGitHub Actionsの新しい検査が通過した。ローカルで競輪テストを全探索すると、変更前にも同じ7モジュールが未収録の依存で読み込めなかった。環境にあったChromiumを指定し、権限テストを標準のumaskで走らせると、最初に失敗した環境依存の2箇所を含む24テストが通過した。[GitHub Actions](https://github.com/haji84/RACE-AI/actions/runs/45226157211)
