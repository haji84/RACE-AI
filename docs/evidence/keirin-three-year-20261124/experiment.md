# 競輪の3年分の資料とライン別履歴の精度検証

対象は2023年11月24日〜2026年11月23日 JST。月別CSV、Kドリームス由来のSQLite、出走表の版が残る公開データを日付・場・Rで照合した。収録を確認したレースは82,731件、1,096日。月別CSVの並び欄は区切りを復元できる形式の裏づけがない。SQLiteの2025年10月〜2026年11月では、並びと出走車が整合する29,159件を確認した。ガールズは競技区分が確認できた場合に各車を単騎とした。旧い23か月は、各月の7車レースの時系列上の中央1件をKドリームスの元ページで確認した。23件で並びとB、21件でSが得られた。別の結果掲載元と同じ車番・氏名で、公式出走表由来の登録マスターにも一致したのは延べ161人中130人。7車すべての一致を確認できたのは5レース。元ページの確認時刻はレース後。[月別CSV](https://github.com/Kenseimk/keirin-data/tree/8ba8316329c145aea55b5ada529b0af7b0d94c48/keirin_data) · [SQLiteと公開欄の抽出方法](https://github.com/sumidatadayoshi/keirin-data/blob/2a1260fb0940ad11160b56a36f9c24cc4fb2f6d2/keirin_scraper.py) · [旧い資料の照合](older-identity-spot-check.json)

過去のS・Bは結果欄のマークを使う。Sは発走後に先頭誘導選手の後ろを取った記録。HとBは最終ホーム・バックの先頭通過を示し、全選手の位置や仕掛けの開始時点とは別の情報。SQLiteではS・Bと勝者の決まり手を確認できた。Hの通過順や仕掛け時点を公式レポートで確認できる個別例がある。全件に使えるH・通過順・仕掛けの時点は未収録。[KEIRIN.JPのマーク定義](https://keirin.jp/pc/dfw/portal/guest/news/2007khn/12/news20071213_01.html) · [京王閣の公式レポート](https://keirin.jp/pc/dfw/portal/guest/report/GIII/27keiokaku/2024/report_4.html) · [松阪の公式レポート](https://keirin.jp/pc/dfw/portal/guest/report/GIII/47matsusaka/2025/report_3.html)

選手の履歴は、同じレースの両アーカイブで車番と氏名が一致し、出走表側の登録番号と公式出走表由来の登録マスター上の氏名が一致し、両方の予定ライン内の役割が一致したときに採用する。予定されていた先頭・番手・後方・単騎ごとに、その後結果欄に記録されたS・Bと、勝者が逃げ・捲りだったかを集計する。各項目の観測数も残し、3走未満は評価に使わない。役割は公表された予定であり、レース中の後続選手全員の通過位置は計測していない。欠測は欠測として扱う。[登録マスターの保存版](https://github.com/mitiki0720-oss/keirin-datalavo/blob/c2dd29784525ec357906eea8962c73174bb69260/public/data/analytics/kurari-ex/exact/rider-master.generated.json) · [出走表保存版](https://github.com/kurinaka12-afk/keirin-app-data/tree/a8c7851a062e36da1e10101dcbbe1aad278fe168)

2026年9月3日〜10月20日を学習、10月21日〜31日を設定選び、11月1日〜23日を評価に使う。学習時の履歴は対象の前日まで、評価時は10月31日までに固定する。照合できた個人履歴は8月25日以降の資料から採用した2,843レース、延べ17,960行。比較するのは、既存の着順別の評価方式、並びを追加する版、並びに過去の同じ役割でのS・Bと決まり手の実績も追加する版。3着の評価係数と算出方法は3版で共通。2車単は1・2着の評価だけで順位を付ける。選定は調整期間の2車単2点、2車単4点、3連単8点の順。既存A/Bは同じ出走表で生成した候補の上位を使い、選別や見送りを含む実運用の成績は評価対象外。上限1・2・4点の2車単、上限4・8点の3連単を測り、全版で実際の点数をそろえた集計も保存する。

評価用の出走表は、保存版に記録された生成時刻とGitコミット時刻が出走表の締切前だった版を優先する。後日取得した出走表を使う再現検証は別に採点する。時点の確認対象は当日の出走表で、過去走の役割は後日保存された資料でも照合している。2026年11月23日は既存の結果台帳で締切後に照合した記録を使う。今回の評価ラベルとして着順と払戻を取り出す前に、予想・係数の照合用ハッシュを固定した。評価期間の一部は過去の検証と重複する。採用した出走表の時刻は締切の約159〜1,099分前で、締切10〜15分前の保存版は0件だった。この比較の入力は出走表と過去走まで。

## 学習プログラム

Python 3.12、NumPy、SciPyで実行できる。学習と調整のgzip圧縮JSONは、各行が `input` と `outcomes` を持つ配列。 `input` には対象日から始まる`race_id`、全車の`riders`、車番を並べた`line_groups`が必要。登録番号が確認できた選手の`history`には過去の同じ役割での`s`、`b`、`front_win`の各項目を置き、観測件数を`n`、該当件数を`yes`で渡す。`outcomes`には確定した2車単・3連単を`2t`と`3t`に渡す。

```sh
python -m scripts.keirin_line_history_study \
  --fit fit.json.gz --tune tune.json.gz --output line-history-weights.json
```

レビューで同じ車番が複数の着順にある入力を除外する検査を追加した。今回の収録データでは、再学習した係数と調整期の採点が固定版と一致した。予想原本と照合用の情報は作業環境の本人用領域に暗号化して保管した。
