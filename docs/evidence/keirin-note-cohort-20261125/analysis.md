# 本人用の三連単結果を締切前予想の検証に使う

公開予想の結果と、本人用の研究履歴の結果は出典と取得項目が異なる。既存の結果巡回は、研究履歴からKdreamsとnetkeirinの三連単を照合できる。公開結果の採点経路は二車単も要求するため、本人用の経路では三連単だけを同じ1・4・8点で採点する。特殊結果と確認できないレースは保留し、通常の結果に変換しない。

## 読み戻しと採点

1. 通常のGitHub認証で `state/keirin-note-view` のコミットを確認し、そのコミットの索引と対象日の暗号化ファイルをローカルに取得する。
2. 既存の本人用P-256鍵で `node scripts/keirin_note_result_readback.cjs --repo <local-repo> --revision <git-sha> --date <yyyy-mm-dd> --capability-file <existing-private-key-file> --output <new-private-file>` を実行する。ツールはローカルGitだけを読み、既存公開経路と同じ暗号検査を使い、結果の改訂の連鎖と最新索引を照合する。一時ファイルに復号した結果を含むため、本人用の領域に保管する。
3. 既存 `scripts.keirin_research_cohort_score` のmanifestに `note_results` と `note_index_commit` を渡す。公式の保存資料がある場合は `official_result_records` も指定する。このファイルは `scripts.keirin_official_day_pipeline.private_snapshot_json({'races': <official-source-records>})` による既存公式レコードの私用JSON。採点時に本人用の復号原文を索引のSHAに結び直し、公式結果は保存した取得元の生バイトから再解析する。
4. 両媒体の三連単、公式の三連単、公式結果に列挙された出走車番、締切と事前登録を照合する。公式資料を確認できない2媒体一致は採点から保留し、両媒体一致件数を別に記録する。対象件数、欠測、保留、各点数の的中率、獲得と取りこぼしを集計する。

本人用経路と公開結果経路は別の入力として動く。既存の予想原本の出走者集合は車番で保存されているため、この採点経路が事前と事後で照合するのは車番。同じ車番を別の選手が引き継いだかは、事前の登録番号を結んだ資料が別途必要。公式資料と索引の取得元を確認する作業は利用者の取得手順に属し、ローカルの採点処理から公開や収集は行わない。

## 実データの確認

- 認証済み索引の11月25日分4パケットを本人用に復号。2媒体一致53、保留1、結果待ち1。西武園11Rは既存の公式保存資料を再解析し、締切前に公開された予想と同じ三連単4点・8点で的中を再確認した。
- 11月26日の締切前に登録した8場84件について、松山を含む5つの比較と1・4・8点が採点対象になることを確認した。索引の翌日分は0件で、この時点は84件すべて取得待ち。的中率は算出していない。
