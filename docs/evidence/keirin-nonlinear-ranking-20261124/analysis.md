# 競輪3連単の候補順位を、選手とラインの条件に応じて補正

## 学習と固定

従来の着順評価は、競走得点、着順別の実績、予定ライン、公開された予想印を使い、着順ごとに候補の順位を付ける。今回は、選手の得点差、予定ライン内での前後関係、別線の強さ、登録番号を照合済みの過去実績を組み合わせ、固定した方式の順位を決定木で補正した。1着、1着を仮定した場合の2着、1・2着を仮定した場合の3着の確率を各候補内で正規化し、全ての有効な着順を同じ手順で順位付けする。別の試験では順序つきの1・2着を一組として直接学習し、そこへ3着を組み合わせた。[着順ごとの補正](../../../scripts/keirin_boosted_choice_study.py) · [1・2着を一組として学ぶ処理](../../../scripts/keirin_joint_pair_study.py)

4〜7月向けは2025年10月〜2026年1月の8,810件で学習し、2026年2〜3月の4,381件で設定を選んだ。10〜11月向けは2025年10月〜2026年7月の22,372件を学習、8〜9月の3,050件を設定選びに使用。締切前の資料では予想印の有無に差があるため、学習時に約4分の1のレースで予想印を伏せる設定とし、調整期間は予想印がある場合と伏せた場合の2条件を再生した。調整期の3連単8点、次いで4点の的中数で設定を選んだ。どちらの期間も、1・2着を一組で学習する方式より、着順ごとの補正を選んだ。評価対象レースの結果と確定オッズを予想に使っていない。ここでいう印は出走前に掲載される資料中の予想印。[学習と予想固定](commitment.json) · [1・2着の固定](joint-commitment.json) · [4〜7月向け設定](earlier-configuration.json) · [10〜11月向け設定](recent-configuration.json) · [採点前のGitHub Actions](https://github.com/haji84/RACE-AI/actions/runs/45297183660)

## 確率を混ぜる追加比較

1月末までに学習した二方式の確率を25%、50%、75%で混ぜる設定を、相手と着順の各候補に対して比較した。2〜3月の調整で、予想印ありならB方式のみ、伏せた場合は今回の補正のみが選ばれた。別に確保した8〜9月3,050件は予想印があり、選んだ設定の8点は1,200件。補正のみは1,215件、75%混合は1,221件。後から分かった最高成績の混合率を設定選びへの使用や採用の根拠にしない。この試験は1月までの学習だけで行い、10〜11月向けの学習・調整と区別している。[追加期間と固定した混合条件](blend-results.json)

研究用の学習ライブラリはLightGBM 4.6.0。学習した決定木と予想原本は作業領域で暗号化し、設定、採点結果、照合用ハッシュを既存PR #327に保管した。対象の出走表と確定結果は11月23日までの過去資料を使った。[既存PR #327](https://github.com/haji84/RACE-AI/pull/327)
