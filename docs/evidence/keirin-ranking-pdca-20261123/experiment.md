# 競輪A/Bの着順別評価を見直す

年間の出走表を用いた現行Aは、並びが欠けている場合に全着順を候補にする。現行の1着評価は得点60%、勝率30%、掲載印10%。2着と3着には1着実績を含む連対率・3連対率を使う。候補の順位を決める各項目がどの着順に効いているか、投票組数を揃えて確かめる。

2025年11月23日〜2026年7月31日のうち単一着順が確定しているレースで学習した。8〜9月を調整に使い、10月1日〜11月22日の結果は予想と係数を固定してから読み込む。着順別条件付き評価は、前の着順に置いた選手を次着の比較から除き、2着だけと3着だけの過去実績を分ける。欠測は観測の有無を明示する。

調整では、着内率を使う方式、着順別に分解する方式、脚質を追加する方式を同じ資料で試した。上位4組で2車単が現行以上の方式から3連単の的中が最大のものを選んだ。選定方式から競走得点、掲載印、着順実績をそれぞれ外して再学習し、どの項目が調整期間の的中差に寄与したかを確かめた。候補ごとの調整成績と学習係数を保存する。

並びありのレースは現行A/B、番手自力の展開を増やした比較版、同じ展開候補を学習係数で並べ替えた版を比較する。最初に各券種の到達可能な全候補を確認し、同数の上位4組に入った数を別に集計する。1・2着の評価は3着評価と独立させる。採用点数は既存の可変点数規則で算出する。

11月23日の未締切レースでも、同じ係数と同じ出走表を使って両版を事前に作成した。予想原本は本人用領域に保存し、照合ハッシュはGitHubのCI作成時刻と照合する。

## 学習を再実行する

リポジトリのルートで、NumPyとSciPyがある環境から学習を実行する。今回の実行環境はPython 3.12.14、NumPy 2.2.6、SciPy 1.17.0。比較候補の順位は、学習時にも実際の予想エンジンで計算する。

```sh
python -m scripts.keirin_fit_ranking_weights \
  --fit fit.json.gz --validate validation.json.gz \
  --fit-end 20260731 --validation-end 20260930 \
  --output fitted-weights-local.json
```

入力ファイルは、結果照合済みのレコードを配列にしたgzip圧縮JSON。各レコードには `cohort: "annual"`、出走表を正規化した `input`、2車単・3連単の確定した組の配列を `2t` と `3t` に持つ `outcomes` を渡す。 `input` は年月日から始まる `race_id`、 `riders`、 `line_groups: null` を含む。先に学習期間と調整期間に分け、評価用の期間はこの入力から外す。元のデータとレース単位の予想は本人用領域に保管している。GitHubには係数・採点集計・照合用ハッシュがある。[採点集計](results.json)

初回の調整用計算で支持が同点に近い場合に候補順がずれたため、予想エンジンで4,608レースを再採点した。9設定すべての採点、選定した設定、係数が一致した。特徴を外す試験は、着順実績を外した2車単が2,124件から2,125件に変わった。評価期間の予想と11月23日分の予想は、初回から予想エンジンで生成した。[初回に固定した係数](fitted-weights.json) · [再採点](results.json)
