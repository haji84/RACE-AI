## 接続経路

1. 既存 Actions の `boat_pdca_production_readback` が、所有者キーで固定SHAの暗号化履歴を復元する。
2. 復元内容のSHA・元コミットを照合し、保存済み admission と最新公式結果を再検証する。GitHub の実際の `run.created_at` と、その実行のHEADに固定された予想ハッシュも再照会する。run IDをartifact IDには転用しない。
3. 各レースの最新の保存入力を選んでから、固定された会場別データセットを本当に使用した原本を選ぶ。後から取得した集計値を古い原本に追加しない。
4. 入力と結果の全取得元について、独立した利用条件レビューの `model_training` 用途を確認する。`analysis` や暗号化キーだけでは学習許可にならない。
5. 許諾が揃えば既存学習器を呼ぶ。最低8つの異なる正常結果レース、時刻順のtrain/holdout分割、少数出走特徴量の係数維持をそのまま使用する。モデル違い・P0/P1・結果改訂を別レースに数えない。
6. 学習候補またはHOLD状態を既存のAES-256-GCM方式で保存し、復号して一致を確認する。公開artifactは `learning.enc`、認証付き `learning.json`、件数だけの `summary.json`。復号SQLite・特徴量・結果原本・係数の平文はアップロードしない。

既存workflow内のステップ追加だけで、新しいworkflow・job・定期実行・権限は追加していない。既存の7日artifact保持を使用する。候補は元の暗号化原本から再計算できる。長期保管の承認を新たに仮定しない。

利用可能な範囲の法的判断をHMACで代用しない。最初の開発条件「規約が不明な用途では取得・保存・学習を実行せず、その部分を保留する」に従い、実際の係数学習を保留している。既存の暗号化履歴の検証とHOLDの記録は実行済み。

許諾の根拠が確認できた場合は、既存 `PermissionPolicy` 形式の独立したレビュー記録を用意する。取得元URLとrights refを正確に指定し、実際の根拠URL・レビュー者・確認日時・有効期限・`model_training` を含める。既存の `RACE_AI_SOURCE_REVIEW_KEY` で認証し、暗号化用の `RACE_AI_STATE_KEY` とは分ける。有効期限切れ・改変・用途違い・未登録取得元は学習を通さない。

Actionsは `audit/state/boat-venue-learning-permissions.json` が存在する場合のみ読み込む。このファイルは現時点で**作成していない**。非公開の許諾資料を公開リポジトリに置かない。CLIでは公開安全性を確認したレビュー記録または所有者管理の非公開ファイルを `--permission-policy` で指定できる。

```bash
python -m scripts.boat_pdca_github readback \
  --input audit/state/boat-pdca-production-input.json \
  --private-dir /private/boat-production-readback
python -m scripts.boat_venue_learning \
  --restored-dir /private/boat-production-readback \
  --out-dir /private/new-venue-learning-candidate
```

キーは環境変数で渡す。コマンドライン・ログ・Gitに値を記載しない。出力先は毎回空の専用ディレクトリを使用し、既存候補を上書きしない。

## 検証と次工程

合成データでは、実際の既存学習器で20レースから2系統の係数を推定し、暗号化保存・復元後に既存 `make_shadows` の未来入力契約へ接続できた。これは合成テストであり、実データ学習・予想精度改善・本番運用成功の証拠ではない。

検証対象: 利用用途・期限・署名、未来時刻・スナップショット改変、同一レースの重複計上、後の非会場別P1を古い会場別P0に戻さないこと、holdout結果が学習係数に影響しないこと、少数母数、暗号化改変、独立GitHub証拠、元履歴SHA維持、復元状態と入力ポインターの不一致、キー欠落時の無取得HOLD。

7件の追加・公式結果照合・独立証拠の追記は完了した。最小の残工程は、62取得元に対応する学習用途の根拠を確認し、既存の用途別レビュー記録を用意すること。根拠と有効な記録が揃えば、この接続が既存学習器を呼ぶ。その後、候補の独立した保存証拠を取得し、未来レースで基準モデルと同条件のshadow比較を行う。本番への反映は別途承認を必要とする。
