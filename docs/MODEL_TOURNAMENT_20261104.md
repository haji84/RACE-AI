
# RACE-AI 既存モデル・同一レース比較ゲート（2026-11-04）

## 方針
**新しい予想モデルを追加しない。** 4競技共通の既存4モデルと、条件が揃った場合の既存時系列学習型を、同一レース・同一コホート（A／B等）・同一as-ofの入力で比較する。既存のボートA/B/C-liteやオート専用版は異なる情報量の予想を同条件と偽らず、個別コホートで比較する。

## 今回の実装
- race_ai/model_tournament.py：保存済みの共通run_suite出力と別時点の結果観測を読み、モデル×買い目4方式（固定8、固定12、事前の荒れ判定8/12、少点数1〜8）の成績を集計。
- tests/test_model_tournament.py：架空の4競技で入力と原予想のSHAを検証。未確認、中止・全額返還、万舟、欠落レース、重複、結果の時間逆転を試験。
- 同一コホートの同一レースで各モデルを比較。実購入は行わず、1点100円均等の仮想収支、的中率、回収率、万舟捕捉率、順位別Hit@1/3/6/8/12を別々に表示。
- 1〜12点の予想に0点は認めない。見送りは予想の買い目数ではなく別の状態として記録する。

## 実行
Python標準ライブラリと既存コードで動く。外部HTTPは行わない。ユーザーの非公開領域にJSONLを保存して使う。

1. 保存済み予想と後刻の結果を1行のJSONにする。各行は cohort、suite、result の3項目。suiteは改変していないrun_suite出力。resultは既存ticket_selection_engine.evaluate_ticket_trials形式。結果待ちはnull。
2. 発売対象の全レースを別のschedule.jsonlに1行につき cohort、race_id で列挙する。欠落した予想は勝手に分母から削除しない。
3. コマンド：
   python -m unittest tests.test_model_tournament -v
   python -m race_ai.model_tournament --bundles PRIVATE/suites_and_results.jsonl --schedule PRIVATE/schedule.jsonl --out PRIVATE/model_tournament_001
4. summary.json（モデル別指標と研究用順位）、per_model_per_race.csv（全買い目方式・的中順位・返還・払戻・元モデルSHA）を出力。既存ファイルの上書きを拒否する。

## 研究用の選抜規則
- 同じA/B区分で、同一レースの全モデルが固定8点について正常精算された**共通母集団**で比較する。
- 最低100レース、5つの別日、指定した台帳の予想欠落ゼロを最小の暫定比較条件とする。統計的有意性は別途必要。
- 的中数、仮想収支、万舟捕捉の3条件すべてで他モデル以上、少なくとも1項目で優れ、競合トレードオフがなければ「仮の研究リーダー」。そうでなければ勝者なし。
- モデルの本番自動切替、main統合、公開、課金、自動投票はしない。ソース利用権限・実締切前保存の第三者時刻・結果真正性・統計的再現性が確認されるまで正式的中率・確定優勝を表示しない。

## 未達の実データ接続
- 同じ未来レースで全モデルを発走前に不変保存し、別途結果・返還・訂正を取得する運転経路は完全実証されていない。
- 11月3日の朝版252レースは参考照合用で、共通4モデルの同条件事前保存が全件あるわけではない。後から予想を再計算して前向き成績にしてはならない。
- 既存ボート全国締切順タスクの原本保存経路を再利用し、モデル数を増やさず、まず1日の欠落なし実証と原本の非公開長期保存を完了する。データを許諾なく大量再配布しない。
