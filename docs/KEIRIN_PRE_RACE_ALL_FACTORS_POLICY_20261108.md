# 競輪：全情報の予想前チェック運用 v1（2026-11-08）

## 全レース・全選手に適用

RACE-AIで競輪3連単予想を出す時は、**すべての項目について「確認したかどうか」を必ず記録する。** 現在の観測値が見つからない場合も省略せず「未取得・理由・予想への影響」を記録。推測で数値を埋めない。

機械的な全項目正本：race_ai/keirin_preflight.py（RACE_ITEMS / RIDER_ITEMS）。
適用範囲：全競輪場・全レース・各出走選手。最大8点、締切前保存、結果の後付け禁止、オッズのモデル投入禁止、返還・実収支の分離は既存Issue #67の仕様を優先。

## ① レース単位で必ず確認

| 分野 | すべて確認する項目 |
|---|---|
| 同一性・条件 | 開催日、競輪場、R、race_id、級班・格付、予選/準決/決勝、開催何日目、距離、発走、**公式締切** |
| 勝ち上がり | 予選突破条件、勝ち上がり規則、点数条件、開催段階ごとの戦略の違い。**勝利動機は推測**として扱う |
| 出走状態 | 全選手の車番、直前欠場・補充・出走変更・訂正、情報の版と更新時刻 |
| ライン・戦術 | 並び、先頭・番手・3番手、競り、単騎、先手ラインの選択、選手コメント、主導権争いの候補 |
| 展開シナリオ | 前受け、突っ張り、逃げ、捲り、番手差し、先行争い、ライン分断、番手離れ、他ライン混在、位置取りの変化 |
| バンク | 周長、カント、コーナー形状、直線長、走路状況、同距離・戦法別の適性 |
| 天候 | 実際の風速・風向、雨量、路面の濡れ、気温、湿度、当日のバンク傾向（観測できない場合は未確認） |
| 証拠 | 出典URL、発表時刻、取得時刻、利用許諾、観測SHA、予想時点で有効か、複数ソースの矛盾 |

## ② 各出走選手について必ず確認

| 分野 | すべて確認する項目 |
|---|---|
| 能力 | 車番、本人、級班、競走得点、相手の強さ、年齢、期別、経験 |
| 着順 | 1着率、2着率、3着率、3連対率、試行数と集計期間 |
| 近走 | 直近3走・10走、相手関係、過去の展開、着順以上の競走内容、近走映像、調子の変化 |
| 脚質 | 逃げ、捲り、差し、マーク、それぞれの試行数と成功率 |
| S/H/B | スタート・ホーム・バックの回数、定義、観測期間、ソース間の食い違い |
| 速度と粘り | 上がりタイム、ラスト1周の伸び、加速、持久力、ペース耐性 |
| 位置取り | 前受け、後方待機、突っ張り、飛び付き、イン粘り、進路、単騎対応 |
| ライン連携 | 先頭役、番手の追走と差し、3番手の追走と離れ、同一ペア・同一ラインでの過去実績 |
| 対戦関係 | 今回の選手同士の直接対戦、過去の主導権争い、相手脚質との相性 |
| 場・天候適性 | 当地・同周長・同距離成績、バンク角度と直線適性、風・路面適性 |
| 状態 | 落車・失格歴、欠場理由、復帰後の状態、分かる範囲の怪我/体調、休養日数、連戦疲労 |
| 作戦・機材 | 選手の公開コメント、ギア倍数と変更、機材トラブル・交換履歴 |
| 根拠品質 | 情報の時点、ソース、利用許諾、データ母数、他資料との矛盾 |

重要度は「調査優先度」であり、実測されたモデル特徴量寄与率と同義ではない。年齢や当地成績などはサンプル不足や相関重複があれば過大評価しない。

## ③ 毎予想の必須ゲート

1. 当日対象レース全体を登録し、1Rから**締切の早い順**に確認。未予想・取消・締切超過も別管理する。
2. 正当な情報源から、レースの全項目 + **全出走選手それぞれの全項目**の状態を確認する。
3. 各項目の状態は verified（根拠確認）、unavailable（未取得）、stale（古い）、rights_blocked（利用不可）、not_applicable（非該当）のいずれか。未取得は理由必須。**確認状態がない項目を一つでも残さない。**
4. 重要項目（選手・級班・出走・レース条件・締切・ライン・主要脚質・直近実績・役割・コメント等）が確認できなければ**正式予想を停止**。欠測値を偽造しない。
5. 予想用データは必ず**締切前に公開・取得されたもの**。現場で取れなかった新情報は予想に使わず、未取得と明記する。事後の着順や失格判定も推論には混入させない。
6. 全3連単有効候補を検討して最大8点。ライン主導権・番手差し・捲り・別ライン混在など複数展開を比較。推定確率は実際に校正された証拠がなければ**未校正**と明記。
7. 出典と発表/取得時刻、race_id、各選手、観測ハッシュ、監査状態とモデル版を同じ入力スナップショットに結合して**締切前に別保存**。締切後に原予想を書き換えない。
8. 確定後は公式の着順・払戻（100円単位）・失格・同着・返還・中止・訂正を照合。結果の事後訂正は revision として旧集計を置換し、二重加算しない。
9. **A/Bは同じ未来レースの事前保存済み両版のみ公平比較。** 外れ原因は確認事実/推測/不明を分ける。
10. 参考収支は有効な事前予想の1点100円で計算。実購入額や実利益は記録がなければ不明（未確認）。確定払戻を事後の参考収支に使う以外、オッズ・人気・市場由来データを予想・学習・モデル比較に入れない。

## ④ 監査データの契約とシステム接続状況

- 監査契約：RACE_AI_KEIRIN_PRE_RACE_AUDIT_V1
- race_id、starters、official_cutoff_at、evidence_sha256、checked_at、items を記録。
- 各 item は key、status、reason、source_url、published_at、captured_at、rights_ref、observation_sha256 を持つ。
- verified には HTTPS出典、公開/取得時刻、用途を確認すべき権利参照、観測SHAが必要。その他の状態では理由を残し、観測値や根拠を偽造しない。
- 監査を入力スナップショットの facts.keirin_pre_race_audit_v1 に入れ、同じスナップショットの facts.pr71_evidenced_snapshot のハッシュで結び付ける。
- race_ai/keirin_pr71_model_adapter.py では**実データ研究スコープ**で全項目の監査と重要項目の確認が終わらなければモデル呼出し前に拒否する。合成テストは別扱い。
- **注意：監査内の rights_ref 自体は本物の許諾証明ではない。別の信頼できる審査経路で利用権限を検証する。** 公開GitHubへ個別の非公開予想原本を置かない。
- この変更では外部データの合法的自動取得、全特徴量の既存モデルへの実装、実データ学習、実稼働、正式な時刻凍結や98%達成は証明していない。次は許諾済みフィーダーが監査を生成する接続と、全特徴量が予想モデルで使われるかの対応表を検証する。

**改訂時の原則：** 新しい項目を見つけたら正本契約に追加し、全レースで調査対象とする。未確認のまま「すべて確認済み」と報告しない。
