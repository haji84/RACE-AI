# レース単位の非公開クラウド観測

正式引継書の直前情報・オッズ・結果を、既存の当日番組に接続する工程。
通常開発とPreview検証の継続指示に基づく。既存Python Functionsと非公開Blobを使い、
Production、秘密値、OIDC信頼先の設定は変更しない。

## 保存と配信

- `POST /api/publish-race` は既存専用GitHub OIDCとPreview環境、アプリの完全コミットSHAを照合する。
- 当日APIの承認済み番組からレースを選ぶ。登録番号・正規化氏名・枠・締切時刻を共通契約で照合する。
- 原本HTMLは保存しない。正規化した観測の不変版を非公開Blobへ保存し、全バイト読戻し後にサーバーの実時刻を測る。
- `cloud_saved_at` はこの読戻し後の時刻。RunnerのSQLite保存時刻とは別に保持する。
  発走前の資格は、元観測・Runner保存・実クラウド保存のすべてが締切前の場合だけ付ける。
- 観測本文とクラウド受領記録は別の不変キーに保存する。同じ内容の再試行は最初の受領時刻を維持する。
- 現在版マニフェストは各種別の最新1版、最大3版だけを参照する。古い版の遅配では最新を戻さない。
  過去の不変オブジェクトは残るが、全履歴の利用者向け照会APIはこの工程に含めない。
- `GET /api/race?race_id=YYYYMMDD-vv-rr` は当日の番組と現在版、受領記録、本文を再照合する。
  本文とSHA、時刻、種別、枠・登録番号が合わなければ表示を止める。未取得は404で表す。

共通契約は `web/race_contract.py`。Functionsのデプロイルート内で独立して読み込める。
オフライン結合側も同じ契約を使う。過去レースを後日取得した監査記録は残せるが、
当日クラウド入口は取得・保存日も当日に限定する。最終オッズと確定結果は事前特徴量にしない。

Blob SDKにcompare-and-swapはない。書込は既存ワークフローの共通concurrency groupで直列化する。
別の書込経路を追加する際は同じ直列化が必要。API自体が分散ロックを提供するという主張はしない。

## 取得・画面の範囲

`scripts/publish_race_updates.py` は当日APIを再利用し、最初の未締切レースの展示と3連単オッズを
最大2回GETする。全レース終了後は最後のレース結果を1回GETする。1回の実行で全国全レースを
巡回しない。デフォルトは通信なしのdry-run。日次B番組表を再取得する処理は含めない。

画面は選択したレースの詳細を取得し、展示・120通りオッズ・結果を別パネルで表示する。
切替前の遅い応答は破棄し、失敗時は以前の観測を表示から除く。未確定値はゼロに補完しない。
元の番組艇データを上書きせず、出典・取得・実クラウド保存時刻と締切前後の区別を表示する。

実レースの自動予想保存、購入履歴のクラウド保存・結果精算、全場の定期巡回、
PC不要の日次cron、実精度の評価は別の未完工程として残す。

早朝の実ページで確認した「6行すべてが空の展示グリッド」と「120通りすべてが0.0の
発売前オッズ」は、日付・レース・6艇の氏名等の証拠と正確な構造を照合した場合だけ
`PENDING`、`data:null` として記録する。0倍のオッズとして表示しない。
正確な当日表・120通り・6艇・単一の公式更新時計を照合でき、従来の最終オッズラベルが
ない現在の掲載形式では、正のオッズと0.0の混在を `PARTIAL` として扱う。正の値だけを
保持し、0.0の枠は `null` と `SOURCE_ZERO_PLACEHOLDER` にする。0.0の理由を
「票なし」「未発売」と断定しない。従来・最終オッズラベルでの混在、欠けたグリッド、
時刻・艇の証拠が欠ける場合は拒否する。所有者確認は事実データの範囲のみを使う。

一方の取得が失敗しても、別種別の検証済み観測は保存できる。失敗した種別の新しい
観測を捏造せず、現在版を書き換えない。実行ログは `PARTIAL_VERIFIED` と
`failed_kinds` の固定コードで不足を示す。全取得失敗ではPOSTせず異常終了する。
中止・不成立・延期を一度確認したレースは、更新失敗でも手動購入記録を再開しない。

## 検証

合成テストで入力拒否、120通りの完全性、未確認の払戻、遅配、再試行、締切をまたぐ保存、
番組の差替え、改変した受領記録を確認する。Windows/Linux CI、独立レビューと
保護されたPreviewの実通信・画面証拠を別に記録する。合成テストを予測精度の証拠にしない。

小さなレース単位応答は256KB以内に制限する。
実装時に確認した [Functionsの制限](https://vercel.com/docs/functions/limitations) と
[Python実行環境](https://vercel.com/docs/functions/runtimes/python) の範囲で動作させる。
