# RACE-AI：購入検討時間と全3連単オッズの正式追加仕様 v1.1

決定日：2026-10-23 JST。上位GOAL [Issue #67](https://github.com/haji84/RACE-AI/issues/67)／既存画面 [PR #71](https://github.com/haji84/RACE-AI/pull/71)。**この文書の登録・合成テストと本番完成は別。**

## 問題の修正

以前の「公式販売締切より1秒でも前に予想を保存すればよい」は、買い目を比較して購入検討する**利用者にとって遅すぎる**。また「AIの固定8点のオッズだけ公開」では、他の組番を見たい利用者がサービス外へ移動する。次の2つを独立した受入条件とする。

### A. 利用者が購入判断できる時刻までに公開する

すべての時刻は公式**投票販売締切**を起点とし、発走予定時刻と混同しない。以下は現時点の**製品用初期設定案**であり、主催者の公式締切や達成実績ではない。競技/会場の本物の運用値が得られたら検証し、オーナー判断で調整する。

| 時点 | 要件 |
|---|---|
| T-30分 | 早期予想の初回**公開目標**。公開済み正規情報しか使わず、取得できなければ「準備中・欠測」と表示。架空の予想を埋めない |
| T-10分（初期正式SLA） | **最大8点の正式購入検討版のユーザー画面公開・予想SHA・外部受領時刻・読戻しまで完了していること**。内部生成やローカル保存だけでは達成扱いにしない |
| T-10分以降 | AI予想の順位・選抜結果を後変更しない。新規情報で出走変更/欠場・成立条件が変われば警告/失効扱いとし、旧予想を改ざんしない。全オッズ画面は別途更新継続 |
| T（公式締切） | 予想・ユーザーが閲覧できた時刻・オッズスナップショットの最終監査。以降は「販売締切済み」、購入検討用の当日リアルタイム表示を止め、参考履歴を明示 |

`race_ai/purchase_window_policy.py` の初期値は初回T-30、正式版T-10。これは**時刻の並び・期限計算のライブラリ**であり、自己申告の `visible_at`／`frozen_at` だけでは真正性を証明しない。`BUFFER_TARGET_REPORTED_NOT_ATTESTED` は外部証拠未確認という意味。製品の完成判定には独立に検証したサーバー公開/受領時刻が別途必要。

予想生成・内部凍結・外部保存・ユーザー画面に届く配信完了は**4つの異なるイベント**として記録する。T-10を満たせずT-5に成功した予想でも「買い目検討に十分間に合った」とは表示せず、`LATE_FOR_PURCHASE_REVIEW` を監査する。取りこぼし、予想なし、未公開は対象台帳・未達KPIから消さない。オッズを見る時間が必要なので、T-10以降の全面的な再予想は行わない。

### B. 予想8点と無関係に、全3連単オッズを閲覧できる

- 競技別の対象出走数 N から**すべての有効な異なる3着順：N×(N-1)×(N-2)通り**を扱う（例：6艇120、7車210、8車336、18頭4896）。取消・返還・特殊な発売ルールは主催者の実際の提供情報に従う。
- UIは［全3連単オッズ］の独立ページ。**未予想のレースでも**閲覧導線を表示する。AI8点だけの抜粋表示や「予想されなかった組番は非表示」は不可。
- 組番検索、1着固定フィルタ、オッズ高低/組番順、参考100円払戻、単純な損益分岐確率を提示。想定払戻は**購入時払戻の保証ではない**。
- 欠測した組番の値を0倍・予想値・架空のオッズで埋めず、各組番に `UNAVAILABLE` と `null` を明記。「全組番が列挙されていること」と「すべてに実オッズが提供されていること」は別。
- 予想8点との対応表示は別の独立した予想のread-only参照から計算する構想。**オッズでAI順位を入れ替えることは不可**。
- オッズ提供時刻、RACE-AI受信時刻、画面確認時刻、情報源のURL、レース締切、オッズ取得済み数/欠測数を常時明示。受信から120秒超は「更新遅延」、実締切後は「参考値」を表示。60秒周期の**自サイト保存済みデータの再取得**は、公式提供元の毎分更新を保証しない。
- **アクセス/再配信条件を独立確認した提供元だけ**運用で接続する。無料という仮定で全競技の全組番オッズが毎分取得できるとは決めつけない。

## 物理的に分離するデータの流れ

```text
  [許諾された出走/選手/馬/展示/環境]
                   ↓
      ForecastEngine (オッズを渡さない)
                   ↓
      Top8 + 入力SHA + 外部時刻receipt
                   ↓
    T-10までに読戻し＋閲覧配信確定 ─────→ AI予想8点
                                              │ 読取だけ
                                              v
  [用途別許諾を確認した公式全オッズ提供元] → OddsIngest → FullOddsStore
                                                     ↓
                                           全組番オッズ閲覧
                        ※オッズからForecastEngineへの逆方向接続は禁止
```

オッズは `RACE_AI_FULL_TRIFECTA_ODDS_V1`、予想は既存の予想正本。データベース/ファイル/API名前空間・権限・テストを分離し、オッズフィードの更新が予想のSHA/候補/正式モデル選択に影響しないようにする。

## 画面用部品の実装範囲（Draft PR #71）

- `web/full-odds-model.js` は全有効組合せを照合し、欠落・重複・価格不正・ソース時刻不整合を拒否する。実ソースの真正性/ライセンス/受領時刻を自動証明する機能ではない。
- `web/full-odds.html`, `web/full-odds.js`, `web/full-odds.css` はiPhone向けの全オッズ閲覧画面、検索/ソート/1着番号フィルタ、未取得/古いオッズ表示、同一サイトに配信済みの `data/odds/{race_id}.json` を60秒おきに**閲覧時のみ**再確認する仕組み。提供元Webに直接接続しない。
- 各レースの既存 `web/forecast-audit.js` カードから全オッズページへ**同一サイト内リンク**を設ける。
- `race_ai/purchase_window_policy.py` はT-30、T-10の目標時刻/ユーザー公開遅延分類を定義する。サーバー側の配信完了/公式締切の独立照合は未実装。
- `tests/full_odds.test.cjs` と `tests/test_purchase_window_policy.py` は組番数・欠損・時刻・モデル分離を合成で検査する。

## バックエンド接続・正式受入までの未達

1. 全4競技の**公式オッズ全組合せの実取得元**（競馬は中央/地方を分離）の利用条件、取得上限、転載/再配信、費用・更新周期・最新性を調べて権限登録する。
2. 提供元の配信オッズをオッズ専用の形式に正規化して、1着～3着の全有効組合せと欠測/欠場/停止を検証。出走変更で組合せ宇宙を改訂する場合は版と時刻を保持。
3. 実際の公式販売締切に対しT-30初回公開、T-10正式版の**外部保存＋配信到達**を測定する。締切直前にしか公開されない展示などはT-10以降に買い目を密かに差し替えない。
4. 源流の毎分GETが許可される場合に限り、原則**締切が近いレースだけ**対象にした1分周期の限定ポーリング、同一データの再取得抑制、キャッシュ、403/429で停止・リトライ抑制を入れる。GitHub Actionsの5分最短スケジュールは使わず、Cloudflareの毎分Cron等は**別途費用と公開承認を得てから**実装する。
5. UIの実iPhone Safari表示・鮮度警告・全面組番閲覧・表示失敗からの復旧を受入試験。完全な公式更新と想定払戻の正確性を現物で検証する。

**現段階では公式オッズの自動取得・毎分新規取得・本番配信・T-10公開の実レース受入・実際の外部freeze・Hit@8 98%再現性のいずれも未達。** 合成デモを実オッズとして配信しない。main統合や本番公開、課金、自動投票を勝手に行わない。
