## 3. 維持する予想・評価の要件

処理順は次のとおり。

選手・並びなどの事前事実 → 初周 → 打鐘 → 最終ホーム → 最終バック → 4コーナー → ゴール → 候補 → 券種別の選択 → 点数

- 買い目を先に決め、その結果へ届く展開を後付けしない。
- 3連単と2車単は別々に選ぶ。2車単は3着候補を割り当てる前の1・2着支持から評価する。
- 点数は展開と根拠に応じて可変。旧方式の最大12点や、今回の評価窓である4点へ固定・水増ししない。
- 3連単の集中度は上位4組。勝者の集中度は上位2車のまま。現行の1・2着上位4組指標も維持する。
- 評価表示は「激アツ🔥、高、中、低」。判断材料がない場合の「未評価」を残す。
- 上位4組は評価の窓であり、購入候補を必ず4点にする指示ではない。
- 主要分岐の取りこぼし、欠測、未モデル化のリスクを表示する。強い評価を出すために閾値を緩めない。
- 内部支持の比率は実測的中率ではない。A/Bは同じ入力・展開集合を共有し、一致を独立した二重の裏付けとして扱わない。
- 旧v1/v2/v3、正式sidecarの契約、凍結済み評価を遡及変更しない。
- オッズ・人気・市場由来の値を予想、学習、特徴選択へ入れない。確定後の仮想収支評価は別工程にする。

## 4. 豊橋6Rで確認できた欠陥

対象は2026-11-22豊橋6R、race_id 202611224506。確認した全着順は2 → 3 → 1 → 5 → 4 → 6 → 7。3連単2-3-1は15,550円、2車単2-3は3,360円。Kdreamsとnetkeirinの結果表示が一致した。

### コードから確認した事実

- 元の3連単全10候補に2-3-1がなく、2車単全8候補にも2-3がなかった。採用段階で落としたのではなく、候補生成の段階から存在しない。
- 掲載ラインは[7,1,3] / [6,2,5,4]。全候補の上位2車には必ず6番か7番が入る。
- _evidence_profilesは2番をexplicit_attack=Trueと判断するが、_evidence_scenariosは掲載ラインの先頭だけを仕掛け役にする。
- 番手差しFOLLOWER_PASSでは、元の先頭が2着に残る。2番が勝つ唯一の候補は2-6-5である。
- ATTACKER_FADEも限定された経路であり、両ラインの先頭がともに後退し、後続が別線をまたいで上位になる経路を十分に表現できない。
- 支持値は1着能力の2乗 × 2着能力の1.3乗 × 分岐係数。2番の勝ち筋を6番の2着残りに縛るため、2番の評価が6番の低い2着能力にも抑えられる。
- 現在の主要集合は、候補支持比率10%以上の各候補を代表するシナリオに、各対抗分岐種類の最強シナリオを一つずつ加えたもの。分岐種類の代表は仕掛け役ごとには選ばないため、支持の低い反対側ライン・別の仕掛け役の経路が主要集合から外れる場合がある。
- 狭い生成集合を合計1へ正規化し、生成されなかった展開の残余リスクを持たないため、内部集中度が過大な安心感につながる。
- 上位4組に変更してもA・3連単は94.6457506074%で「激アツ」のまま。評価窓変更だけでは生成欠落を解決しない。

## 5. 深掘りする選手特性の8群

| 群 | 観測・条件 | 予測への接続 |

| 1. 仕掛けの選び方 | 突っ張る・抑える・かます・捲る。どの位置、相手、時点で選んだか | 打鐘・最終H・最終Bの行動候補と選択傾向 |
| 2. 加速と踏み続ける力 | 踏出しへの反応、外を踏んだ区間、終盤の位置変化 | 仕掛けへの追随、持続、終盤の後退分岐 |

| 4. 番手での動き | 追走継続、差し、自力、別線への切替とその条件 | 先頭の状態を踏まえた番手の独立行動 |

「その動きができる」「今回その動きを選ぶ」「相手に対して成功する」は分けて扱う。選手名に固定の万能スコアを一つ付ける設計に戻さない。

映像で測っていない速度・加速度・消耗を実測値として出さない。年齢・期・所属地区だけで能力加点や連係成功を決めない。養成所時代の最高速度・ダッシュ力・持続時間を現在の能力へそのまま転用しない。

- 出走数当たりのH/B/Sには同じ期間と集計定義の分母が必要。不明なら算出しない。

- 一部条件の標本が少ない場合は推定の不確かさを示す。部分プーリング等の採用は提案として検証し、重みや事前分布を実績なしに確定しない。

## 8. 実装順

### P0：現状の固定と差分の境界

最新main、関連PR、生成器と入力の版、元の評価、再現用の合成fixtureを固定する。私有原本へアクセスできなければその事実を記録し、合成fixtureと公開済み監査から進められる修正を続ける。

### P1：既存の特性を展開へつなぐ

番手自力、先頭を見切る切替、追走離れ・再接続、複数の先頭後退、別線後続の進出を、局面の状態・位置・進路・行動条件として実装する。

全順列を追加して当たりを含める方式にしない。各経路に事前根拠と成立条件を付ける。根拠が不足する場合は確定行動にせず、仮説と不確かさを出す。重複する同じ経路・ゴールで支持を水増ししない。

分岐種類だけでなく仕掛け役・対抗側も見て、主要な経路を扱ったかを監査する。生成集合の外が不明なまま、集中度だけを総合的な確信として表示する問題も扱う。未モデル化の確率を根拠なく数値化しない。

### P2：登録番号と履歴の接続

出走表から公式登録番号を検証して接続し、取得・公開・統計対象時点と出典を保持する。既存の履歴受入部品を現在の方式へ適合させる。未確定IDや将来データを混ぜない。

直近の着順だけでなく相手、級班、役割、開催条件を区別する。データがない項目は明示して、利用可能な項目から進める。

### P3：条件別の特性

8群を、利用可能性と増分効果を見ながら段階的に導入する。バンク形状・みなし直線は出典と適用時点を確認する。風はレース時刻付近の方向・速度と走行方向を関連付ける。車場の一般説明だけで当日の風向を埋めない。

映像解析は既存の許可・取得経路で扱えるものに限り、観測できた局面と品質を記録する。位置や行動ラベルが不足しても、それを捏造して作業完了にしない。

### P4：同じ未来レースで評価

学習・調整用期間と、採否を判断する未使用の未来期間を分離する。旧版と改修版を同じ対象レース・同じ締切前情報で凍結する。対象期間、対象抽出、版、評価指標を先に固定する。

結果を見てからモデルを選び、その同じ結果を未知データの評価と呼ばない。改修版を自動的に正式採用せず、根拠と不確かさを報告する。

## 9. 技術上の合格条件

変更箇所に対応した意味のあるテストと独立レビューで確認する。

1. 特性の入力から使用局面・分岐まで追跡でき、読み取っただけの未使用特徴も判別できる。
2. 番手の自力・切替が、ゴールだけの並べ替えでなく、それ以前の局面から成立する。
3. 各局面で出走車の重複・消失がなく、位置変化に経路と条件がある。成立しない条件も確認する。
4. 合成ケースで両先頭後退や別線後続の進出を表現できる。豊橋の車番・実結果の直書きに依存しない。
5. 仕掛け役やラインの名前・車番を変えても、意味が同じ条件では恣意的な優遇を生まない。
6. 3着候補の追加・重複だけで2車単の支持や評価が増えない。2車単を3連単の採用分から抽出する実装に戻さない。
7. 点数を12点や4点へ固定せず、件数、除外理由、支持の分母を出す。
8. 登録番号、出典、時刻、対象期間、欠測が保持され、対象結果や未来データが特徴へ流れない。
9. 旧原本と旧評価を同じ版で再現できる。新しい研究出力は新しい時刻・版として保存される。
10. 生成器、CLI、評価、公開要約の契約が整合する。欠測のあるデータを「特性を加味済み」と表示しない。
11. 原本・秘密情報・取得本文を公開GitHubやログへ出さず、既存の暗号化保存・原本照合を維持する。

テスト件数の増加自体を成果としない。変更で生じた具体的なリスクと既存の必須ゲートを検証する。

## 10. 実際の有効性を判断する指標

ソフトウェアの合格と、予測が改善したという判定を分ける。

| 指標 | 必要な記録 |
| --- | --- |
| 候補集合からの実結果欠落 | 3連単・2車単ごとの包含有無、候補総数。候補を増やしただけの改善を見分ける |
| 3連単上位4組 | 凍結済みの上位4組が実結果を含む割合、対象数、評価期間 |
| 勝者上位2車 | 凍結済みの上位2車と実際の1着の対応。2車単的中とは別に集計する |
| 採用買い目の成績 | 券種別の的中、採用点数、見送り、未予想。可変点数の成績と同点数・同予算比較を併記する |
| 仮想収支 | 事前固定した配分と公式払戻による計算。実購入・実収益と混同しない |
| 六局面 | 検証可能な実映像の観測と予測の差。見えていない局面を分母へ都合よく追加しない |
| 評価の妥当性 | 激アツ・高・中・低別の件数と結果、不確かさ。内部支持率を実測確率と扱わない |
| 入力の品質 | 登録番号の接続率、特徴ごとの欠測、出典・時点不備、締切前凍結率 |

各特性を外した場合の比較も使い、どの追加が役立ったかを確認する。少数の成功例や一つの高配当レースだけで採用を決めない。

実レースの証拠は、締切前の取得 → A/B等の原本凍結 → 別の実行によるハッシュ照合 → 結果・改訂の照合 → 同じ原本を使う画面表示まで確認する。関連する実データ工程が未達なら未達と書く。合成E2E、CI、事後再現、PRマージで実戦精度を証明したことにしない。

## 11. 制約と保存

AGENTS.mdを優先して読み、GitHubを正本として既存の許可された経路を使う。Cloudflare、Vercel、新しい外部基盤、課金、権限変更、秘密情報の変更、自動購入は今回の引継ぎに含まれない。既存Siteの画面資産を利用することは、新しい予想バックエンドを許可する意味ではない。

公開リポジトリへ、私有予想原本、平文SQLite、秘密鍵、取得ページ本文、私有の全入力レコードを載せない。既存のAES-256-GCMと所有者の設定済みSecretを使う契約を維持する。キーを公開情報から作らない。原本が復元できない場合、空のDBへ黙って置換しない。
