# RACE-AI 四競技・全情報型予想モデル v1.0（2026-10-23）

最上位GOAL: [Issue #67](https://github.com/haji84/RACE-AI/issues/67)、開発P0: [Issue #68](https://github.com/haji84/RACE-AI/issues/68)、既存差分: Draft [PR #71](https://github.com/haji84/RACE-AI/pull/71)。

**この文書は現時点で実装・テストした研究モデルの契約と、全4競技を実データで予測する際の必須ゲートを記録する。実測Hit@8=98％の達成・本番稼働を宣言しない。**

## A. 予測入力の範囲

### 全競技共通

長期能力、直近の成績・推移、スタート信頼性、末脚・上がり、距離/コース適性、持久力、戦術適応力、安定性、出走者の走法タイプ、枠/車番/艇番、対戦構成、実際のレース種別・距離・開催日、風・雨・湿度・気温・走路濡れ。

**注意:** 年齢、性別、体格、負荷・疲労なども検証候補だが、実データ出典、必要性、予測寄与を検証して追加する。情報が多いこと自体は高精度の根拠にならない。情報源の許諾、予測時点、母数を明示しない特徴は採用しない。

### ボートレース

選手の全国/当地勝率・級別、3/10走などの近走、STと反則リスク、モーター2連対率/交換効果/整備、ボート機材、展示タイム・展示ST・進入、コース適性、ターン・伸び、追い風/向かい風・波/うねり・水流・潮位、フライング/欠場/進入変更。公式サイトの出走表・直前情報は入力候補だが、自動取得権利は別途審査。

### 競輪

競走得点、直近内容、脚質（逃・捲・差・追）、S/H/Bの回数と**成績の母数**、先行/追走能力、ライン人数と選手順/連携、番手/3番手、同型競合、バンク周長・勾配・直線長、風・走路、先行/追込みの展開、疲労/日程、補充・欠場・並び変更。

### オートレース

選手能力、級別/直近成績、試走タイム、スタート力、0m～のハンデ・追い抜き、車/エンジン・タイヤ調整、独走力・追込み力、良/湿/斑走路、走路温度・風・雨、枠と前走の実測、対戦とスタート隊列。

### 競馬（JRA・地方）

馬の能力指数、過去レース・ラップ/上がり、先行力・末脚、枠順・ペース/隊列・不利、距離・芝/ダート・馬場・含水・コース方向・開催条件、斤量・馬体重の増減、年齢・休養/間隔、調教・追い切り・パドックで予想前に確認できた情報、騎手/厩舎・コンビ・血統適性、展開相性、頭数、クラス上昇。馬名の表記揺れ、取消・騎手変更に注意。

### 入力技術契約

`race_ai/comprehensive_four_sport_models.py` の `RACE_AI_FOUR_SPORT_EVIDENCED_SNAPSHOT_V1` を正本入力型とする。共通必須8指標＋競技別必須3〜4指標・多数の競技別任意指標、共通気象5指標＋競技別環境4指標、レース識別・予測時刻・締切・revision・出走者識別/脚質/枠/ライン。全観測に `value` / `published_at` / `captured_at` / `source_ref` / `source_rights_ref` / `sample_n` / `transform_id` を要求。

- 各競技の入力は独立に正規化。時間や斤量・ハンデなど「小さい値がよい」生データは、過去データだけで定めた明示的変換で正規化し、学習データと未来データの間で係数を再計算しない。
- 必須値や日時・権限が足りなければモデル実行を拒否し `NO_FORECAST + reason` とする。任意特徴の不足は**明示記録**し、存在しない情報を架空の数値で補完しない。
- 未来の結果、実着順、払戻、オッズ、人気・市場情報を予想入力へ入れない。オッズは事前確定後の経済評価だけ。
- データ閲覧可と自動収集・保存・学習・二次公開可能を同一視しない。各行の用途別権利と時点を独立確認し、不足するソースは当該用途だけ停止。

## B. モデルの構成

| 系統 | ID | 予測の中身 | 現状 |
|---|---|---|---|
| 共通総合要因 | `multisport-factor-interaction-v1` | 能力、近走、適性と走路・気象の相互作用 | 係数未学習、契約テスト済 |
| 展開混合 | `multisport-scenario-ensemble-v1` | 先行・差し/追込み・荒れた展開を別確率で合成 | 係数未学習、契約テスト済 |
| **条件付き対戦** | `multisport-conditional-duel-v1` | 1着を仮定した後続の能力、同ライン追走、対戦相性を反映した2・3着の条件付き分布 | 新規実装、係数未学習 |
| **着順展開** | `multisport-race-trajectory-v1` | 先行/追走/波乱の3条件付き経路を、事前の天候や展開圧で混合 | 新規実装、係数未学習 |
| 時系列学習 | `four_sport_learning.py` の `LEARNED_ID` | 前向き過去データで学習、訓練/検証/ホールドアウトを時系列分離 | 合成データによる学習テスト、実データ学習は未実証 |

新しい2モデルはPlackett-Luceの固定能力式だけでなく `P(1着) × P(2着｜1着・展開・相性) × P(3着｜1着2着・展開・相性)` で全組番を計算。競輪同ラインの後続、競馬の先行・追込の相互作用、オートの追抜き・湿走路、ボートの進入・波の適応を仮説係数で反映。全モデルが1レースに対し厳密に `N×(N−1)×(N−2)` 通りを評価し、同じ入力時点の最大8点を別々に出す。

## C. 共通モデル実行と本人評価

- `race_ai/four_sport_model_suite.py`：共通1スナップショットに対して**固定研究4モデルを並行計算**する。事前に学習して検査済みの学習器を明示供給した場合だけ5モデル目を加える。学習を本番レース中に行ってはいけない。
- `race_ai/four_sport_matchup_models.py`：条件付き対戦＋着順展開モデル。原スナップショットのSHA、全候補、Top8、モデル版、実行前情報の欠測情報を保持。
- `race_ai/four_sport_learning.py`：ラベルは出走前特徴と物理的に分離し、訓練・検証・最終未使用テストの時点を順守。実学習データの許諾と前向き予測精度の別監査が必要。
- `race_ai/verified_event_projection.py`：**元の確定本命予想**は結果後に別モデルへ差し替えない。対照予想も各々独立SHAと外部時刻receiptを持つ。
- iPhoneの `web/forecast-audit.html` には、本命8点・各比較モデル8点・結果・的中/不的中・未予想理由・モデル別Hit@8の実母数を表示する。現状の実データ配信・配備は未完成。

## D. 公平なPDCA

1. **前日から全開催の公式一覧を確保**し、4競技を締切昇順に処理。未予想・欠場・不成立を含む全発見台帳を保存。
2. 合法な出走前特徴を各モデルに**完全同一のsnapshot SHA / as_of / cutoff**で投入し、モデルIDと候補全件/Top8・予想原本を実締切前に独立時刻検証付きで固定。
3. 公式確定結果と改訂/同着/失格/返還を結果源で検証し、凍結前に結果の一切をモデルへ戻さない。
4. 正式主KPIは `Hit@8_all=的中した事前固定8点があるレース数/3連単発売・公式評価可能な**全対象レース**`。予想失敗・見送り・締切超過も分母に残す。研究/合成と実測は別区分。
5. モデルごとに全競技・会場・期間・母数・的中/不的中・欠測・95%信頼区間・校正指標/回収率（購入と仮想は別）を記録。**同じ未来レース集合だけで比較**し、結果を見てから最も良かったモデルを過去の本命に採用しない。
6. 失敗を「1着違い/2着違い/3着違い」「出走変更」「データ欠測」「天候急変」「対戦・展開違い」「モデル校正不足」「ソース不適格」に分類し、確認できた事実・仮説・不明を分ける。未来期間の再現性がない係数変更は採用しない。

## E. 製品完成まで残るゲート

- **リアルデータ**：公式競技別出走/近走/モーター/展示/試走/馬場/気象の用途別権利を確認し、出走前事実スナップショットを継続供給できること。
- **本番保存**：公式販売締切の前に不変データを外部信頼できる時刻証明付きで保存し、予想原本と再起動後読み戻しが一致すること。
- **公式結果**：発売/着順/払戻・取消/返還・訂正の結果revisionを自動取り込み、時刻付きで照合できること。
- **本人画面**：iPhone Safariで4競技すべての全レース・予想5モデル比較・結果・理由・証拠を実機確認できること。
- **精度**：未来の全対象レースで実測Hit@8を追跡して98％以上という非常に高い目標の実証と再現性を得ること。現時点で**未実証・到達可能性の保証なし**。
