## 4. 実行アーキテクチャ：一つの予想AI

- 既存のAは比較基準、既存Bを改良、Cは独立データが確認できる場合に継続。C未完成でA/Bを停止しない。モデル系列を乱立させない。既存実装（カルテ、JointFinish、6局面、既存分類器/採点器、暗号化原本、公開UI）を再利用。
- MacBookとActionsの受渡し契約：race_id、公式登録番号、source_id/時刻、cutoff、schema_version、model_id、artifact SHA256、観測信頼度・欠損、認証されたreceipt、状態versionを一致させる。既存schemaに互換の拡張を優先。古い・重複・破損・未許諾・不正時点の入力を拒否。単一書込権限、排他、冪等キー、原子的な公開切替、ロールバックを実装。安全な復元ができない場合は初期化しない。
- MacBookから新しいカルテ/特徴量/比較モデルが到着したら検証し、承認済み版だけ既存予想へ接続。実際に次の締切前予想でその版が読まれたことをreceiptと原本で証明する。MacBookが一時停止しても既存の安全な承認済み版を使用し、鮮度/欠損を記録。学習が遅れても当日の全国予想・結果照合を止めない。

## 8. 選手カルテ・研究特徴
長期（全収録/3年/1年/6・4・3・1か月）と短期（直近30/20/10/5走、3開催、今開催、前日、最新コメント）を分離。級班・グレード・車立て・予選/準決/決勝/一般/特選・時間帯・ライン役割・相手の強さ・バンク・気象・落車/欠場/復帰を条件別に評価。少数標本を補正し、期間・分母・欠損・根拠・信頼区間を持つ。
必須の能力分類: 身体能力（持久/瞬発/ダッシュ/加速/再加速/末脚）、戦術、判断/反応、展開支配、環境適応、調子、消耗耐性、連係。現時点の結果だけでなく強敵への走行内容、不利な位置からの回復、着差・上がり、H/B/S、相手の強さを評価。
追加必須:
- 主導権獲得力と先頭維持力を分ける。先手を取った逃げ/カマシ/捲り/番手自力の継続距離・時間、加速回数、外周、踏合い、並走、失速開始局面、再加速、消耗後の伸び、残存脚力（潜在推定）を記録。先行距離/時間別の着順維持・失速率。着外の選手も展開の起点として評価する。
- 単騎：前受け、他選手を行かせる、2/3/4番手・中団維持、単騎先行/突っ張り/捲り/切替、他ライン利用、仕掛け順、単騎での展開支配。S回数と初周・中団維持を混同しない。
- 多段捲り：誰の仕掛けに誰が何時点で反応し、その上を誰が捲るか。後仕掛け逆転、捲り合戦の成功/失敗、外回り消耗、急加速への番手追走。
- 番手：先頭の失速時の援護/差し/番手自力/切替/抵抗/追走/千切れ、並走の内外、3番手の追上げ、ライン維持/崩壊後の着順。番手の自力能力を独立評価。
- 連係関係：同県/地区/ホーム/練習拠点/同門/師弟/同期/先輩後輩/地元/連係履歴、勝ち上がり条件。実行動・発言に基づき条件別先行距離・早仕掛け・援護・追走・着順を比較。誰を勝たせたいかは仮説であり、内心や不正を断定しない。同県を固定的な有利要因にせず交絡を調整。
- コメントは原文、公開時点、出典を記録し、調子・脚・疲労・重い走路・風・戦術方針・前日からの変更・連係を抽出。発言と実際の行動の一致を検証。
- バンク周長/直線/カント/形状/幅/屋内外/傾斜、風向・風速・温湿度・雨・湿潤路面・ホーム/バック風向、類似バンクと選手別戦術の相互作用。予報と事後実測を区別。
- 対戦相性：能力差、先行型/捲り型の人数、分戦、役割、相手別の仕掛け/消耗/位置取り。成功例だけでなく不発例を含む。
カルテは登録番号ごと、時点別に復元可能とし、更新前後と根拠を保存。過去能力と当日評価は別物。

2. 更新済みカルテ・観測・エラー種別・市場との同時点比較から、設定された探索空間内の特徴量/重み/校正/条件別モデル/ハイパーパラメータ候補を自動生成。実験ID、乱数seed、入力SHA、コード版を保存。
3. 時系列walk-forward等で学習/調整/未使用評価を分離。既知評価を繰返し使って候補を採用しない。複数候補探索による過学習を制御し、候補数・計算時間・メモリ上限・停止条件を設定する。
4. Baseline、A、現Champion、Challengerを同一レース・cutoff・点数・入力条件で比較。機能除去比較、区分別成績、確率校正、欠損、信頼区間も確認。
5. 有効候補は固定・SHA保全し、未使用未来の事前予想を現行版と並行して出す。十分な独立評価が終わるまでは本番を置換しない。採否の条件と最低検証件数/期間、許容劣化、不確実性を事前に定める。点数水増し、高信頼ラベル水増し、評価期間の事後変更は禁止。
6. 承認済みの探索空間・昇格ポリシー内のモデル更新を自動化する。現行のHuman Gate/本番pin承認が必要な場合は候補・証拠を準備し承認待ちとし、無断昇格しない。重大な仕様/コード/権限/デプロイ変更は従来のレビューを保持。自動でコードを書き換え保護を迂回する方式にしない。
7. 採用/棄却/保留の理由、精度差、処理時間、データ版、実験履歴、モデル版を保存。失敗・精度低下時はChampionを維持または安全に復旧。新しい研究項目は提案・検証できる範囲を広げ、プログラム改修が必要なものは課題として残す。無限の改善案生成ではなく成果物と採否を確定。
一巡を手動のCodex入力なしで実演すること。外部AI利用枠が尽きても既存処理・学習・評価が止まらないか、実際の運用で証明する。
