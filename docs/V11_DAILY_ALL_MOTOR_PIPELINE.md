# RACE AI v1.1 日次全モーター更新（安全なデータ入力方式）

## 目的
全国24場の現在のモーターを対象に、前節使用選手の実績・選手能力補正・整備・最新オリジナル展示の情報を、日次の研究用レポートで照合する。

**実装済みの範囲**: ユーザー/提供元から許諾済みで投入されたJSONデータについて、台帳掲載モーターを漏れなく処理し、入着履歴・乗り手補正の未校正残差・前節・同一日の展示を照合。欠測や取得元の信頼性もレポートへ明記。

**未実装の範囲**: 全国24場の実在するモーター番号の全自動発見、Webページへの自動アクセス、公式B/K/LZH本体の全量取込、オリジナル展示をライブで自動取得するフィード、モーター抜き期待値モデルの学習/較正、展示動画からの自動機力判定。全国すべての番号を網羅したことや確率精度の改善を主張しない。

## データ投入
標準出力先: daily-report.json と daily-report.html（外部通信なし・日本語で全モーターを表示）。実行前に以下のデータファイルを作業ディレクトリに置く。いずれも利用権限を確認したファイルのみ。プロジェクトが公開リポジトリの場合、権利未確認の原本や個人データをコミットしないこと。

1. inventory.json（必須）。基本構造:
```json
{
  "rights_confirmed": true,
  "published_at": "2026-10-14T21:10:00+09:00",
  "captured_at": "2026-10-14T21:12:00+09:00",
  "current_meet_id_by_venue": {"19": "meeting_20261014"},
  "venues": [
    {"venue": "19", "motor_cycle": "2026-A", "motors": [11, 12]}
  ]
}
```
これは説明用の架空番号の一部台帳であり、全国の現行モーター番号ではない。**モーターが1件しか書かれていなくても、その1件だけを「全国全量」とは言わない**。

2. motor_observations.json（任意）。レース結果履歴を全期間の配列として準備。外側のpublished_at、captured_at、rights_confirmed と rows の各行それぞれにも同じ3項目が必要。各行の必要項目は motor.py の import_motor_observation を参照: venue, motor_cycle, motor_no, race_id, meeting_id, racer_id, lane, actual_course, finish, race_at, rider_label, provenance, (あれば)事前motor-blind baseline。
3. motor_service.json（任意）。補修/部品変更イベントの配列。motor.py の import_motor_service と同じ必須キー。
4. exhibition.json（任意）。通常展示、1周、回り足、直線、スタート展示の時刻付きスナップショット配列。各要素は保存したときの published_at/captured_at/rights_confirmed を含み、内側 metrics に各艇laneの計測結果を持つ。コース進入と艇番は別管理。
5. assignments.json（任意）。**当日の**レースにどの艇番がどのモーターを使うか、公開時刻を含めた配列。レースIDは YYYYMMDD-VV-RR。exhibitionの race_id+lane と一致する場合にだけモーターの現在展示と結び付ける。艇番だけから自動で特定しない。

## 実行方法
```bash
python -m race_ai.daily --input-dir data/live --output daily-report.json
python -m race_ai.daily --input-dir data/live --asof 2026-10-14T22:00:00+09:00 --output daily-report.json
python -m unittest discover -s tests -v
```

## 自動更新の設計
- GitHub Actions daily-motor-audit.yml は日本時間23:00頃（日次予定）に実行する（UTC 14:00）。GitHubのschedule実行時刻は遅延する可能性がある。
- トリガーはschedule、workflow_dispatch。**GitHub Actionsのscheduleは原則デフォルトブランチ上のワークフローしか実行されないため、Draft PRのままでは毎日自動実行されない**。
- 更新元は作業ブランチ上のGitHub配下 data/live のJSONを読み、レポートをActionsの成果物として出す設計。外部に対する勝手な自動スクレイピングはしない。
- 一般公開リポジトリへ権利のない転載データをアップロードしない。別途、提供元との利用契約や安全なデータ転送先が決まっていない限り、真の「全24場のリアルタイム更新」運用は開始できない。
- 源泉JSONの更新が止まれば、レポートは当然古くなる。**ジョブの起動成功と情報の取得成功は別**。最新の実物がなければ「情報不足」またはSAFE_STOPを表示し、失敗にする。
- GitHub Actionsへ最新版を書き戻す権限は付与しない。レポート成果物は手動または許諾された基盤で取得し、GitHub自体は書き換えない。

## 予想に使うときの留意点
- 前節に新人が乗ったとき、単に「新人だから除外」はしない。モーターを使っていない事前予測確率と実績の残差を、標本数で縮めて参考表示。
- 「前節」には節IDが必要。最新の個別レースは前節の代理ではない。
- モーターの主要整備後は別の状態として集計。整備前の機力と現在の展示を同一視しない。
- 現在展示を紐付けるには公式のrace_id・艇番・モーター番号を一致させること。オリジナル展示3数値が欠けても勝手に補完しない。
- 予想時に公表・取得されていない情報は使用できない。速報用のデータ取得契約が未確認なら未取得として扱う。
- 予測モデルの確率・利益の改善は時系列の未使用レースで検証してから採用。

3. 日次ジョブを本番のデフォルトブランチで実際に2日連続で検証し、前日の値を今日の値として誤表示しない（**未完**）。
4. モーター抜き基準モデルと独立した機力の予測検証を行い、的中率・LogLoss/Brier・回収率を比較する（**未完**）。
