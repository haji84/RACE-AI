上記3モデルは勝率98%の保証ではない。全場で使える**共通コード**の実装であり、全場のリアルタイム実特徴量の取り込み実績はまだない。展示・天候は各レースの締切前に実際に観測された値に限る。未観測/公開前の値は推測しない。

## 予想処理

- `race_ai/boat_feature_adapter.py` は既存PR #64の正規化出走表に対し、利用承認済の過去レース着順・スタート・モーター・展示・風/波を追加して、厳格な `RACE_AI_BOAT_MULTI_FEATURE_SNAPSHOT_V1` を作る。**通信なし**。
- 出走者ID/艇番・モーターとデータ源の結合、出典参照、公開/取得時刻、予想時点、公式投票締切を検証。オッズ、人気、配当、当該レースの結果を含むフィールドは拒否。前日以前の履歴が最低5レース必要で、ない場合は`MISSING_FEATURES`とし予想自動生成を行わない。履歴補完・なりすましの恣意的数値は禁止。
- `race_ai/boat_multi_feature_models.py` は上記スナップショットを受け取り、各モデルで120件の3連単確率に正規化し上位8点を出力。特徴入力・モデル・全候補・Top8のSHA-256付き研究用出力を生成。
- **重要：モデル出力時点では未凍結。** 結果予想の「締切前完成」は、正規保存先の書込完了と独立受領・読戻し・正式投票締切の照合に成功した場合のみ認定。保存前にレース確定結果が見えたなら当該レースの事前予想には昇格させない。
- `race_ai/verified_event_projection.py` は正式予想`forecast`と対照用`comparison_forecasts`を**別々の署名/時刻/入力ハッシュで**検証。比較候補が不的中でも正式予想の買い目を後変更しない。
- `web/forecast-audit-model.js` は主モデルのHit@8_allと、比較モデルそれぞれの各レースの結果/独立受領を分離。比較モデルの的中率も競技内の評価可能な全対象レースを分母にし、予想を出さなかったレースを勝手に除外しない。
- `web/forecast-audit.js` のレースカードで同一レースの本命最大8点・比較モデル各8点・確定3連単を見比べ、モデル別・期間別表で評価可能。新しい合成表示例は`web/data/example-synthetic-forecast-audit.json`。全デモ買い目・結果は架空、実績に加算しない。

### 本番への切替条件

1. 適法な取得/保存/学習/派生表示が独立確認されたソースから各レースの事前実特徴スナップショットを受ける（用途不明なら該当ソースを無効にする）。
2. レース締切より前に**本番の採択モデルIDと8点を固定**し、保存先の実receipt/hash/読戻しを検証する。対照モデルも同じas_ofで別に固定し、未来の未使用レースで両者を比較。
3. 主催者結果ソースの結果確定/訂正と払戻の別イベントを検証し、変更前の結果/予想を保持したまま再照合してUIへ供給。
4. 1レースのE2E検証を横展開して全場・全レースの欠落検知を通す。未予想・見送り・期限超過は分母から外さない。元の艇番研究用予想は上書きしない。
5. 本人のiPhone Safariで競技タブ、予想モデル比較、結果訂正、購入有無、日時/証拠リンクが正しく動くことを確認する。
6. 98%は結果未使用の未来の実データで長期的に観測されて初めて達成と扱う。重みを後から改変して過去的中率を上げない。
