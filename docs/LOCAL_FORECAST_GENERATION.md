# ボタン不要の自動予想と保存原本の表示

既存PR71の個人用ローカル実行。既存の巡回ポリシーを同じアプリの起動中に使い、実入力取得→既存nativeモデル→私有SQLite保存を自動で実行する。ブラウザは保存された原本を自動表示する。予想生成ボタンの操作は不要。新しいcron/定期タスク/workflow、モデル系統、外部サービス、公開先、実投票は追加しない。

## 起動

LinuxまたはWindowsのWSL2、Python3.11以上、libarchiveまたは既存lhafileランタイムが必要。私有保存はLinuxの権限・no-follow・`/proc/self/fd`を使うため、Windowsの通常のPythonでは動かない。PR64/PR72の固定参照コードも必要で、配布用ZIPには実ファイルとして同梱する。

```bash
python scripts/start_local_forecast.py --check
python scripts/start_local_forecast.py
```

通常起動で待受を開始すると、許容される巡回が残っている場合に自動開始/再開する。ブラウザを開くことやボタンを押すことは、巡回開始の条件ではない。`--check`は保存先と依存の確認だけで、自動巡回・取得・推論を開始しない。

そのサーバーを起動したPCの`http://127.0.0.1:8765/`を開くと、最新の保存原本がボタン不要で表示される。競技・朝版/展示後の選択は表示する原本を切り替える操作で、取得や推論を命令しない。終わる時はCtrl+C。クラウド環境内の127.0.0.1は手元PCのアドレスではない。

既定の保存先はLinuxホーム内の`.local/share/race-ai-owner`。`--private-dir /absolute/private/path`と`--port`を指定できるが、外部向けbindのオプションはない。保存先はGit外、所有者専用0700、ファイル0600。配布物の`private-seed`は初回にだけ検証・移入し、既存原本を上書きしない。既存ディレクトリが不完全なら黙って置き換えず停止する。

静的な`web/index.html`は従来のJSON読込を維持し、生成サーバーを探す通信を行わない。静的HTMLを開いただけではPython推論は動かない。

## 巡回の範囲と停止

- P0は初回の正常完了後に再生成せず、保存済み原本を再利用する。その後は締切前の直前対象に絞ってP1を確認する。公式展示が未公開なら未予想のまま保持する。
- 間隔180秒、最大24巡/65分、日付境界停止を維持する。2026-11-05の追加指示で、固定GET回数上限は撤廃した。これらのうち先に達した条件で止まる。無期限/24時間稼働や、全日全レースP1を保証する常駐運転ではない。
- 開始時刻、次回時刻、巡回数、P0完了、取得回数、停止理由を私有領域に保存する。同じ日の再起動で上限や65分の起点をリセットしない。停止済み・時刻逆行・状態破損・中断巡回は、その条件を無視して自動再開しない。
- 同じ保存先はプロセスロックでwriterを1件に制限する。別経路の既存workflowが実行中と分かった場合も重複収集を避け、新しいローカル巡回を起動しない。
- サーバー終了時はworkerを停止する。画面を閉じるだけでは、起動中のサーバー側巡回は停止しない。PC/クラウド環境の停止後も実行し続けるサービスは追加していない。
- 4xx/redirect/真正性不一致で停止する。一時的な取得失敗も自動の即時再試行はせず、残る巡回枠と次回時刻を守る。

自動管理中は手動生成POSTを拒否する。上限で停止した後にボタンから同じ制限を迂回することもできない。

## 保存・出典・画面の契約

- 時刻・入力元URL・許諾スコープ・保存先はサーバー側が決める。自動管理中のブラウザはstatusと選択した競技/時点のlatestをGETで読むだけで、生成POST・取得・推論を行わない。Host/Origin/nonce境界を維持し、私有ファイルをstatic assetとして配信しない。
- 今回の明示的な個人予想/私有保存指示を、取得した正確な当日URL/referenceとanalysis/private_storage/private_derivedへ限定して適用する。クライアントのtrueや署名鍵未設定を利用して認可を迂回/捏造しない。商用再配布の権利は認定しない。
- 元LZH/HTMLとmetadataを私有保存してから解析。公開時刻が不明ならnull。未取得の特徴・締切・出走者・校正済み確率を補完しない。
- 既存`PrivateDispatchJournal`が先に原本を読み、新規が必要なモデルだけ実行する。保存済みのモデル/版/Top8/SHAを再生成・上書きしない。
- 推論後も実時計と210秒の保存余裕を再検査し、超過時はトランザクションを戻す。commit後の実時計も別のローカル記録に保持する。遅延/逆行/保存時刻不明の原本は再試行でも採用せず、元原本を削除/再生成しない。
- ローカル保存時刻は独立外部freezeではない。独立受領/公式成績/全モデル稼働/精度改善/本番採用のフラグはfalseを維持する。
- 表示は既存の厳格なprivate view parserを通す。statusで確認したサーバー開催日・選択競技/時点とlatestの対応も検査し、クライアント時計で開催日を上書きしない。ブラウザは180秒ごとに状態を確認し、revisionが変わった保存原本だけを読む。
- 自動更新で購入候補の金額・確定状態・選択原本SHA・タブ/絞込を消さない。金額入力中は表示更新を待ち、入力終了後に再確認する。候補が属するレースや日付が変わる場合は表示を保留し、候補整理後に同じrevisionから復帰できる。
- 手動で読み込んだJSONや合成表示は自動更新で上書きしない。「自動予想を表示」は表示を戻す操作で、生成の開始ボタンではない。未公開P1や不正な応答でも、現在のP0原本を消さない。
- 実行中/次回待機/停止/停止理由を表示する。停止済みや状態不明を稼働中と表示せず、ブラウザ復帰時も読取更新を再開する。

## 取得回数上限の撤廃（2026-11-05追加指示）

自動予想経路のprovider・反復session・localservice/controller・P1pilotから固定GET回数停止を外し、上限metadataはPython `None`/JSON `null` とする。カウンターは負数/bool等を拒否し、回数減少・原本上書き・保存済み停止の自動解除はしない。画面は明示されたnullだけを「取得回数上限なし」と表示し、取得数も併記する。旧metadata240と既存原本を読戻せる。旧上限による停止済みprofileを、記録削除や新しい保存先で迂回して再開しない。

固定されたHEADで動く既存GitHub runへ、ローカルの修正は途中反映されない。今回の変更は未pushで、稼働中処理の再起動・追加run・環境再公開はしない。65分/24巡の上限はGET回数上限とは別に残る。過去の独立したone-shot診断の6GET等の制約は今回の自動予想経路の変更範囲に含めない。
