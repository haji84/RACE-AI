# WINTICKET 開始前〜終了後の全レース映像録画: 受入ゲート

対象: Matsuyama / RACE-AI / 既存 Draft PR #102。2026-11-08 1Rは既に終了。
過去の 92.208 秒「着順映像」はダイジェストで、全4周の原本ではない。

## 開発した独立工程

1. `race_ai/keirin_video_lap_gate.py`: 地元JST開催日、レース番号、公式由来の発走日時、同一会場の録画URL、開始90秒以上前・発走後5分以上の録画窓を確認。時間誤認・未設定の録画権利情報・異なる出走レースで fail-closed。
2. `scripts/keirin_winticket_prestart_recorder.py`: 指定時間より前にGoogle Chromeの通常ブラウザを起動、WINTICKET松山ライブを再生、録画窓が終わるまでブラウザ画面のWebM画録。プレーヤーの時間・一時停止・読み込み・映像寸法と実経過を計測。固定録画時間がゴールを含む保証はない。
3. FFprobeとOpenCVでWebMを読み、実際に復号可能な動画から数秒ごとの縮小フレームハッシュ、輝度、映像変化量を算出。映像が停止・暗転・切断した場合、健康判定に通さない。画像と動画はGitHub公開ログ・公開ブランチへアップロードしない。
4. 別個の映像証拠ゲートは `race_start/lap4/lap3/lap2/lap1/finish` を時系列で要求。独立に検証された視覚認識器と、実録画のSHA・実フレームハッシュへの一致がなければ絶対に「4周確認済み」にしない。
5. 実録画権利と保存条件が確認された運用に限り、録画成功分をオーナー管理の公開鍵でAES-256-GCM暗号化＋RSA-OAEP鍵封入してGitHub Actions短期暗号成果物へ保存する。利用可否の法的確認と配信元への負荷管理は別工程であり、環境変数だけで許諾されたと法的にみなさない。

## GitHub Actions

- `.github/workflows/keirin-winticket-prestart-gate.yml`: 合成キャンバス動画の再生・自動画録・メタデータ整合性・欠落時fail-closedのみ。**実レースの4周を成功扱いしない。**
- `.github/workflows/keirin-winticket-authorized-single-race.yml`: 事前に特定した1レースの時刻・許諾証拠・出典を明示する手動dispatchのみ。現時点でPRはDraft、本番無人録画や毎日の自動日程取得は有効化していない。
- 使用者が録画権限を持つ場合でも、秘密情報 `RACE_AI_VIDEO_RECORDING_PERMISSION` と個別の鍵が存在しないと失敗する。public RSA鍵のデモ用鍵で本番運用しない。
- GitHub-hosted runnerの起動が遅れると録画冒頭が欠落するので、事前待機を含む起動条件を設け、開始遅れは失敗扱い。GitHubのcronは秒単位の開始精度を保証しない。

## 実際の受入条件

A. 実ソースの視聴・録画利用条件を確認し、許可された経路のみ使用。
B. 実際の松山4周レースについて、開始前からゴール後までの連続映像が録画されている。
C. 実フレームから4周カウント・発走・ゴールを車番と時刻付きで独立に認識できる。録画時間だけでは合格不可。
D. 実フレームのSHAを基に、映像上の証拠とレースID・公式結果の対応を確認する。
E. 走行映像の分析を締切前予想へ後付けして書き換えず、独立の事後PDCAとして評価する。

**現時点ではA/B/C/Dをすべて確認できていない。実レース完成とは宣言しない。**
