## 2. 特徴量レジストリ

正本実装：`race_ai/comprehensive_four_sport_models.py` の `COMMON_REQUIRED`, `SPORT_REQUIRED`, `SPORT_OPTIONAL`, `ENV_COMMON`, `ENV_SPORT`。

| 競技 | 個体・能力・競技動作・組み合わせで記録できるもの |
|---|---|
| **共通** | 個人/馬ID、能力、直近フォーム、スタート信頼度、終盤の伸び、会場適性、持久力、戦術対応、着順安定性、出走番号/枠、先行・中団・追い込みの脚質/戦法 |
| **ボート** | 全国/当地成績、級別、選手別直近3/10走、各コース実績、平均ST・F/L関連のリスクコントロール、モーター2連対率/交換/整備履歴、ボート機材、展示タイム・展示ST、進入コース、旋回・伸び、休み明け、干満/風波への対応 |
| **競輪** | 競走得点、直近着順、ラインの組み方/番手/3番手の関係、逃/捲/差、S/H/B、バック/ホーム回数、ラスト周回の脚、位置取り・バンク角度、前後関係、直線長さ、風への対応、機材、日程疲労 |
| **オート** | 選手の戦歴、ハンデ/発走位置、スタート反応、試走タイム/順、タイヤ・エンジン整備/交換、車両特性、乾湿走路適性、コーナー性能、路面温度、ハンデによる渋滞・抜きやすさ |
| **競馬（中央・地方）** | 馬齢/クラス/騎手/厩舎、近3/5走、時計/ラップ、末脚・上がり3F、先行ペース/脚質、距離/芝ダート/コース回り適性、枠・頭数・ペースとの相互作用、斤量・馬体重変化、調教、休養間隔、馬場含水・クッション値、血統適性、パドック所見、展開時の進路取り |

気象・環境：気温・湿度・降雨・風速・路面湿潤度を全競技共通で管理。追加でボートは波高/潮流/横風/潮位活動、競輪はバンク/風曝露/路面/ライン複雑度、オートは走路温度/濡れ具合/グリップ/発走グリッド、競馬は馬場湿潤/クッション/内外柵/予想ペースを管理する。

**特徴量名が列挙されていることと、値を取得できたことは別。** 入力は正規化して0～1（大きい値が適性・能力上優位）または明示した物理単位へ変換する。特にハンデ秒・斤量変化・リスク・時計は生の大きさを単純に優劣へ加点せず、変換手続きと学習履歴を検証する。欠損特徴を架空の平均で埋めない。

### 必須と直前値のタイミング

全レース予想を前日から開始できるよう、**当日展示タイムと試走値はオプション入力**とする。実際の公開前には使用しない。

- P0 **前日～早朝**：合法な番組表/選手・馬ID/過去の実績/会場特徴/事前気象予測などの確保。一定の必須事前情報で早期モデルを実行し、締切までの時間と取得状況を残す。
- P1 **直前**：展示・試走・確定枠/欠場・当日気象/馬場が公開済みで取得可能なレースは再評価する。ただし新しい特徴の利用時刻が実際の公式投票締切より前でなければ一切使用しない。
- **P0/P1の予想両方を別版・別ハッシュで保存**。正式成績の採択モデル・どの版を評価するかは締切前のルールで事前固定し、結果後の都合のよい選択は禁止。表示画面には各版の予想と別モデルを並列表示。

## 3. 真正性・リーク防止のデータ契約

- 参加者の各特徴は`value / published_at / captured_at / source_ref / source_rights_ref / sample_n / transform_id`を必須にする。利用許諾検証コールバックがなければ`OPERATOR_SUPPLIED_RESEARCH`スコープも拒否。
- `race.as_of < sales_cutoff_at`が必要。公開時刻・取得時刻が予想基準以降の情報は拒否。失格・実着順・結果・人気・オッズ・払戻・市場予想の投入は禁止。
- `ENV_COMMON + ENV_SPORT`の必須環境値が無い場合、そのモデルは入力不成立。許された気象**予報**と実測は、発表時刻・出典・不確実性を分けて扱う。晴/良を欠測の埋め草にしない。
- 3連単全組み合わせを、6艇120/7車210/9車504/18頭4896など実際の出走数に応じて評価し、最大8点を順位付きで選ぶ。車券のライン内外・馬の脚質/枠/展開相互作用が単独順位と一致しない場合も保持する。
- オッズは予想モデルとその学習・モデル選択に入れない。予想確定後の採算評価モジュールだけで使用可。
- **研究用出力は`official_prediction=false`, `NO_BET`, 外部証拠`null`。** モデル推論のSHA-256は不変性の検査に役立つが、他者に対する実保存時刻の立証にはならない。

## 4. 学習とPDCA

正本：`race_ai/four_sport_learning.py`。

- 各競技の学習履歴データは「締切前の独立スナップショット」と「確定後の独立した公式結果ラベル」の2要素で保存する。例数・母集団と利用許諾が不足したら**未学習**と表示する。
- 日付境界`train_end_at < validation_end_at < test_end_at`を厳守。学習は**TRAINのみ**に実行し、検証結果や未知の未来テストの着順を重みに使わない。モデル採択・チューニングに使わなかった将来データの成績のみを最終証拠とする。
- 固定総合型・展開型・学習型を同一未来レース集合で**締切前に各々保存**してA/B/Cで比較。各モデルの予想漏れ・見送り・結果不確定を分類し、3連単発売・評価可能な全対象母数を共通で使用。
- 集計：`Hit@8_all`, 1着/2着/3着の誤差、公式的中単価、仮想回収率、確率校正、Brier/log loss、競技別・場別・時刻帯別・天候別・脚質/展開別、モデル間の95%区間など。仮想購入は実購入と混ぜない。
- 失敗後に結果を使って旧予想を作り直したなら別モデルの**新しい未来レースでのみ**評価。過去への後付け的中は禁止。
