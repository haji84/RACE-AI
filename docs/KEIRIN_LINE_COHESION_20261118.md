## 追加した研究用の実装

### 1. 選手登録IDと役割別に過去の共走経験を読む

race_ai/keirin_line_cohesion.py。

過去の1レースで同じラインを組んだ実例を、次の独立した情報として要求する：

- race_id、イベント終了時刻、ソース結果の公開時刻、ラベル利用可能時刻
- leader_athlete_id、follower_athlete_id（車番ではなく**毎レースを跨いで同じ人と分かる登録ID**）
- SECOND_WHEEL / THIRD_WHEEL、CHALLENGE/A1_A2/S/GIRLS等、予選/準決勝/決勝
- KAMASHI / MAKURI / TSUPPARI / NIGE / OTHER に対する HELD（追走維持）/GAPPED（離れ）/SWITCHED（切替）/UNKNOWN
- 実映像・レビュー原本のSHAと、レビュー結果全体のlabel SHA
- 独立した確認者/既存信頼済み private source admission からの検証関数（無い場合は拒否）

**共走したレース数と追走成否の分母は別**。UNKNOWNのレースは共走履歴には加えるが、追走成功/失敗の学習分母にはしない。0件の履歴は「初めて組んだ証明」ではなく「確認済みサンプルなし」。

### 2. 履歴が充分にあるペアだけ、6局面の展開質量を研究用に補正

- 同じ級班・段階・役割・先頭戦術の過去グループ率（3結果の分母）を元に、同一ペアの追走率を事前設定の平滑化で推定。現状の研究設定例は、基礎グループで最小6ラベル、同一ペアで最小2ラベル、各結果の平滑化係数1、ペア縮約係数4、相対補正倍率上限3。**どれも研究用の仮置きハイパーパラメータで、実データで校正した成績でも絶対的な正解値でもない**。設定と設定時刻はSHAで固定し、結果を見た後に変更しない。
- 3連単の確率を直接作るのではなく、元の段階別シナリオ質量に「同一ペアの追走結果の相対比（ペア推定/同級班・戦術のグループ推定）」を掛けて再正規化する。**0件のペアは相対比1で、機械的なマイナス補正なし**。基礎グループも不足なら補正HOLD。
- 1組に複数の番手イベントが出ても同一ペアを何回も独立した標本とみなさない。最後の明示的な追走/離れ/切替結果を1度だけ評価。複数ペアの証拠は単純に掛け合わせず、幾何平均で強すぎる確信を抑える。
- BELL→FINAL_HOME→FINAL_BACK→FOURTH_CORNER→GOALの実際に予想した展開を再計算し、段階のみの第1候補と段階＋連係経験の第1候補を出力。第1候補変更・相対質量の差は**架空事例の動作確認**であって的中改善ではない。
- 推論は親入力as_ofより後、公式締切の少なくとも65秒前までに計算し、旧予想と新予想を別々に保全。結果やそのレースの事後動画のラベルを同レースに逆流させない。独立readerで原本SHA/計算時計を後から再確認することが本番ゲート。

### 3. 三つの研究方式で同じ未来実レースを採点

race_ai/keirin_line_three_arm_audit.py。

- A: 既存PR71の正式4モデルのうち保存済みの親モデル原本。
- B: 開催クラス・勝ち上がり条件を考慮した6局面研究モデル（段階のみ）。
- C: Bに先頭・番手・3番手の過去の実連係／追走を加えた研究モデル（段階＋連係）。

旧・B・Cの親入力SHA、同じ締切、事前保存receipt、条件付き数値のSHA、独立レビューラベルSHA、結果原本と観測時刻を同じ実レースIDで検証。認証した公式結果が無ければHOLD。結果が揃えば、Hit@1、Hit@全候補、各点100円の仮想回収率を同一レースで比較。事前登録した未来レースの母数を全部維持し、返還・中止・結果未取得を不的中にしない。

**重要：第1候補の順位が改善しても、全候補に同じ買い目が含まれていればHit@全点は変わらない。** 合成テストでこの区別も確認対象とした。

## 本番完成へ残るゲート

1. 過去映像を既存の非公開保存・復号経路で取得し、実際の車番/先頭/番手/3番手/仕掛け/追走/離れを**時刻と正本SHA付き**で認証する。検証できたものだけ本ラベルスキーマへ変換。ビデオの色一致から勝手にHELD/GAPPEDを作らない。
2. 観測時点・過去履歴・今回選手ID・予定ラインの実時点資料を確認し、出走番号・本人コメント・クラス・開催の進出番組コードへ結合する。連係数が多いだけで高確度と判断せず、別の相手・バンク・天候の影響はモデルの変数として保留。
3. 過去学習と未知の将来テストレースを完全に分離。戦術の条件付き数値・平滑化係数・レース集合を事前凍結してから、旧PR71とB/Cを本番締切前に同時計算、AES保存・別runner SHA検証する。
4. 未来1実レースを公式結果・払い戻しと結合し、同じ前登録レース母数でA/B/CのHit@1/Hit@全候補/仮想ROI、保留率を計算。次に1開催・複数開催へ拡張。偶然の1回的中でモデル改善採用しない。
5. 松山7Rの別軸5工程（実結果取得→照合→AES保存→別runner SHA→HTML実画面）は同じ証拠を必要とする。PR #308のmain統合だけでは合格ではない。完成ゲートとは分離して追跡。
