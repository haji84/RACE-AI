対象：既存Draft PR #101（正当な取得権限のある出走情報の前向き入力）とPR #103（研究用8点と可変0～12点、全候補研究順位の締切前保存）。PR #71の元モデル、元SQLite、結果履歴を後付け改変しない。

## 残っている2個の実データ依存

1. **取得元**: 既存の `race_ai/keirin_licensed_api_ingest.py` にV2の明示的許諾済みJSONフィードを追加した。同一のHTTPS 1回GETで出走情報（`deliveries`）と全3連単オッズ（`odds_snapshots`）を同時受信できる。7車は210通り、9車は504通りで、欠落・重複・不正・将来・古すぎる値・締切直前・権限不一致は拒否。本人保存済みCSVを通す既存 `race_ai/keirin_owner_odds_csv.py` も維持。いずれも**新規の無許可クロールや画面の内部API解析は実装していない**。
2. **本番用データ提供者との契約・認証**: 現時点でRACE-AIが利用できる外部提供元の有効な実契約、発行されたAPIエンドポイント、全210/504券の一次実測値は未検証。架空の許諾証や自己作成した `rights_ref` だけでは供給開始にならない。WINTICKETの利用規約（第15条）やnetkeirinの私的・営業利用制限から、閲覧できるサイトを無条件の自動収集元にはしない。

## 本番暗号保存の実装方針

- AES-256-GCMは既存 `scripts/keirin_github_checkpoint.mjs` をそのまま使用。GitHub Actions信頼済みmainで2026-11-09 02:08 JSTに `RACE_AI_STATE_KEY` が既存コードの形式検査へ合格したことを確認。ただし実データの復号、鍵の読み出し、利用契約の証明ではない。
- 新コード `scripts/keirin_github_production_bundle.py`: **既に存在する**所有者非公開SQLiteから、同一未来レースの2方式不変原本、入力パケットSHA、全210/504券オッズ、各時刻を再計算し、現行の許諾資料SHAと用途別マシン取得権限を確認。元DBや結果を変更せず、一時作業ディスク上のSQLite整合バックアップを既存AES-GCMで密封。元の保存時刻を後付け生成しない。
- 新コード `scripts/keirin_github_production_archive.py`: 合成履歴 `state/keirin/v1/` に触らず、**同じ既存GitHub stateブランチ** `state/keirin-encrypted-history` の `state/keirin/production/v1/` を独立世代にする。本番鍵で暗号文を認証復号してSQLiteの整合性と固定原本を確認し、暗号文・scope・限定的証明だけをGitコミット、fast-forwardでpushし、別のGit読戻しを実行。生のCSV、SQLite、個別予想、公開合成鍵、本人の鍵はpushしない。
- 本番Git pushには、保護mainで成功した専用producerの`workflow_run`イベント（出元リポジトリ・ブランチ・コミットSHA・run ID・専用名）、事前のSHA／所有者の許諾書類、現時刻が締切65秒以上前、`RACE_AI_PUBLIC_CIPHERTEXT_APPROVED=OWNER_APPROVED_PUBLIC_AES_GCM_CIPHERTEXT_V1`をすべて要求する。**この承認値と実データプロバイダは未設定なので実際の本番pushは動いていない**。
- プログラム上の「利用目的承認」は契約の法的真正性を独立に保証しない。公開GitHubへ暗号文を保存する場合は、暗号文・サイズ・コミット時刻は外部に見えることへの明示的了解が別途必要。
- 確定結果・返還・訂正・原本との照合は従来のappend-only SQLite結果改訂の処理を利用。研究原本を正式な確率校正や収益証明と混同しない。

## GitHub Actionsと未完成条件

既存PR #103の回帰CIで、架空2030年7車・210組を使用して新コードを試験する。使う鍵はテスト時に生成した一時的なランダムキーで、既存本番秘密鍵をPRジョブへ渡さない。PRジョブから本番pushできないことと、既存合成履歴が上書きされないことを確認する。

本番稼働に必要な残り：
1. 本当に利用可能なライセンスのある出走表・全オッズの自動供給。
2. PC不要の信頼済みmain producerで、過去の本番暗号状態を先に復元し、同じジョブ内で原本作成→暗号化artifact handoffを完了する運転経路。今のowner agentは一時runnerを永続DBとは扱わず、無条件開始は禁止。
3. 公開暗号文に関する明示的承認設定、初回世代と暗号保存先の独立復元。
4. 現実の未来1レースの公式締切前の外部時刻証明、公式確定結果、モデルA/Bの前向き収支検証。

**結論：コードと合成CIに合格したとしても、未確認の外部データや本番writerの自動稼働を作り出せない。現実の本番予想原本が保存されたとは報告しない。** 既存PR・main・state内の過去原本は破壊しない。
