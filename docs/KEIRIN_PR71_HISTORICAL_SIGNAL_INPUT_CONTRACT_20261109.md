# 競輪 PR #71既存モデル向け、過去実績3指標入力契約 v1

ステータス: **研究用入力候補のみ**。PR71の既存4モデル、既存係数、確率校正、main、本番データを変更しない。
固定版: \`keirin-prior-signals-research-v1-fixed-20261109\`
実装: \`race_ai/keirin_historical_prior_signal_rules.py\`
境界: \`race_ai/keirin_allowed_delivery.py\` の既存 \`RIDER_MAP\` と \`audit_pre_race\`、\`PR71\` プロジェクトの出典/権限監査は引き続き必須。
このv1はモデル入力の正本ではない。成果物の値はすべて \`approved_for_pr71_input=false\`。

## 1. 当時存在した情報だけを使うための要件

- 対象レースの入力スナップショット時刻 \`as_of\` は締切より前。過去レースの開始、終了、ライン発表時刻、確定結果の公表時刻、履歴資料のSHA、出典URLが保存されていること。
- 過去レースの **結果公表時刻 <= 対象レースの \`as_of\`**。日付だけでなくタイムゾーンを保持する。結果が対象レース後に公表された行は計算全体を拒否。対象レースそのものの着順・映像・オッズ・払戻は一切入力しない。
- 過去365日以内のレースのみ。級班/クラス、レース区分、距離を一致させた同一選手を比較。コース変更や距離・相手級班の違いによる見かけ上の勝率差を比較対象に混ぜない。
- HTTPS出典URLと元ソースのSHA-256を保持。公表時刻・利用許可・リプレイ原本の真正性は**書類の自己申告だけでは独立証明にならない**。外部確認ができない限り候補値としてだけ残す。
- 結果から係数・閾値・日数・候補点数を逆算しない。v1の後で変更するなら新バージョンとして未使用期間へ。

## 2. 「終盤」の指標を2つに分離

**終盤の伸び（\`finishing_power\` 候補）**

- KEIRIN.JP公式説明では「上がりタイム」は最終バックからゴールまでの**半周**。瞬間加速度そのものではない。
- ある過去レースで、同一競走の有効な上がりタイムが5名以上ある場合に、速い順の同レース内分位を \`1 - (順位インデックス)/(有効人数 - 1)\` で計算。同タイムなら平均順位を使う。
- 対象選手の過去3走以上の比較可能な分位を平均した値を候補にする。0〜1だが、実的中確率ではない。
- 上がりタイムの他選手比較は、過去レースの状況に依存する。選手本人の加速度やスタミナの実測値ではない。

**加速度（\`sprint_acceleration\` 候補）**

- 「終盤の2つの連続した同距離区間」の**計測済み**距離 \`d1,d2\` と秒数 \`t1,t2\` があるレースのみ。
- \`v1=d1/t1\`, \`v2=d2/t2\`; 区間代表速度の変化率の近似値 \`a=(v2-v1)/((t1+t2)/2)\`（m/s²）を計算。真の瞬間加速度ではない。
- 同じレースで5人以上の有効2区間データがあれば、\`a\` の大きい順の分位を計算。対象選手で3レース以上なければ \`None\`。
- **上がりタイムだけ、B回数だけ、ゴール映像だけでは加速度を埋めない。** 実計測区間距離の根拠が無い動画から秒数を捏造しない。

既存 \`RIDER_MAP\` は \`finishing_power\` と \`sprint_acceleration\` を同じ \`last_lap_acceleration\` に結び付けている。今回のv1ではそこへ値を書き込まない。代理上がりと実加速度を混ぜると同じ情報を二重に重み付けする可能性があるため、次段で**バージョン付きの入力マッピングを別途審査**する。

## 3. ライン連携（\`line_coordination\` 候補）

- 対象より前にライン発表と結果が公表された過去レースのうち、本人と**同ラインの別選手が最低1名**いた記録だけを母数にする。
- 同じ過去レースで「本人が3着以内、かつ同ラインの少なくとも1人が3着以内」を満たした件数を母数で割る。
- 比較可能な同ライン出走が過去5走未満なら \`None\`。並び不明は単騎/不成功と扱わず母数から除外する。
- この値は \`teammate_pair_history\` へ流用するための**連動入着の関連指標**。ブロック・牽制・位置取り等の連携行動を映像で実測したスコアではなく、因果的な連携力を証明しない。

## 4. 個人のバンク適性（\`bank_fit\` 候補）

- 同選手の「対象競輪場」過去5走以上と「それ以外の競輪場」過去5走以上を、同じクラス・区分・距離で比較する。
- \`p_home=(home_top3+1)/(home_n+2)\`; \`p_other=(other_top3+1)/(other_n+2)\`。v1は観測件数による極端な0/100%を避ける**一様Beta(1,1)の固定研究用平滑化**を使う（学習済みパラメータではない）。
- \`bank_fit_proxy = 0.5 + 0.5*(p_home - p_other)\`。0〜1の相対指標で、0.5付近は同程度の実績を意味するだけ。「適性50%」でも「勝率50%」でもない。
- **場の周長・直線・傾斜と選手個人の適性は別**。周長400m・直線58.6mの固定値だけで本人の\`bank_fit\`を埋めない。コース改修前後の違いも独立検証まで分ける。

## 5. モデルへ接続しない条件

- v1の入力は構造確認可能な過去レース資料を対象とした**純粋な研究用候補値**。提供元の利用権限、元ページの実際の公開時刻、レース結果改訂・返還、元データSHAの第三者証拠は、このコード単独では立証できない。
- 出走前ライン・着順・上がりタイムは過去レースのものだけ。結果が対象レースより後なら例外を投げる。欠測なら0や平均を入れない。
- PR #71へ流すには、別の許諾済みデータアダプターで既存347項目監査を通し、出典・有効時点・サンプル数・変換版・SHAを固定しなければならない。研究用候補を生の \`late_lap_and_agari_time\`, \`last_lap_acceleration\`, \`teammate_pair_history\`, \`venue_and_distance_compatibility\` と偽って投入しない。
- 実際の11月8日松山2R/7Rの保存資料には、終盤の分割計時・過去ライン別同時入着の元イベント一式・本人の同場/他場同クラス母数がそろっていない。**現段階でこれら3指標の実データ正式入力は0件**。
