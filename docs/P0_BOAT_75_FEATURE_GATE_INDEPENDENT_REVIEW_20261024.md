## 判定

**BLOCK: 現行「75数値を全件必須」は、全対象レースで締切前予想するという製品要件に対し構造的な障害。** 必須性が実験的に証明されていない17種類の数値項目まで、欠測1件で推論を禁止する。これは安全な入力検証としては正直だが、予想可能率を構造的に落とす。設計変更案は**別版の部分特徴量モデル**として検証すべき。現在の研究モデルをこっそり緩めない。

### まず数字の読み替えが重要

現在の `75` は「75種類の異なる特徴量」ではない。**20種類**（各選手11種類 × 6艇 = 66観測スロット＋レース環境9種類 × 1 = 9スロット）の合計。Bデータからは**3種類×6艇=18候補スロット**を構造変換できる。**未候補57スロットは、8種類×6艇＋9種類であり、固有項目としては17種類**。これらが予測に不要と実験で判明したわけではない。

## 独立コードレビューで確認した設計上の問題

1. **ハード停止が二重化**：`validate()`は全選手11/11と環境9/9を要求。推論関数`_utility()`, `_mix_weights()` も `f["..."]`、`env["..."]` を直接参照する。**単にrequiredをoptionalに書換えると例外や統計的な歪みが起きる**。必ず新しい独立モデル版と欠測アルゴリズムが必要。
2. **存在自体を保証できない潜在指標の必須化**：`stamina`、`tactical_adaptability`等は直接観測値ではない。勝率等を無理にコピーすると特徴量の二重カウントとなる。
3. **環境値の過剰な共通化**：水域条件に依存する潮汐・流況を全場共通で要求。特定場で「適用外」を認めるべき。
4. **メタデータ型が不自然**：`_observation()`は気象瞬時観測にも`sample_n >= 1`を強制。過去成績の`sample_n`と、気象値の`observation_kind / issued_at / valid_for / captured_at / uncertainty`を区別する設計変更案が必要。元の取得時刻を捏造しない。
5. **推定確率は未校正**：既存モデルは固定仮係数。必須緩和で算出できるようになっても、校正・Hit@8・回収率の改善を示さない。出力の確率のような値を根拠なく確率校正済みと表示しない。
6. **データ可用性と予測価値を混同**：Bが18候補しか出せない事実から、残り57スロットの「予測上不要」を導けない。歴史的観測のアブレーション＋未来A/Bで判定する。

## 提案する正式な実験設計（未採用、変更にはオーナー事前承認）

- **モデルA：現行FULL研究モデルを不変**。証拠が75項目揃うレースだけ影響を検査。未予想・見送りも全対象分母に残す。現行予想SHAの後書き禁止。
- **モデルB：新しい`BOAT-B-LITE-v1`（提案）**。予想時点に利用できたB由来の選手3指標、出走枠・レース識別など最小限の実証可能項目だけで始める。元値の公開時点と利用許諾が不明なら**研究用の候補に留める**。重要入力がまったくなければ`NO_FORECAST`。見送り件数と理由を保存。係数は未学習なら未学習と表示。
- **モデルC：`BOAT-ENRICHED-v1`（提案）**。前回までのK等から本当に確認できた履歴情報と、時点検証済み天候等だけ順次追加。必須値を結果を見て選別しない。直前の展示があれば別時点のP1として保存、P0のSHAは変更しない。
- **欠測処理案**：`MISSING / NOT_YET_PUBLISHED / NOT_APPLICABLE / RIGHTS_BLOCKED / SOURCE_UNAVAILABLE`を区別し、勝手なゼロ/平均/晴れ補完を禁止。モデルごとのスコア計算は観測された特徴のみ、重み正規化やmissing-indicatorの設計を**過去TRAINデータだけ**で決める。欠測があるモデルを既存FULLと同じID/バージョンで上書きしない。
- **比較**：同じ未来対象レース一覧を事前固定して最大8点・締切前外部レシートをモデル別に保存。主指標は欠測込み`Hit@8_all`、捕捉率、日別/場別成績、信頼区間。回収率は公式払戻と仮想券購入条件を分ける。信頼できる事前確率が保存されている場合のみ校正/Brier/Log Loss。
- **採択**：安全・時点・権限・費用ゲート維持。旧予想の再採点で新モデル有利と宣言しない。モデル採択ルール/最小レース数は未来評価の**前に**事前決定。98%は未達の挑戦目標であり、この変更は達成保証ではない。
