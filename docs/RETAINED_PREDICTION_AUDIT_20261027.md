# Auditing already saved predictions

An existing prediction archive must not be recast as a newly predeclared experiment. The retained-audit path preserves the original input, generation and readback claims and records a separate current import time. It executes no model and reads no provider. A changed prediction, invented generation time or later-added history is rejected rather than repaired.

This path is development evidence. Its policy was declared after the original forecasts; prior result exposure may already have occurred. It cannot establish an untouched final test, an authoritative cutoff, a provider publication time or a formal Hit@8_all rate. The ordinary experiment plan/seal remains a separate stricter interface.

The importer validates expected source-file byte hashes and their facts/bundle/seal/manifest/execution links, then preserves every race and model slot. Original missing predictions and null generation times remain missing. Aliases and unavailable inner-response hash preimages are explicitly described. An outer frozen-file digest is not relabeled as proof of an unavailable inner response.

The import and result journal uses create-only files and the same local physical-race exposure registry as the ordinary evaluator. A successful import already reserves potential exposure for the full cohort under the shared lock; there is no gap in which another audit can claim those identities as untouched final data. A separate, outcome-free request fixes each later observation's race, revision, source, local path and expected byte hash before the lazy reader opens a result file. Changing an experiment name does not make those canonical identities unseen. The registry remains a trusted local filesystem: changing roots, deleting records or lying about venue/source identity is outside its proof boundary. Boat identities preserve the existing `boatrace-jcd-XX` spelling and guard its known two-digit `XX` equivalent; arbitrary venue aliases are not authenticated.

Reports retain the full scheduled denominator, unknown/unscored observations, missing forecasts, per-model Hit@1/Hit@8 and separate prediction-only rates. A secondary timing-valid subset is descriptive and cannot replace the full cohort. Official observations with a changed cutoff, unavailable source or pending result stay unscored until a separately admitted revision resolves them. New result batches never regenerate predictions or amend old observations; interrupted operations do not authorize automatic rereading.

The retained adapter and its arithmetic are separate modules. They share the local exposure protocol with the ordinary journal, not a fabricated generic prediction seal. The existing prospective scorer remains unchanged. The retained CLI imports no prediction modules; source and result claims are validated structurally, not independently authenticated by a hash.

## Private command sequence

Use `python -m race_ai.retained_evaluation_cli` with the same trusted private registry root as `evaluation_cli`. There is no `--now` override. The original six-file request selects `facts`, `bundle`, `seal`, `manifest`, `proof` and `registry`; each entry has an exact local path and original file-byte SHA256. Result files and reports are not members of this request.

The policy names `RETAINED_PREDICTION_AUDIT`, the current declaration time, prior exposure, allowed source ID, authorization reference and settlement policy. `NORMAL_FINISH_ONLY` rejects refunds or nonstandard finishes for scoring. Broad cancellation/dead-heat handling requires a separately explicit policy; a revision number alone cannot enable it. Correction observations must bind their previous observation and file hash, provider revision reference, six registration identities, source and unchanged planned cutoff.

1. `import`: supply `--origin`, `--expected-origin-request-sha`, `--policy` and `--expected-policy-sha`. Retain the returned import hash.
2. `observe`: supply `--expected-import-sha`, `--label-request` and `--expected-request-sha`. The outcome-free request lists race ID, revision, source ID, path and file-byte hash for every selected observation.
3. `append`: supply a new label request, the next `--batch-number`, unchanged import hash and `--expected-report-sha` of the prior completed report.
4. `report`: recover the verified chain, optionally selecting an explicit `--through-batch` and checking `--expected-report-sha`. `--output` creates a new private file and refuses overwrite.

Every command also requires `--root` and `--audit`. Descriptor, policy and report hashes use compact, sorted UTF-8 JSON without a trailing newline; original source-file hashes include every byte. Stdout contains counts and hashes. Full reports stay in the private journal or the explicitly selected private output file. Interrupted imports/result batches remain stopped; a different audit name cannot establish non-exposure.
