## 2. 共通の実装契約
- `DailyRaceLedger`: sport, organizer, venue, meeting, event_date_jst, race_no, authoritative_sales_cutoff, status、発見/更新/延期/中止/未取得理由の全履歴。開催なしの証拠と取得失敗を分ける。
- `SourcePermissionLedger`: Providerごとの自動取得・閲覧・非公開保存・学習・派生結果公開・原文再配布・映像の用途別ALLOW/DENY/UNKNOWN/承認待ち、証拠URL/取得時刻/費用/クォータ/対象範囲。未知の用途では通信・保存・学習をしない。合法な独自解析と著作物・規約に反する再配信を混同しない。
- `PreRaceSnapshot`: 正規ID、出典、公開/利用可能/取得/加工/採用時点、as-of、入力hash、訂正revision、欠測・品質。未来の情報を混ぜない。締切を発走時刻で代用しない。
- `FeatureAdapter`: ボート(ST/進入/展示/1M/モーター/風波)、競輪(ライン/先行捲り差し/番手離れ・混在/S/H/B/バンク)、オート(試走/ハンデ/湿走路/スタート・車両)、競馬(主催/馬体/距離/馬場/ペース/近走/騎手/調教)。許諾・入手・時刻の条件を満たす情報だけ計算。
- `OddsFreePrediction`: 全有効3連単 `N*(N-1)*(N-2)` を検証付き列挙（例6艇120、7車210、9車504）、各着順依存・展開別候補を比較、上位**最大8点**と順位/根拠/スコア/校正状態を出力。未校正のスコアを実際の的中確率と表示しない。オッズ・人気・市場由来指標・第三者予想・未来結果は**学習/特徴選択/モデル選択/推論/上位8点選抜すべてから隔離**。市場データ入替え時も8点出力が完全一致する回帰テストを設ける。
- `PredictionFreeze`: race_id、snapshot_hash、model/schema/feature_allowlist hash、trained_until、as_of、generated_at、**actual persisted_at**、frozen_at、authoritative_cutoff、run_id、入力/予想hash、Top8順位と証拠ID。外部保存時刻も検証し、`persisted_at < cutoff`が確認できた予想のみ正式記録。締切後の追加/編集は禁止、許容範囲の出走変更は**新しい版**として別保存。STOP/欠測は偽の予想で埋めない。
- `OfficialSettlement`: 結果の確定/訂正、失格、同着、返還、非成立、欠場等を公式ルールに沿って別revisionで保存。予想は固定したまま派生スコアを再計算。
- `STANDARD_8`予想と`SHADOW`、凍結後の`ECONOMIC_EVAL`、旧16/24/32点の手動比較機能を分離。8点を超える券や市場情報を正式予想に混ぜない。自動投票・決済なし。

## 3. 自動PDCAと98%指標
- `Hit@8_all` = 事前凍結された上位最大8点で公式的中した件数 / 当日の全開催中、3連単が正式発売され、確定結果でその券種を評価できる全レース数。
- 未取得/未予想/見送り/締切超過を**母数に含める**。非発売・中止・不成立・未確定は全レース台帳に残して別計数する。サンプル数・集計期間・確率校正・信頼区間・coverage・`Hit@8_predicted`、競技別/場別/日付別、1点/3点/5点/8点の累積的中を併記。実購入と仮想等額購入の払戻回収率は分離。
- 外れは`FACT / HYPOTHESIS / UNKNOWN`で分類。推測を原因の事実にすり替えない。候補モデルを別バージョンとして学習期間・ハッシュ・仮説と紐付け、walk-forwardと未使用の未来レースでチャンピオンと同じ事前情報・締切条件で並走比較。改善を信頼できる精度で観測し、CI/レビュー/安全ゲートを満たすまで昇格しない。悪化なら旧モデルへ復帰。98%に届かない場合、未達と報告。
- 300件は初期の評価点であって、98%の再現性や4競技共通達成の統計的証明ではない。

## 4. Actions中心・ZBook不要の運用要件
- 既存PR #64のActions、認証済みOIDC→保護Preview→private Blobを優先再利用し、無断Cloudflare移行・Vercel Production変更・権限拡大はしない。ZBookは研究映像・重い学習・任意の開発端末。通常の全R discovery/収集/予測/結果/集計はZBook OFFでも完走できる構造にする。
- ワークフロー責務をCI、当日開催発見、許諾付き更新取得、締切前スナップショット/予測凍結、結果照合、日次PDCAに分ける。必要性のない多数のworkflow/PRを乱造せず既存Jobを再利用。
- 定期Actionsは正確な定刻起動が保証されない。**締切に余裕を持った事前実行**、締切安全マージン、実行遅延検出、次の周期での取りこぼし確認と`CUTOFF_MISSED`記録を実装。未取得や失敗を予想済みにしない。実際の遅延分布を測るまで「全レース締切保証」と宣言しない。
- Runnerは揮発環境。状態は権限限定された永続保存先へ版付き/追記で保存し、少なくとも別runから復元するE2E。定期ジョブを設置するだけで運用成功と扱わず、ZBook不使用の**複数回の観測済みrun**でレース発見→事前凍結→結果→復旧を実証。
- Runner権限最小化、trusted workflow/branch/environment、Secrets非出力、Publicリポジトリ公開前のコード/ログ/証拠検査、重複実行lease・冪等再試行、停止中POST/nonce非再投入。追加クラウド費用0円志向、枠/処理量/超過課金ゲート。Cloudflare Workers/D1/R2は検討候補であり、既存環境からの実移行には実費/互換/認証/復旧/切替の別承認が必要。
- Codexは実装/PR担当、Actionsはジョブ実行担当。**Actionsを作ること自体はCodexの自律継続を意味しない**。開発自律化は別の実行権限/スケジューラ・独立レビュー・承認境界のE2Eが必要。

**D. 競技別合法実データの拡張**: ソース権利/許諾/費用/時点と欠測を明示し、各競技ごとに開催発見・実1レース事前凍結→実結果の検証まで実施。未許諾はその用途のみBLOCKED。
**E. 精度改善エンジン/可視化**: 予測外れの分類→新モデル候補→未来A/B→採否/復帰を実実行、iPhone Safari UI・障害/精度/権利表示を実機で確認。
最優先順は実装障害に応じて見直すが、予想性能に直接関係しない装飾的UIや新しいPRを優先しない。
