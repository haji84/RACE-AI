# オートレースA/B予想・結果照合の自動制御（2026-11-03）

対象：Issue #67/#68、既存Draft PR #71。ボート用の`exhibition_autorun.tick`と`cutoff_job_queue.plan`、既存4競技の`four_sport_model_suite.run_suite`を再利用し、新規モデルの追加は行わない。PR #72の`autorace_official_trial_adapter`は別ブランチのため、このPRではコピーせず、正式統合後の入力アダプター候補とする。

## 今回の到達点

`race_ai/autorace_ab_pdca.py`に、権限確認済みデータを受け取る**オフラインの制御層**を追加。

* 全レースを締切の早い順に評価する。A（試走発表前）とB（同一レースの試走結果確認後）は別キーで取得、別の排他予約、別の予想SHAで扱う。
* Aは「試走がまだ公開されていない」という外部確認と、試走特徴量がない入力を要求する。試走公開後に『試走前予想』と称して遡及生成しない。
* Bは同一レースの試走表と出走者の対応関係が確認され、**全車の試走正規化特徴量**が時点付きで存在するときだけ実行する。単なる『試走T』の見出しや汎用の中止文言ではBを発行しない。
* 既存の4研究モデルのうち事前指定した1モデルから、全3連単候補の基本8点と追加4点を独立出力する。4点は手動検討用の比較枠で、従来の正式Hit@8 KPIに混ぜない。数値スコアは未校正のため、実測的中確率として表示しない。
* 既存の2分安全余裕、先に読戻し、CLAIM、POST、検証の順を遵守。POST不確実時は**再POST禁止**、次の巡回で解決済とみなさない。
* `audit_cycle`は正式な結果確認を行う外部検証アダプターを必須とし、的中1点/8点/最大12点をA/B別に照合。未予想は、公式結果が評価可能な場合に限り分母に残す。中止・払戻特殊・未確定を0的中として扱わない。訂正は新revisionとprevious SHAで追記し、元の予想を変更しない。
* PDCAの次候補は将来の未締切レースのみ。結果が1件出ただけで『精度向上』『重みを自動採用』を主張しない。

## 実データ接続に必要な外部アダプター

`tick(records, clock, readback, acquire, claim, submit, verify, authorize_feature)` の7つの関数は**インターフェース**であり、本番の実装/許諾を保証しない。`acquire(row, phase)`は指定されたデータ使用条件（自動取得、保存、解析・学習、派生表示）、事前の締切・試走公開状態、全車のID照合を別途検証する。`authorize_feature(ref, rights_ref, 'analysis')`は各時点付き特徴量の利用許可を承認済み文書から判断し、許可がない場合は常に拒否する。単に`source_rights_verified=true`というJSONを作るだけでは認証にならない。

保存アダプターは、非公開の永続ストアで `(race_id, phase, model_id)` を原子的に排他登録する。独立したサーバーの時刻とSHAを伴うレシートを読戻し、締切前を証明して初めて正式予想として計上できる。GitHub上の研究PRや自己申告時刻を正式な凍結証明として採用しない。第三者サービスの登録/課金/権限変更は本変更の範囲外。

`audit_cycle(records, clock, load_forecast, load_result, verify_forecast, verify_result, latest_audit, append_audit, read_audit)`の8つの関数も非公開保存と独立した公式結果検証を必要とする。モデル推論と結果読取りは異なるタイミング、異なる権限で行う。

## 完全自動への残りの関門と順序

1. **権利**：公式 https://autorace.jp/policy/ に従い、出走表・試走・結果・保存・解析・通知の用途、提供頻度、商業利用の有無について明示の権利確認。現状自動収集未承認。無断の繰返しHTTPを始めない。
2. **入力アダプター**：権限付き提供フィードの開催/全レース/出走者/予定締切/試走時刻/確定結果を正規化し、PR #72の同一レース判定を正式な統合経路経由で再利用する。出場変更と日をまたぐ開催も調べる。
3. **時刻・永続保存**：サーバー時刻の外部証明付きプライベート保存、結果revision追記、POST不確実時の解決手順、同時重複ジョブ排他と災害復旧を隔離検証。
4. **実トリガー**：GitHub Actionsのscheduleは最短5分で遅延・実行漏れがあり、試走後から締切までの全イベントへの対応を保証しない。提供元Webhookか許可された短間隔ジョブ、永続キュー、締切監視、アラートを費用と運用承認後に選ぶ。
5. **未来の実レースE2E**：1レースでA/Bそれぞれ締切前の独立レシート、公式結果、その後の訂正まで確認 → 同日全場→欠測率計測→前向きの比較評価。正式なHit@8 98%は未実証目標。

**運転判定**：`real_provider_polling_enabled=false`、`live_result_polling_enabled=false`。現時点ではプロバイダー接続・cron・本番配備・main統合・公開・自動購入をしていない。完成したのはA/B+PDCAの制御ロジックおよび合成検証工程であり、完全無人本番稼働ではない。


## 2026-11-03 追記：公式データの利用権限と非公開保存の現況

### 公式一次資料と窓口

- 公式利用規約 https://autorace.jp/policy/ ：一般財団法人オートレース振興協会の公式サイト。掲載記事・写真・映像等の無許可転載/複製等および私的範囲を超える商業利用や迷惑な大量アクセスを制限している。
- 出走表と試走タイムの表示 https://autorace.jp/race_info/Live/ 、過去結果検索 https://autorace.jp/race_info/SearchRace を確認した。**公開表示されることは自動取得・保管・学習・派生表示の契約上の権利を付与しない**。
- 個別に許可された正式フィード/API、契約料金、許容頻度、認証方法、保持期間は調査では確認できず、全用途のプログラム取得はRIGHTS_UNVERIFIEDで停止する。
- 公式問い合わせ https://autorace.jp/inquiry/ で、出走表・予定締切・全車試走・確定/訂正結果の継続的な機械可読提供と、個人利用/AI研究/保存/有償配信の許諾区分、Webhook/頻度/料金を照会する。

### 追加した安全なローカル接続と合成E2E

## 2026-11-03 ユーザー方針修正：個人用予想を許諾待ちで停止しない

本人の利用目的は、一般のファンと同様に公開されている出走表・近走・ハンデ・試走結果を確認し、**本人専用の予想A（試走前）/B（試走後）、結果照合、PDCAを行うこと**。商用の情報転載・第三者配信・自動投票は依頼していない。

公式 https://autorace.jp/policy/ を再確認した結果、私的利用を超えた商業利用と大量アクセスを含む不正アクセス等は制限されている。一方、個人が通常の方法でページを閲覧して予想すること自体に特別なデータ供給契約が必要だとは書かれていない。**「正式データAPI契約の取得が、個人の予想AI開発の必須前提」という以前の扱いは過剰**だったため、以下の二つの開発経路を明確に分離する。

- **個人の手元データからの予想：開発継続（新規許諾契約待ちにしない）**。本人が閲覧・記録したレースの実測値を、出典・観測時刻・レースIDとセットで非公開入力する。予想と結果原本は時点付きに分け、A/Bの入力混同・後書き・買い目再上書きを拒否する。自作のモデルと入力チェック・非公開保存・合成試験は先行実装してよい。本人の申告のみで外部時刻証明やモデルの実測的中率を捏造してはいけない。
- **主催者サイトからの無人定期取得：取得方法・負荷・規約適合性を別途確認**。公開情報だからといって大量クロール、転載、配信許可まで自動的に得られるわけではない。自動接続では、条件に合う公開配信・正規の提供手段、更新頻度、同時接続、レスポンスサイズ、再試行間隔を確認してから実行する。正規API契約が存在しないからといって、本人用の予想処理まで一律にBLOCKEDとしない。

優先順位を修正する：
1. 個人研究の**試走前A→試走後B→非公開保存→公式確定結果との照合**を、本人が通常の方法で得た入力によりまず1回、実データで検証する。公開予想・自動投票は行わない。
2. 既存のローカル保存の読戻し/再起動復旧・結果訂正・欠測の扱いを固める。外部時刻付きレシートがなければ正式な時刻証明済みHit@8とは区別する。
3. 自動データ取り込みの許容方法を個別評価し、負荷制御と欠測監視を通してから低遅延自動実行を組み込む。

**自分用の予想作成は進めるが、公式サイトの自動巡回の利用条件が確認できたと偽ることはしない。** 契約問い合わせ文は必要となった場合の補助資料であり、最初の完成マイルストーンではない。
