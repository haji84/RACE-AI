## 0. 製品の最上位完成条件（変更禁止）

1. 前日から4競技の全開催・全レースを発見し、投票締切時刻の早い順に、許可された締切前情報のみからオッズ非依存の全有効3連単を評価して最大8点を締切前に不変保存する。
2. 3連単が発売され、公式結果で評価可能な**全対象レース**（未予想・見送り・期限超過を含む）で、未来の未使用レースによる実測 `Hit@8_all` **98％以上を目指し、達成を実証して初めて最終精度条件達成**とする。到達可能性は未検証で、達成保証・合成実績の転用は禁止。
3. **オーナー本人が予想と結果・的中/不的中・取得失敗・モデルの品質を直感的に独立評価できること**をUI完成条件に加える。裏側の分析精度が高くても評価画面が使えなければ画面機能は未完成。
4. 自動投票・自動決済・未承認の課金・一般公開・権限拡大を行わない。

## 1. 画面の情報設計（モバイル優先）

### 1.1 共通レイアウト

- 画面名称：「予想と結果」。元の参考スクリーンショットは**UIの見せ方のみ**参照し、掲載日・的中・払戻・AI名称などの数字を実績に転用しない。
- 上部：RACE-AIロゴ／「今日の全レース」または選択日／最新確認時刻（JST）／取得状態。取得異常時は「更新停止・最終確認時刻」を明示。
- **横スクロール可能な競技タブ**：［全競技］［ボート］［競輪］［オート］［競馬］。一度のタップで切替え、選択中を色・下線・aria-selectedで明示。競馬内で中央／地方を追加切替可能。全競技を選んだ場合も競技ごとの成績を混ぜて表示しない。
- 期間切替：［今日］［今週］［累計］と日付選択。週は日本時間の月曜00:00から日曜23:59:59まで。日付境界・日跨ぎは開催日（JST）を優先し、確認時刻とは別。
- 集計カード：対象レース総数、事前保存済、結果確定・評価可能、**Hit@8（的中数/分母）**、未予想、データ鮮度。実購入がある場合のみ購入総額・払戻総額・差引収支。未検証は「未検証」、分母0は「－」でなく理由を表示。
- リスト：締切前予想・公式結果・的中/不的中が**同じレースカード**に入る。新しい開催／レースを検索して確認できる。
- iPhoneの375px幅・320px幅・390px幅で横はみ出しなし。予想8点はカード内で折返し／詳細展開。タップ対象は原則44×44 CSS px以上。固定タブで本文・広告と重ならない。

### 1.2 競技タブの振る舞い

- 切替後も選択した期間・状態・並び順を維持し、競技の切替だけで結果フィルタを消さない。
- タブには必要なら「確定/全レース」件数を併記。データがない場合もタブを消さず「未取得・未確認」を表示する。
- 他競技の予想と結果を同一レース扱いしない。固有キーは `sport / organizer / venue / meet_id / event_date_jst / race_no` とし、変更・延期・再編は版または明示リンクで追跡。
- UIの競技識別値は既存PRの `boat` / `keirin` / `autorace` / `horse` に揃える。旧UIの `cycle` / `auto` は表示変換層で吸収し、API・台帳に混在させない。

### 1.3 状態フィルタ（複数状態を明確化）

- ［全件］［的中］［不的中］［結果待ち］［未予想］［照合不可／停止］。少なくとも「的中だけ」「不的中だけ」をワンタップで切替。
- 的中・不的中は**3連単発売が公式に確認され、公式結果が確定し、締切前の不変予想が検証されたレース**にのみ付ける。結果が分かっても、凍結証拠がないものに無条件で的中表示しない。
- 「未予想」「結果待ち」「非発売」「中止」「同着等の特別処理」「結果改訂中」「取得失敗」「時刻不一致」を的中・不的中と区別。必ず理由または次の確認先を示す。
- フィルタで表示から隠しても、上部の全レース母数・Hit@8_allを都合よく変えない。フィルタ対象だけの率を出す場合は別途「表示中○件の参考率」と明記。

### 1.4 並び替え

- ［新着順］：基本は確定結果の受信/改訂時刻の降順、未確定は公式締切予定時刻降順。イベント種別が異なるときは明示的な安定同点キー（開催日・競技・会場・R・race_id）で決定。
- ［払戻順］：確定した公式3連単払戻（**100円当たり**）の高い順。未知・非発売・未確定は末尾。「払戻順」は購入済み金額順ではないことをラベルまたは注記で区別。
- ［的中率順］：**単一レースには的中率がないため、モデル別または会場別に集約したグループのHit@8_allの降順**と定義。レース単位リストにこの並びを適用する場合は「所属モデルの検証率順」と表示し、同一母数・評価期間・件数・信頼区間を示す。分母0・未検証は最後。
- 操作によって保存された事前予想の買い目順序・モデル選抜結果を変更しない。

## 2. 1レースカードで必ず見えること

初期表示の順番：
1. **［競技］会場名・レース番号・開催日・クラス/種別（確認済みなら）**。予想モデル名/版。結果の状態を「的中」（赤/強調）「不的中」（灰）「結果待ち」（青）「未予想」（黄）等、文字＋アイコンで表示。色だけを判定根拠にしない。
2. **［AI予想］最大8点**。先頭候補だけでなく**全点**を番号・順位付きで表示。的中した券は枠線と文字で強調。予想出力順はそのまま固定。
3. **［公式確定結果］3連単の着順（例：1-2-4）**を大きく表示。データ未取得時に番号を推測しない。公式の同着、失格、返還、成立・不成立の解釈と結果版を表示。
4. **［一致判定］** 公式確定結果の有効当たり券が最大8点のいずれかと一致すればHit@8=的中。複数的中券があり得る特別ルールは主催者の定義に従う。公式結果改訂時は旧判定を消さず履歴を保持。
5. **［実購入・払戻］** 購入していないレースは「購入なし」とし、実収支を0円損益として計算しない。実購入額・実払戻/返還額はユーザー確認済みの記録からのみ表示。別欄で公式100円当たり払戻および**仮想購入シミュレーション**を表示できるが、必ず「参考」「未購入」を明記。オッズ・配当は予想を締切前に凍結した後だけ評価画面側へ渡し、予想モデルには流さない。
6. **［もっと見る］** モデル版、予想生成/永続保存/外部受領時刻、公式締切の出典、入力ハッシュ、予想ハッシュ、予想根拠と欠測特徴、前後の予想改訂・結果訂正、リンクを表示。

展開時の追加情報：
- 予想を固定した日付/時刻（JST）、予想根拠で使った特徴・出典・公開時刻・取得時刻、オッズ独立の証明、モデルID/版、学習終了時点。
- 保存証拠：予想の原本、SHA-256、外部保存receipt ID、GitHub commit SHA/参照、保存後読戻しの一致検査状態。「証拠リンク」は原データそのものの公開権を意味しない。閲覧者権限外の資料は非公開のまま、アクセス可否を明示する。
- 結果証拠：主催者の確定発表元と発表時刻、適用中の結果revision、公式払戻・返還・同着等の解釈。閲覧可能な公式ページへのリンクは許可条件を守り表示。
- 不的中なら「外れた組番」「結果との違い」、原因分析（**確認事実 / 推測 / 不明**）の区別、見直し対象の特徴量。事実ではないモデル説明を捏造しない。
- 同一レースの予測モデル複数個は各バージョンの凍結された候補と結果を比較できる。ただし正式運用モデル1つの成績とシャドー候補モデルの成績を混ぜない。

## 3. 成績の見せ方・正確な集計

### 3.1 全対象の98％目標の計算

`Hit@8_all = 締切前に不変保存が立証された予想の上位最大8点のうち、公式3連単的中券を含むレース数 / 3連単発売かつ公式結果で評価可能な対象全レース数`

- 未予想・期限超過・見送り・権利/入力不足で停止したが公式に評価可能なレースは**分母に含め、的中数には含めない**。
- 3連単非発売・正式中止・不成立・結果未確定は全台帳には残す。結果未確定は分母確定前の保留として「未確定件数」へ隔離し、都合よく不的中や的中へ算入しない。
- 公式結果訂正があれば結果版を遡及適用して**集計版の更新**を許すが、事前予想原本は絶対に改変しない。変更前/後の集計と採用理由を残す。
- 合成テスト・デモ・仮予想・権利不明データは実績率の分子分母に入れない。データ不足・母数ゼロは率「未検証」。
- 競技別・会場別・モデル別・開催日別に分母、的中数、率、95%信頼区間、凍結率、未予想率、欠測件数を並記。少数例で98％表示になっても「長期安定達成」と断定しない。

### 3.2 期間集計

- ［今日］：開催日JSTが選択日の0:00–23:59:59。
- ［今週］：選択日を含む月曜0:00–翌月曜0:00直前（JST）。他に「直近7日」を設ける場合は別名称とする。
- ［累計］：データがある全期間。最初の適用日とデータ欠落を表示。未収録の過去レースは母数0扱いにせず「全期間の捕捉未検証」を明記。
- 期間切替はタブ・フィルタ・モデル比較へ一貫適用。「開催日」と「結果確認日」の違いを表示。
- 今日/今週/累計の切替で的中率、的中数、全対象数、未予想率、実購入損益を更新。公式結果が遅延しているレース件数を同時に表示。

### 3.3 AIモデル別比較

- モデルID/版ごとの名前、対象競技、モデルの運用/研究区分、発表時期・学習終了日を表示。
- **同一開催・同一未来レース・同一締切情報での前向き並走比較**を正式なA/Bとする。モデル間で分母・時点が異なる比較は「参考、条件相違」と表示し、自動昇格の根拠にしない。
- `Hit@8_all` の率・分母・的中数・95%信頼区間、予想凍結率、母数に含む未予想、日次推移、推定確率が校正済みの場合だけBrier/Log Lossも表示。
- ［的中率順］はグループの実測率で並べるが、少数サンプルの上振れを強さの保証にしない。比較対象や期間のフィルタによる母数差を明示。
- 「的中特化型AI」「バランス型AI」などの名称は**実在するモデルIDとの対応が検証できた場合だけ**表示。デザイン上の架空ラベルから実モデルを作ったことにしない。

### 3.4 払戻と収支の計算

- 公式3連単払戻＝主催者確定の券面基準（通常100円当たり）。単勝/複勝/2車単など別券種混入禁止。
- 実購入の総支出・総払戻・返還額・純損益を固定小数/整数円で計算。戻し金は利益に二重加算しない。未購入に実購入収支を付けない。
- 「モデルが8点予想した＝8点買った」ではない。仮想収益は`SIMULATION`ラベルと購入前提金額を表示し、実購入/残高と分離する。
- 予想締切前のオッズをモデルに混入させない。予想確定後に購入価値を検証する場合も保存済み予想の順位・集合を改変しない。

## 4. 結果速報・自動更新（「すぐ分かる」の受入条件）

- 画面の目標は、主催者の**確定結果が利用可能になった後、許可済みデータ経路で取得・検証でき次第**、カードを「結果待ち→照合完了」へ自動更新すること。**情報提供源より早い速報や秒単位の遅延上限は保証しない**。
- 更新経路：`OfficialResultProvider（用途別権利審査）→ ResultRevisionStore（追記専用）→ ExactSettle（券種/例外）→ VerifiedReadProjection → UI`。予想の追記専用原本とは別テーブル/イベント列にする。
- 各カードに「最終確認時刻」「公式確定時刻」「結果revision」「更新失敗時刻（ある場合）」を表示。最新が取得できない場合は旧結果に「前回確認時点」を付ける。古い値を「最新」と断言しない。
- 許諾・利用上限の範囲で各レース終了後の再照合をイベント駆動／定期ジョブで実行。手動の［再確認］も用意するが、再確認ボタン連打で禁止/高負荷アクセスを発生させない。
- 回線断・GitHub Actions遅延・API停止・結果未確定・変更/返還・重複ジョブ・日付跨ぎでもデータを消さず復旧可能にし、遅延理由を表示。手動更新しかない状態は「自動速報完成」としない。

## 5. 結果改訂履歴と検証証拠

- 各確定結果に`result_revision_id / source_url / source_available_at / fetched_at / persisted_at / official_status / winning_combinations / payout_yen_per_100 / supersedes_id`などの履歴を付与。
- 旧版をUPDATE/DELETEで消さず、新revisionを追加し、画面で「改訂前→改訂後」「改訂理由」「取得元」「時刻」「的中判定や収支への影響」を確認できること。
- 不変の予想について`prediction_id / model_id / model_version / generated_at / persisted_at / cutoff_at / input_hash / prediction_hash / external_receipt_id / rights_evidence_id`を監査可能に保持。
- 証拠リンクはGitHub commit・read-only保存receipt・公式結果URLへ遷移可能。ただし秘密鍵・個人データ・権利制限原本をpublic repoへ置かず、必要なら認証アクセス+ハッシュ照合にする。
- 候補予想の結果を見て本命モデルへ付け替えない。選定ルールとモデルIDは締切前に固定。後日の結果から過去予想を修正しない。

## 6. 読み取り用データ契約・安全ゲート

- 既存PR #71の `RACE_AI_FORECAST_AUDIT_V1` は**暫定の読み取り用投影**。正本（出走スナップショット・予想freeze・公式結果revision）との1対1参照が必要。表示モデルが正本を自己生成/改変しない。
- 将来の投影バージョンは`sport, organizer, venue, meeting, event_date_jst, race_no, result_status, result_revision_id, ticket_offering, cutoff, top8, model_version, prediction_receipt, source_provenance, payout_data, actual_bet, snapshot_status`を欠損許容の型付き値で持つ。欠測は0・空的中・偽時刻で埋めない。
- 入力検証：種別、日付/JST、固有race_id、重複、出走者・欠場の変更、3連単各券が異なる3人/艇/馬・出走者有効、最大8券、オッズ由来フィールド混入拒否、ハッシュ、凍結時刻が公式締切前、確認済の外部保存receipt、結果確定後の正本証拠。
- 他者サイトの数字・文章・画像・動画を無許諾で自動保存・転載しない。表示・保存・学習・再配信・動画は別用途として審査。出典/アクセス条件が未確認ならそのデータ源の当該用途を停止し、レースと不足理由は台帳に残す。
- エンドポイント認証・閲覧権限と公開リスクを確保。無許可公開・認証秘密の表示禁止。コードの単体テストだけで外部時刻真正性を証明したと主張しない。

## 7. iPhone/PC操作・アクセシビリティ受入条件

- iPhone縦画面の第一画面に［競技タブ］［期間］［全件/的中/不的中］［Hit@8］［レース一覧］の見出しが認識できる。
- タブは横スワイプ/タップ可能で、意図しない競技リロードや選択解除がない。読み込み時のスケルトン/オフライン/権限不足状態が分かる。
- 色覚に関係なく「的中」「不的中」「未予想」「確定待ち」「訂正あり」をテキスト・アイコンで判別。結果券番号は高コントラスト、テキストサイズ変更・VoiceOverを妨げない。
- 320/375/390px、PC 1440pxで横溢れ・画面外の結果・操作不能がない。大量レースでも一覧をページング/仮想表示し、集計は絞り込み結果だけでなく正本全体の母数から実施。
- 日付/競技/状態の切替、並び替え、カード展開、根拠URL、結果改訂履歴、ユーザーの手動買い目とAI予想の区別を実機で検査。
- 最新の画面UIの成功は本番データ供給・98％達成を意味しない。
