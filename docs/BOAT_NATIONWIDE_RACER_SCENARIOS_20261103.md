# 全国締切順A/Bと選手特徴・展開予測（PR #71追補）

状態: オフライン基礎実装・8テスト成功。全国の実レース定期予想と新モデル実測は未達。

## 目的
宮島固定の検証を全国開催場へ広げ、レースを公式締切順に処理する。未検証のモデルBを昇格させず、A/B原本と未来レースの時刻証拠を保存し、結果確定後に独立PDCAする。Vercel、投票、課金は利用しない。

## 追加した純粋ロジック
- race_ai/boat_deadline_queue.py: 確認済み公式当日スケジュールから締切昇順・同時刻は場コード/R番号順に整列する。締切まで3分以下、重複した原本、既に凍結済みのレース、欠けた時刻・SHA、未来に取得されたと主張する情報は拒否。予定が22分より先なら保留する。実データの収集・予想実行・artifact保存はこの関数だけでは行わない。
- race_ai/boat_racer_tendencies.py: 歴史的な公式結果が入力された前提で、選手登録番号ごとに実進入コース別の出走/1着/2連対/3連対、枠より内に入った回数、枠より外に押し出された回数、外枠艇が自分の内に進入した回数、1コース敗戦の勝者決まり手別件数を算出する。入力元の真正性はこの関数では認証しない。非標準結果や不明情報は勝率へ混ぜず拒否する。
- tests/test_boat_deadline_queue.py / tests/test_boat_racer_tendencies.py: 合計8テストをローカル実行で成功。実レースでの的中率や未来予想保存の実証ではない。

## 続いて接続する工程
1. 公式の当日開催一覧から開催場を特定し、会場別スケジュールと開催中止/締切変更を照合。取得経路と上限を確認する。
2. 競走成績・番組表・レーサー期別成績を、公式提供形式と利用条件に基づいて履歴として蓄積。各特徴の観測期間、母数、取得時刻、SHAを保持する。未来予想時刻以後の成績は遮断。
3. 全場の締切順にA/Bを別々に生成し、レース単位に原本SHA・全120通り・Top8・公式締切・GitHubの保存時刻を独立照合。締切後の保存や失敗は成功扱いしない。
4. 公式確定結果を収集後、Hit@1/Hit@8/Brier/Log loss/着順順位/払戻を独立計算。欠測・中止・返還を別枠にする。原本を再生成しない。
5. 新モデルCとして「選手特性と展開シナリオ」を実験する。枠なり/前付け/逃げ/差し/まくり/まくり差しを条件付き確率で扱い、全120通りに正規化する。少数実績はコース・場・グレードの母集団に基づく平滑化を検討し、若手には年齢だけのボーナスを付けない。
6. A/B/Cの未来レース前向き比較が十分に蓄積するまで、重みの自動更新・昇格・main統合をしない。

## データ解釈の注意
「1コース敗戦で勝者の決まり手がまくり」と「本人がまくりに弱い」は同義ではない。勝者のコース、当日のスタート、対戦相手、モーター、水面、風を共変量として分ける。前付けした選手の実進入と、前付けされて枠より外に出た選手の耐性も別指標として扱う。

BOATERSは枠別場別実績、直近10走、進入変更シミュレーション等を提供。2026-11-03時点で確認した利用規約第8条はスクレイピング/クローリングを禁止し、提供情報の用途も限定。BOATERSは設計の参考にとどめ、データの無断自動取得・再配布はしない。
